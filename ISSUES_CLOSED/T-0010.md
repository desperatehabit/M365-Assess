# T-0010 — Job queue, worker pool, and child-process supervisor

## Report

EPIC-001 SPEC.md §4.2/§4.3 require one job per tenant, a configurable worker pool (default `2`,
SPEC §11.4), and progress events. ADR-0014 requires a supervisor with timeouts and process-tree
kill because "orphaned or hung worker processes" is a named failure mode.

Deliver:

- A queue that accepts a `JobEnvelope` (T-0007) and holds it until a worker slot is free; state
  transitions (`queued`/`running`/`succeeded`/`failed`/`cancelled`) are persisted via the
  repository (T-0009).
- A supervisor that spawns `pwsh -File portal/workers/run-tenant.ps1` with the job envelope,
  reads the `ResultEnvelope`, streams progress events, and enforces a per-job timeout with a
  process-tree kill on expiry or cancellation.
- Worker pool size is configurable with the `2` default for single-node.
- The BFF process never loads the M365 SDKs.

## Acceptance

- [ ] A queued job runs through a stubbed worker and produces a persisted terminal state.
- [ ] Envelope schema mismatch is rejected, not silently accepted.
- [ ] A hung worker is killed by timeout and the run is marked failed; a test covers it.
- [ ] Pool size default is `2` and configurable.
- [ ] No file outside `scope` is modified.
