# T-0227 — Auth-method contracts and phishing-resistant classifier

## Report

EPIC-012 SPEC.md §3.1 and §9: the MFA report must classify **phishing-resistant** methods by
reading methods from Graph, not inferring them. §11.4 resolves the definition to **FIDO2,
passkey, Windows Hello for Business, and certificate-based authentication** as the
phishing-resistant set (with TAP and one-time methods explicitly not counted).

Add `portal/contracts/src/auth-methods.ts` with the auth-method union, the `PhishingResistant`
classification enum, and the method-to-user mapping used by the report, and
`portal/bff/src/domain/auth-methods/phishing-resistant.ts` with a pure classifier over a Graph
authentication-method record. This is the single source of truth consumed by T-0221; keep it
free of M365 SDK calls so it is unit-testable.

## Acceptance

- [ ] Every §11.4 method is classified correctly; TAP/password/SMS are not phishing-resistant.
- [ ] An unknown method maps to a safe `unknown` classification rather than throwing.
- [ ] The classifier is a pure function with no SDK or Graph call.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
