# T-0883 — Groups row actions are broken or no-ops

## Report

`portal/web/src/app/identity/groups/page.tsx:47` routes the Edit action to
`/identity/groups/{id}/edit`, which does not exist (the only pages under `app/identity/groups/` are
`page.tsx`, `usage`, `[id]/bulk`, and `new`), so Edit 404s.

Delete, Hide from GAL, and Delivery management row actions fall through with `default: break;`
(`page.tsx:44-58`; `components/groups/GroupsTable.tsx:385-420`), and
`components/groups/GalDeliveryDialog.tsx` is imported by no page. The backend routes are mounted
(`portal/bff/src/app.ts:990-995`, workers `set-group.ps1` / `set-group-gal-delivery.ps1`), so this is
a UI wiring gap (SPEC §3.1, §3.4).

## Acceptance

- [ ] Edit navigates to a page that exists and saves group changes.
- [ ] Delete, Hide from GAL, and Delivery management invoke their endpoints.
- [ ] `GalDeliveryDialog` is rendered and wired.
- [ ] A component test covers each action.
- [ ] No file outside `scope` is modified.

## Resolution

Edit now opens `/identity/groups/{id}/edit` and saves through PATCH; Delete uses a name-confirmed dialog; Hide from GAL and Delivery management use the previously orphaned `GalDeliveryDialog`; Manage owners opens the bulk page on the owners role. Convert has no backend endpoint and shows an explicit not-available notice. Each action has a wiring test with success and error paths, plus BFF tests for PATCH and the mounted routes. Not verified against a live tenant.
