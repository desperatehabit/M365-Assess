# T-0586 — Mailbox permission strings violate the EPIC-038 taxonomy

## Report

The EPIC-020 routes landed with lowercase permission strings: `mailboxes.read`,
`mailboxes.write`, `mailboxes.permissions`, and `mailboxes.vacation`. The T-0816 taxonomy
test (`portal/bff/src/rbac/permissions.test.ts`) requires every route permission to match
`{Area}.{Resource}.{Read|ReadWrite}` (PascalCase) unless it is a documented admin-only
permission. The fleet QA gate runs the Pester suite only, so this JS-only violation reached
main and fails the suite there.

Rename the four strings across the route modules and their tests:

- `mailboxes.read` → `Mailboxes.Read`
- `mailboxes.write` → `Mailboxes.ReadWrite`
- `mailboxes.permissions` → `Mailboxes.Permissions.ReadWrite`
- `mailboxes.vacation` → `Mailboxes.Vacation.ReadWrite`

The routes are not mounted in `app.ts` yet, so no permission-registry entries are needed —
the mounting ticket adds them, as with the defender routes.

## Acceptance

- [ ] `portal/bff/src/rbac/permissions.test.ts` passes (taxonomy + completeness).
- [ ] The four renamed constants keep their exported names; only the string values change.
- [ ] No file outside `scope` is modified.
