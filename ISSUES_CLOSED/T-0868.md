# T-0868 — Mount EPIC-038 RBAC, Portal Users & API Clients routes

## Report

`portal/bff/src/app.ts:719-720` mounts only `createMeRoutes` and `createAccessRoutes`. The remaining
EPIC-038 factories are never imported:

- `createPortalUsersRoute` (`portal/bff/src/routes/users.ts:1341`, `PORTAL_USERS_PATH` at `:1137`)
- `createRolesRoutes` (`roles.ts:535`, `ROLES_PATH` at `:206`)
- `createApiClientRoutes` (`api-clients.ts:200`, `API_CLIENTS_PATH` at `:13`)
- `createOpenApiRoutes` (`openapi.ts:501`)

so `/v1/users`, `/v1/roles`, `/v1/api-clients*`, and `GET /openapi.json` 404. There is no adapter
under `portal/bff/src/adapters/` binding `portal/db/src/rbac-repository.ts`; the only stores are
test-only in-memory seed factories (`createInMemoryPortalUserStore` `users.ts:1171`,
`createInMemoryRolesStore` `roles.ts:423`, `createInMemoryApiClientStore` `api-clients.ts:54`).

`portal/bff/src/server.ts:15` serves only `/v1/openapi.yaml` (`OPENAPI_ROUTE`), while SPEC §3.5/§6
requires `GET /openapi.json` (OpenAPI 3.1 JSON); the JSON route exists in the unmounted `openapi.ts`
(`OPENAPI_JSON_PATH` at `:483`).

## Acceptance

- [ ] Every EPIC-038 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [ ] Portal users, roles, scopes, and API clients persist through SQLite (no in-memory store in production).
- [ ] `GET /openapi.json` serves valid OpenAPI 3.1 JSON.
- [ ] No file outside `scope` is modified.
