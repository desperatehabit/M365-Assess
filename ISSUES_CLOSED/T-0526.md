# T-0526 — LinkRemovalJob persistence

## Report

EPIC-027 SPEC.md §5 fixes the persisted entity `LinkRemovalJob` (`id`, `tenantId`, `linkIds[]`,
`state`, `results`, `createdBy`) as the audit trail for bulk removal; sharing/permission data is
read live and only removal jobs persist. The optional `SharingReportCache` entity is noted but
not required while reports read live (§11 item 1). ADR-0015 and `03-database.md` require a
numbered, forward-only migration behind the repository interface.

Deliver migration `0051_sharing_link_removal.sql` (do not reuse a claimed lower number) with the
`link_removal_jobs` table storing `linkIds`/`results` as JSON text, plus create/get/update/list
methods on `portal/db/src/repository.ts` and `sqlite-repository.ts`. This ticket adds no routes
and no worker code.

## Acceptance

- [ ] Migration 0051 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes `LinkRemovalJob` create/get/update/list, tenant-scoped.
- [ ] `linkIds`/`results` round-trip as JSON; no secret value is stored.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
