# T-0871 — Destructive device actions are shadowed and unreachable

## Report

`portal/bff/src/app.ts:1014-1026` mounts `createDeviceActionsRoute` (sync/retire) **before**
`createDestructiveActionsRoute` (wipe/fresh-start). Both export the same method and path:

- `DEVICE_ACTIONS_PATH = "/v1/tenants/:tenantId/devices/:deviceId/actions/:action"` (`routes/device-actions.ts:12`)
- `DEVICE_DESTRUCTIVE_ACTIONS_PATH = "/v1/tenants/:tenantId/devices/:deviceId/actions/:action"` (`routes/device-actions-destructive.ts:14`)

The server takes the first matching route (`portal/bff/src/server.ts:247-254`), so wipe/fresh-start
requests reach the sync/retire handler and are rejected as an unknown action (400). The destructive
path's permission (`DEVICE_DESTRUCTIVE_ACTIONS_PERMISSION`) and two-person policy
(`SqliteDeviceActionPolicyRepository`) are therefore never evaluated.

## Fix direction

Give the destructive actions a distinct path (preferred, e.g. `.../actions/:action` reserved for
destructive verbs is ambiguous — route them under a separate segment such as
`.../device-actions/:action`) or dispatch within a single handler by action name, keeping the
stronger permission and policy checks for wipe/fresh-start.

## Acceptance

- [ ] A POST wipe/fresh-start request invokes the destructive handler and enforces the two-person policy.
- [ ] A sync/retire request still invokes the non-destructive handler.
- [ ] A test fails on the current build and passes after the fix.
- [ ] No file outside `scope` is modified.
