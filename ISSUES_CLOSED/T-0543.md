# T-0543 — Incident list worker and API with cross-tenant aggregation

## Report

EPIC-028 SPEC.md §2 US-1, §3.1, §4.2, and §6 define the incident list: Title · Severity · Status
· Classification · Assigned to · Alerts · Last updated · Tenant, with filters by severity,
status, classification, assigned, date, and tenant. §4.2 requires an all-tenants view that
aggregates open incidents by severity and respects RBAC scope. §6 exposes `GET
/v1/tenants/{id}/incidents`; incidents are read live from Graph/Defender per §5 and §7
(`SecurityEvents.ReadWrite.All`).

Deliver a `Get-Incidents.ps1` handler (entrypoint `get-incidents.ps1`) that reads incidents
through Graph, normalizes them via the T-0542 model, and returns a `ResultEnvelope`; plus the
list route validating `incidents.read` and tenant scope with cursor pagination and the §3.1
filters. The cross-tenant view aggregates only tenants within the caller's RBAC scope. Extend
`portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/incidents` returns the §3.1 columns, filtered and paginated.
- [ ] The all-tenants view aggregates by severity and only across tenants in the caller's scope.
- [ ] A caller without `incidents.read` is refused; the BFF performs no Graph call directly.
- [ ] A test covers listing, filtering, and scope-limited aggregation and fails without it.
- [ ] No file outside `scope` is modified.
