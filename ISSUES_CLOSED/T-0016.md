# T-0016 — GET /v1/health reports service, storage, queue, and workers

## Report

EPIC-001 SPEC.md §2 US-7 and §6 require `GET /v1/health` as the liveness endpoint reporting
service, storage, queue, and workers; EPIC-001 SPEC.md §10 makes it an acceptance criterion, and
the §3 diagnostics page consumes it.

Deliver:

- A health route that reports: service version, storage reachability (via the repository),
  queue depth, worker count, and last run timestamp.
- Storage/queue failures are reported as a degraded (non-2xx only for total liveness failure)
  structured payload with stable codes, not a stack trace.
- The endpoint performs no tenant work and requires no tenant scope.

## Acceptance

- [x] `/v1/health` returns the five fields and reflects repository/queue state.
- [x] A test forces storage down and asserts a degraded, structured payload.
- [x] No secrets or tenant identifiers appear in the response.
- [x] No file outside `scope` is modified.
