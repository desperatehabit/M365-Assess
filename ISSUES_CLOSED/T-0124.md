# T-0124 — Schedule CRUD, run-now, history, and system-timer API

## Report

EPIC-007 SPEC.md §6 defines the scheduler endpoints: `GET`/`POST`/`PATCH`/`DELETE /v1/schedules`,
`GET /v1/schedules/system` (read-only), `POST /v1/schedules/{id}/run-now`, and
`GET /v1/schedules/{id}/history`. §4.2 step 5 says `Run now` sets the task due immediately and
enqueues. §4.4 requires a task's `Command` to resolve to a known allowed command and to be
rejected at creation otherwise. §7 gates on `scheduler.read/write/run` and tenant scope.

Deliver:

- Route handlers implementing the five endpoints; user-task CRUD delegates to T-0122, `run-now`
  to T-0123's enqueue path, and history reads the job/run records.
- Creation-time validation that `command` is in the allowed command set; rejection is a
  structured `422`.
- `GET /v1/schedules/system` returns the T-0123 system-timer registry and rejects any write
  attempt; system timers are not editable or deletable.
- OpenAPI updated; tests for CRUD, command rejection, run-now, and read-only system timers.

## Acceptance

- [ ] All endpoints are implemented and match the OpenAPI document.
- [ ] Creating a task with an unknown command is rejected.
- [ ] `run-now` enqueues immediately and appears in history.
- [ ] System timers are listed but cannot be modified or deleted.
- [ ] No file outside `scope` is modified.
