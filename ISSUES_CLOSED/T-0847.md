# T-0847 — Verify EPIC-017 Graph calls against a live tenant

## Report

The EPIC-017 workers were built against mocked Graph only. Assumptions to confirm or correct:

- **App list / detail** (`Get-IntuneApps`, `Set-IntuneApp`): v1.0 `deviceAppManagement/mobileApps`
  with `$expand=assignments` on the list; beta for detail/update/delete. `@odata.type` values
  `win32LobApp`, `winGetApp`, `microsoftStoreForBusinessApp`; detection rules read from `rules`
  with `ruleType`; PATCH needs `@odata.type`.
- **Win32 upload** (`Queue-IntuneAppUpload`): beta sequence create app → `contentVersions` →
  `files` (size = unencrypted, sizeEncrypted) → poll `azureStorageUriRequestSuccess` → block
  PUTs (6 MiB, `x-ms-blob-type: BlockBlob`) + `comp=blocklist` → `commit` with
  `fileEncryptionInfo` → poll `commitFileSuccess` → PATCH `committedContentVersion`. The
  `.intunewin` layout (`IntuneWinPackage/Metadata/Detection.xml`, `Contents/<FileName>`). SAS
  renewal (`renewUpload`) is not implemented; confirm a large upload finishes inside the SAS
  lifetime or add it. Store: `winGetApp` with `packageIdentifier` and
  `winGetAppInstallExperience`.
- **Assignment** (`Set-IntuneAppAssignment`): beta `mobileApps/{id}/assign` with
  `mobileAppAssignments` replacing the whole set; `available` to All devices rejected.
- **Template preflight** (`Deploy-ApplicationTemplate`): `$filter=displayName eq '…'` on
  mobileApps is supported.
- **Autopilot** (`Import-AutopilotDevices`, `Set-AutopilotProfile`): v1.0
  `importedWindowsAutopilotDeviceIdentities/import` body and per-device `state`; beta
  `importedDeviceIdentities/importDeviceIdentityList` (manufacturer,model,serial); beta
  `windowsAutopilotDeploymentProfiles` CRUD, `$expand=assignments`, `/assignments` POST/DELETE,
  and that Graph refuses deleting an assigned profile.
- **Enrollment** (`Set-EnrollmentProfile`): beta `depOnboardingSettings/{id}/enrollmentProfiles`
  CRUD and `updateDeviceProfileAssignment`; beta `androidDeviceOwnerEnrollmentProfiles`;
  `tokenExpirationDateTime` on both; that token/QR fields are the only secrets returned.
- **Status** (`Get-IntuneAppStatus`): beta `mobileApps/{id}/deviceStatuses` shape
  (`installState`, signed `errorCode`); `importedAppleDeviceIdentities` enrollment states;
  Android `managedDevices` `deviceEnrollmentType` values.

Run each worker against a test tenant, correct any wrong endpoint, verb, or payload, and update
the mocked tests to the observed response shapes. A person must run this; the agent has no
tenant credentials.

## Acceptance

- [ ] Each listed assumption is confirmed or corrected against a live tenant, with the result recorded in this ticket.
- [ ] A Win32 `.intunewin` uploads end to end and becomes assignable; a Store app is created.
- [ ] Worker tests reflect observed response shapes; they fail without any corrections made.
- [ ] No file outside `scope` is modified.
