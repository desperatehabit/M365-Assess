# T-0110 — 62-command validation harness (hard gate before apply)

## Report

EPIC-006 SPEC.md §4.5: before any apply ships, each of the 62
`remediation.powershell.command` strings must be validated against a real tenant. SPEC.md §9
names the risk — the commands are unvalidated strings — and §8 makes §4.5 a **hard gate on the
apply path**. The harness records, per check: whether the command runs, is idempotent, has
`before`/`after` captured, and has expressible gates; it updates
`docs/portal-specs/02-controls/remediation-matrix.csv` `specStatus`
(`not-started` → `drafted` → `approved`) and authors `docs/portal-specs/02-controls/auto/NNN-<checkId>.md`.

Build `Test-RemediationCommand` in `Remediate/`, running each command through the typed executor
(T-0107) against a connected tenant child process, twice, to prove idempotency, and emitting a
per-check validation record. The apply gate must treat only `approved` checks as eligible, so an
unvalidated command is never applied. Dot-source the file from `M365-Assess.psm1`. Keep the
matrix edits merge-preserving on `checkId` per the generator's contract.

## Acceptance

- [ ] The harness reports run/idempotent/before-after/gates for each of the 62 auto-candidates.
- [ ] `specStatus` in `remediation-matrix.csv` and an `auto/NNN-<checkId>.md` are written for a validated check.
- [ ] An unvalidated check is ineligible in the apply gate; a test proves it.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
