# T-0913 — CI does not build or test the portal

## Report

No workflow in `.github/workflows/` mentions `portal/`. The only `npm run build` in `ci.yml`
(line ~126) builds the HTML report app. As a result:

- The roughly 6,200 Vitest tests in `portal/` (contracts, db, bff, web) never run in CI.
- `next build` is never run. On 2026-11-17 it failed on main's pages: about 80 pages call
  `useSearchParams()` with no Suspense boundary, which breaks the production prerender. The
  fix (a boundary in `app/layout.tsx`) landed with the Phase 1 PR, but nothing stops a
  regression.

"CI green" therefore says nothing about the portal, and the Phase 2 gate depends on it.

## Fix direction

Add a `portal` job on `ubuntu-latest` with Node 20: `npm ci` in `portal/` (allowing the
`better-sqlite3` install script), `npm run typecheck`, `npm run build`, `npm test`. Make it a
required check.

## Acceptance

- [x] A PR that breaks a portal test or `next build` fails CI.
- [x] The job is listed as required on `main`.
- [x] No file outside `scope` is modified.

## Resolution notes

- New `portal` job in `.github/workflows/ci.yml` (`ubuntu-latest`, Node 24, the version used
  locally): `npm ci` with install scripts enabled (better-sqlite3), then `npm run build`,
  `npm run typecheck`, `npm test`. Build runs before typecheck because `bff` and `web` import
  `@m365-assess/contracts` and `@m365-assess/db` through their gitignored `dist/` output, so
  typecheck fails on a clean checkout until those are compiled. The build includes `next build`.
- A `portal` path filter (`portal/**`, `ci.yml`) gates the job, and the `ci-status` aggregator
  (the required "CI" check) now needs it, so a portal failure fails the required check without
  any branch-protection change.
- Outside `scope`, deliberately: `.gitattributes` pins `portal/contracts/openapi/*.yaml` to LF.
  `openapi.test.ts` compares that file byte for byte with the generated (LF) document, so a
  Windows checkout with `core.autocrlf=true` failed the drift test falsely. This was the only
  failure in a local run of the full portal suite (contracts 50, db 306, bff 4385, web 1505).
- Verify: the PR that adds the job shows it green, and a deliberately broken portal test fails it.
