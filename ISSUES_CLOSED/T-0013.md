# T-0013 — Minimal built-in RBAC and portal authentication seam

## Report

EPIC-001 SPEC.md §7: this epic uses "a minimal built-in admin/operator split" with permissions
`runs.read`, `runs.create`, `runs.cancel`, and diagnostics requiring `admin`; the full RBAC
model (permission taxonomy, custom roles, API clients) is EPIC-038. `05-programming.md` §3
requires that every response be tenant-scoped by the caller's RBAC scope and that a
client-sent tenant list is intersected, never trusted.

Deliver:

- An authentication seam (who is the portal user) and a permission-check layer with the three
  run permissions plus an `admin`/`operator` role split.
- A helper that intersects a caller-supplied tenant selection with the caller's scope.
- The `auth/` interface is deliberately thin so EPIC-038 can replace the concrete identity
  provider (Entra ID) without touching route code.

## Acceptance

- [ ] Permission checks gate the run endpoints; a test asserts an operator without
      `runs.create` is refused with a structured error.
- [ ] The scoping helper intersects, and never widens, a client tenant list.
- [ ] No credential or tenant-secret value is logged.
- [ ] No file outside `scope` is modified.
