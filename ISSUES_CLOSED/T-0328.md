# T-0328 — Autopilot devices, add-device import, and profile templates

## Report

EPIC-017 SPEC.md §3.4 and §4.3 define **Autopilot Devices** (list + detail: serial, group tag,
profile, enrollment state), an **Add Device** wizard (manual, CSV import, device-prep import),
and **Autopilot Profiles** (deployment profiles, group tags). Duplicate serials must be detected
and reported. §5 adds `AutopilotProfileTemplate` (`id`, `name`, `profileJson`, `groupTag`) and §6
fixes the `/v1/tenants/{id}/autopilot/*` routes.

Deliver `Import-AutopilotDevices.ps1` + entrypoint (per-row results with duplicate detection),
migration `0084_autopilot_profile_templates.sql`, an `autopilot-profiles.ts` repository, and the
Autopilot routes (devices list/detail, import, profiles CRUD) behind the T-0108 gated-write seam
and the RBAC `intune.autopilot` permission. Each profile write is audited.

## Acceptance

- [x] The devices route lists Autopilot devices with serial, group tag, profile, and enrollment state.
- [x] Import accepts manual/CSV/device-prep rows and reports duplicate serials per row.
- [x] Profile templates persist and CRUD works; each write is audited.
- [x] Tests cover the route and worker and fail without them.
- [x] No file outside `scope` is modified.

## Resolution

- **Migration** `0084_autopilot_profile_templates.sql` (the ticket named `0017` and `0042`;
  next free number). Templates are portal-wide with a case-insensitive unique name. The
  repository requires an Azure AD or hybrid deployment-profile `@odata.type` and a
  `displayName`, rejects live-profile fields (`id`, `assignments`, …), credential-like keys,
  and bad group tags. It is tested through the route tests.
- **Worker** (`Import-AutopilotDevices.ps1`) dispatches four actions: `list-devices`,
  `get-device` (beta, `$expand=deploymentProfile` for the profile name), `list-profiles`
  (read-only), and `import`. Import takes manual rows, Get-WindowsAutoPilotInfo CSV, or
  device-prep rows (corporate identifiers, `manufacturerModelSerial`), reports **every** row as
  ready/imported/duplicate/invalid/failed, detects duplicates within the batch and against the
  tenant's registered and pending devices (or existing corporate identifiers), sends only new
  valid rows, surfaces Graph per-device import errors, and emits one audit event per applied
  import. Max 500 rows.
- **Routes** (`autopilot.ts`): `GET .../autopilot/devices` (search, groupTag, enrollmentState,
  paging), `GET .../devices/:deviceId`, `GET .../autopilot/profiles`,
  `POST .../autopilot/import` (preview supported), and profile-template CRUD at
  `/v1/autopilot/profile-templates`. Permissions `Endpoint.Autopilot.Read` / `.ReadWrite`;
  import also accepts `Remediation.Apply`.
- **Deviation:** SPEC §6 puts live profile CRUD at `/v1/tenants/{id}/autopilot/profiles`, but
  this ticket's acceptance is persisted templates and its only worker is the importer. Live
  profile deploy/edit/assign is T-0845; this ticket ships the read-only live list there.
- **Not verified live:** Graph calls are mocked (v1.0 for devices and import, beta for the
  device detail, profiles, and corporate identifiers).
