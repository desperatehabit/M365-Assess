# T-0048 — Artifact indexing and streaming download

## Report

EPIC-003 SPEC.md §4.5 defines artifacts as the module's per-run outputs (CSV/HTML/XLSX/JSON/
evidence) written to the run's artifact path and indexed in the DB; the API serves them with
correct content types, streams large files, and keeps access tenant-scoped and audited. §9
names the artifact-size risk (2–3 MB HTML, 5 MB+ large tenants) and its mitigation: stream and
store on the artifact tier, not in the DB. §6 defines `GET /v1/runs/{runId}/artifacts` and
`GET /v1/runs/{runId}/artifacts/{name}`.

Deliver an artifact indexer (scan the run path, record name/type/size, preserve the `-Redact`
distinction from `03-database.md` §7) and the list + download routes with correct content types
and streaming responses. No artifact is loaded wholly into memory.

## Acceptance

- [x] Listing returns indexed artifacts with name, content type, and size.
- [x] Download streams the file with the correct content type; a large file is not buffered.
- [x] Artifact access is tenant-scoped and audited.
- [x] No file outside `scope` is modified.
