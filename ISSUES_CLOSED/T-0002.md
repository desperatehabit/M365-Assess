# T-0002 — Connect-RequiredService accepts -Context with a legacy compatibility shim

## Report

`Connect-RequiredService.ps1:1-6` today takes only `-Services`/`-SectionName` and reads ~20
caller-scope variables (`$TenantId`, `$ClientId`, `$Certificate*`, `$graphScopes`,
`$connectedServices`, `$failedServices`, `$M365Environment`, …) while writing `$script:`
globals (`graphPermissionsChecked`, `tenantLicensesResolved`, `resolvedTenant*`,
`dnsPrefetchJobs`, `domainPrefix`, `logFilePath`, `logFileName`) — the implicit surface
tabulated in EPIC-001 SPEC.md §4.1.

Deliver:

- A `-Context [RunContext]` parameter; all caller-scope reads and `$script:` writes are served
  from `$ctx` when it is supplied.
- A **compatibility shim**: when `-Context` is omitted the function reads the legacy
  caller-scope variables once, builds a RunContext via `New-RunContext` (T-0001), and proceeds.
  This is what keeps the existing 166 Pester suites green during migration (SPEC §4.1 rules and
  EPIC-001 SPEC.md §10 acceptance).
- The EXO↔Purview mutual-exclusion disconnect logic (`Connect-RequiredService.ps1:29-38`) is
  preserved verbatim in behavior.

## Acceptance

- [ ] `-Context` threads tenant/auth/scope/service state with no caller-scope fallback.
- [ ] Omitting `-Context` still works against the legacy variables (shim path covered by a test).
- [ ] No new `$script:`/`$global:` run state is introduced.
- [ ] `tests/Orchestrator/Connect-RequiredService.Tests.ps1` fails without the change.
- [ ] No file outside `scope` is modified.
