# T-0087 — Report block data binding resolver

## Report

EPIC-005 SPEC.md §3.2 says each data-backed block carries a data binding (`static` vs live) and
per-block controls include refresh data and revert to live data. §11.3 resolves the binding model
to adopt: **run summary, findings, compliance, secure score, licenses**. §9 risk "block/data
drift" is mitigated by typed block contracts plus preview validation.

Deliver:

- `Resolve-ReportBinding.ps1`: given a block's `dataBinding` descriptor, resolves the live data
  from persisted rows into the typed block payload the T-0081 contract expects. Bindable entities
  are exactly the five adopted above; anything else is rejected.
- Support for the `static` case (authored content unchanged) and for a captured snapshot when the
  operator uses "revert to live data".
- Pester tests for each bindable entity, an unknown binding rejected, and a drifted/missing field
  producing an explicit validation error rather than silent empty output.

## Acceptance

- [x] Each of the five adopted binding entities resolves from persisted rows.
- [x] An unknown binding is rejected with a clear error.
- [x] A missing/drifted field surfaces a validation error at preview time.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
