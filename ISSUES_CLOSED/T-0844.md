# T-0844 — Mount the EPIC-017 routes and add the Intune Apps nav

## Report

EPIC-017's route modules are unit-tested but not mounted, so the Applications page and the
rest of the epic's UI get 404s from the running BFF. Following T-0818..T-0825:

- Add worker-backed providers under `portal/bff/src/providers/` built on `runFeatureWorker`
  (T-0815): `get-intune-apps.ps1` for `intune-apps.ts` (T-0321),
  `set-intune-app-assignment.ps1` for `intune-apps-assign.ts` (T-0324),
  `deploy-application-template.ps1` for `application-templates.ts` (T-0327, plus a
  `variables` reader over the EPIC-002 tenant-variable store with `isSecret`),
  `import-autopilot-devices.ps1` for `autopilot.ts` (T-0328), and `set-enrollment-profile.ps1`
  for `enrollment-profiles.ts` (T-0329), `set-intune-app.ps1` for `intune-apps-crud.ts`
  (T-0843), `set-autopilot-profile.ps1` for `autopilot-profiles-write.ts` (T-0845), and
  `app-packages.ts` (T-0842) on the shared `AppPackageStore` — mounted only when
  `appPackageSecret` is set.
- **Mount order:** `intune-apps-crud.ts` owns `/v1/tenants/:tenantId/apps/:appId`, which also
  matches `/apps/queue`, `/apps/status`, `/apps/upload`, and `/apps/packages`. Mount those fixed
  paths first (the route also 404s the reserved segments as a guard).
- Write the read-only `Get-IntuneAppStatus.ps1` worker behind `intune-app-status.ts`'s
  `AppStatusProvider` (T-0330 shipped the route with no worker in scope): per-device app install
  state (Graph device install status report / `mobileApps/{id}/deviceStatuses`) and per-device
  enrollment state (Autopilot identities, Apple ADE imported device identities, Android
  Enterprise managed devices). The route maps the raw state names itself.
- Wire `intune-apps-queue.ts` (T-0323): the `SqliteAppDeploymentRepository` (T-0322), the
  `AppPackageStore` with the T-0842 signing secret, the EPIC-001 queue under the `app-upload`
  job type with `runAppUploadJob` as its runner, and the audit sink.
- Register every EPIC-017 path in the `permissions.ts` registry (`Endpoint.Application.*`,
  `Remediation.Apply` for writes).
- Add Intune → Applications (Applications, Queued Applications, Application Templates) and
  Intune → Autopilot & Enrollment entries to `AppNav.tsx` (SPEC §3).

## Acceptance

- [x] Every EPIC-017 route module is mounted with a worker-backed provider or real repository.
- [x] A test per provider runs it against a fake worker runner and checks the envelope and mapping.
- [x] An app-level test reaches at least one read and one write EPIC-017 route through the server.
- [x] The permission registry covers every EPIC-017 path.
- [x] The nav links the EPIC-017 pages.
- [x] No file outside `scope` is modified.

## Resolution

- **Providers** live in `adapters/intune-apps.ts` (the codebase keeps worker-backed providers
  under `src/adapters/`, not the `src/providers/` this ticket named). One provider per EPIC-017
  route module, each on `createTenantWorker` so every job carries the tenant's credential
  block. Structured worker errors are raised for reads the route does not inspect and passed
  through for writes whose routes map them; lists PowerShell unrolls to a bare object are
  normalised.
- **Upload queue:** a dedicated `JobQueue` (pool size 1) runs `app-upload` jobs through
  `createAppUploadRunner` → `runAppUploadJob`, persisting to the shared jobs table but not
  feeding the assessment-run progress hub (which would record upload lifecycle events as run
  state). The upload route enqueues reference-only envelopes.
- **Packages:** with `M365_BFF_APP_PACKAGE_SECRET` set, the real `AppPackageStore` on the
  artifact tier; without it, a stand-in that answers every package operation with 503
  `app-package.unconfigured` naming the setting, so a Win32 upload explains itself.
- **Mounted** after EPIC-016, fixed `/apps/*` paths before `/apps/:appId`. Boolean-style
  authorizers use `canAccess`, so real callers' base roles (not a `permissions` list) decide.
  Template deploy reads variables from the EPIC-002 tenant-variable store with `isSecret`.
- **Status worker** `Get-IntuneAppStatus.ps1` (read-only): per-device install status for Win32 /
  Store apps (capped at 100 apps) and enrollment state from Autopilot, Apple ADE, and Android
  Enterprise.
- **Permission registry:** every EPIC-017 endpoint, in mount order; the completeness test
  (registry == mounted) passes. The signed package download is registered with
  `Endpoint.Application.Read` as its data class; its credential is the signature.
- **Nav:** Applications, Queued applications, Deployment status. Templates, Autopilot, and
  enrollment have no pages yet — T-0846.
- **Tests:** adapter job mapping and the upload runner; app-level tests through the server for
  the app list, `/apps/*` dispatch order, a Store upload running to success on the queue (jobs
  row `app-upload`, audit trail queued → succeeded), the 503 without a secret, a package upload
  with one, Autopilot and enrollment reads/previews, and read-only callers refused writes.
