# T-0764 — Community template trust model (signed/reviewed bundles, admin opt-in)

## Report

EPIC-039 SPEC.md §11 open question 2 and §9 risk "untrusted community templates". This ticket
**adopts** the signed/reviewed-bundle trust model: a community repo is only browsable/cloneable
when an admin has opted it in, and each bundle carries a signature plus a review state
(`unreviewed | reviewed | signed`). The `TrustBadge` component and the repo service surface the
review state and author/source, and clone refuses an unverified bundle unless an admin
explicitly overrode the opt-in (§3.3, §4.1: "never auto-apply").

Trust fields (`signed`, `reviewState`, `trusted`) are stored on `TemplateRepo` (T-0761) and
verified here. Verification failure is a structured error, not a silent pass. Record the admin
opt-in decision in the `AuditEvent`.

## Acceptance

- [ ] A repo is browsable/cloneable only after an admin opt-in; the decision is audited.
- [ ] Bundles carry a review state and signature; an unverified bundle is rejected with a structured error.
- [ ] `TrustBadge` renders source, author, and review state on catalog items.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
