# T-0501 — TeamTemplate and TeamOperation persistence

## Report

EPIC-026 SPEC.md §5 fixes the persisted entities: `TeamTemplate` (`id`, `name`, `owners[]`,
`members[]`, `visibility`, `settings`) and `TeamOperation` (`id`, `tenantId`, `teamId`,
`operation`, `state`, `by`, `at`, `result`) as the audit trail, with `AuditEvent` for every
write; teams/voice/LIS are read live from Graph/Teams and only templates and operation records
persist. ADR-0015 and `03-database.md` require a numbered, forward-only migration behind the
repository interface.

Deliver migration `0050_teams_templates.sql` (do not reuse a claimed lower number), storing
`owners`/`members`/`settings` as JSON text, plus create/get/update/list/delete methods on
`portal/db/src/repository.ts` and `sqlite-repository.ts` for both entities.
`TeamOperation` is append-forward (state transitions recorded in place). This ticket adds no
routes and no worker code.

## Acceptance

- [ ] Migration 0050 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes `TeamTemplate` CRUD and `TeamOperation` create/get/update/list, tenant-scoped.
- [ ] `owners`/`members`/`settings` round-trip as JSON; no secret value is stored.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
