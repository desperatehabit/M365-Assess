# T-0843 — Application row actions: assignment page, update, delete, clone to template

## Report

T-0325's Applications table renders every SPEC §3.1 row action, but four have nowhere to go:

- **Assign** deep-links `/intune/applications/assign?tenantId=&appId=`, and no page exists.
  Build it on T-0324's route: choose groups / All users / All devices with an intent per
  target and merge or replace mode, show the plan preview (add / update / remove / unchanged),
  and apply by echoing `planHash` as `confirmPlan`. Show the 409 "plan changed" case by
  re-previewing.
- **Update** (edit app metadata: name, description, publisher, commands, detection rules) and
  **Delete** (typed-name confirmation, as in T-0303) need a gated-write route and worker,
  `PATCH`/`DELETE /v1/tenants/{id}/apps/{appId}`, with plan preview and audit.
- **Clone to template** posts the app's configuration to T-0327's application templates API.

Remove each action from `APPLICATION_ACTIONS_PENDING` as it lands.

While in `ApplicationTable.tsx` / `DetectedAppsDrawer.tsx`, move them to kit tokens only: they
fall back to names `report-themes.css` does not define (`--text-muted`, `--accent-light`,
`--danger-bg`, `--accent-contrast`) with literal hex colours. Use `--muted`, `--accent-soft`,
`--danger-soft`, `--accent-text` and drop the hex fallbacks, as T-0326's components do.

## Acceptance

- [x] The assignment page previews the T-0324 plan and applies it only with the confirmed plan hash.
- [x] Update and Delete run through a gated-write route with preview, confirmation, and audit.
- [x] Clone to template creates an application template from the app.
- [x] No row action on the Applications page is disabled as pending.
- [x] Tests cover each action and fail without it.
- [x] No file outside `scope` is modified.

## Resolution

- **Worker** (`Set-IntuneApp.ps1`): `get` maps a Win32 or Store app into the portal shape
  (commands, install experience, architectures, and detection rules mapped back from Graph
  rules; requirement rules are left out), `update` previews or PATCHes (always with
  `@odata.type`, rebuilding `installExperience` and `rules` through the upload worker's
  mapping) with before/after, and `delete` needs the exact app name and shows the assignment
  count in its plan. Every applied write returns an audit event, failures included.
- **Route** (`intune-apps-crud.ts`): `GET`/`PATCH`/`DELETE /v1/tenants/{id}/apps/{appId}` behind
  the gated-write seam; `changes` are validated here and the worker decides which apply to
  which app type. Reserved `/apps/*` segments 404 so a mis-ordered mount cannot route
  `/apps/queue` to it.
- **Assignment page** (`/intune/applications/assign`, `AppAssignmentPanel`): targets (group
  object ID, All users, All devices) with intents, merge or replace, preview of the T-0324 plan,
  and apply only for an unchanged valid preview, echoing its `planHash`; a 409 clears the plan
  and asks for a fresh preview.
- **Applications page**: no action is pending any more. Update opens an edit drawer (preview the
  changed fields, then save); Delete prompts for the typed name (warning when assigned); Clone
  to template reads the app and posts a T-0327 template whose Win32 package is `%PackageId%`.
  `ApplicationTable` and `DetectedAppsDrawer` use kit tokens only.
- Group selection is by object ID; a group picker needs the EPIC-011 group search mounted.
