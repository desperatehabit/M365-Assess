# T-0846 — Application templates, Autopilot, and enrollment pages

## Report

SPEC §3 puts four EPIC-017 surfaces in the nav that have backends but no pages:

- **Application Templates** (§3.3): list, create/edit (config + declared variables with
  defaults), delete, and deploy to tenants with a per-target preview, `values` overrides,
  `confirmTargetCount` for more than one tenant, and per-target results
  (`/v1/app-templates`, T-0327).
- **Autopilot Devices** (§3.4): list with search / group tag / enrollment state filters and a
  detail view (`/v1/tenants/{id}/autopilot/devices`, T-0328), and the **Add Device** wizard —
  manual rows, CSV (Get-WindowsAutoPilotInfo output), or device-prep rows — with the per-row
  preview (ready / duplicate / invalid) before import (`.../autopilot/import`).
- **Autopilot Profiles** (§3.4): live profiles, profile templates CRUD, deploy a template to
  tenants, edit, delete (typed name; refused while assigned), and add/remove group assignments
  (T-0328, T-0845).
- **Enrollment Profiles** (§3.5): Apple ADE and Android Enterprise profiles with create (from a
  body or template), edit, delete, and Apple device assignment, plus token status with the
  `alerts` list surfaced prominently (T-0329).

Add the pages to the Intune nav group (Application templates, Autopilot devices, Autopilot
profiles, Enrollment profiles). Kit tokens only; actions filtered by `Endpoint.Application.*` /
`Endpoint.Autopilot.*` when permissions are resolved.

## Acceptance

- [x] Each page renders its route's data and walks its writes through preview before apply.
- [x] Autopilot import shows per-row results, including duplicates, before and after import.
- [x] Expiring and expired enrollment tokens are visible without opening a profile.
- [x] The nav links every EPIC-017 page.
- [x] Component tests cover each page and fail without it.
- [x] No file outside `scope` is modified.

## Resolution

- **Application templates** (`/intune/applications/templates`): list, create/edit (config JSON
  with `%name%` tokens and declared variables with defaults; the app type is fixed after
  creation), delete, and deploy: per-target preview, `name=value` overrides, an explicit
  confirmation checkbox for more than one tenant (sent as `confirmTargetCount`), per-target
  results. Deploy stays disabled until a preview has run.
- **Autopilot devices** (`/intune/autopilot`): filters sent to the API, detail panel with the
  assigned profile's name, and **Add devices** (`/intune/autopilot/add`): manual rows, a pasted
  or file-loaded CSV, or device-prep rows; Preview shows every row as ready / duplicate /
  invalid with the reason; Import is enabled only when some row is ready and shows each row's
  final result.
- **Autopilot profiles** (`/intune/autopilot/profiles`): tenant profiles (create from template,
  edit JSON changes, add/remove group assignments, delete with typed name, surfacing the API's
  "remove its assignments first" refusal) and templates (create/edit/delete, deploy with count
  confirmation). Every write is Preview → Apply.
- **Enrollment profiles** (`/intune/enrollment`): a token-alerts section above everything when
  any Apple ADE or Android token is expiring or expired, a token table with expiry, profiles
  with create (template or JSON; Apple requires choosing its ADE token), edit, delete, and
  Apple device assignment by serial; templates create/delete.
- **Nav**: Application templates, Autopilot devices, Autopilot profiles, Enrollment profiles.
- **Scope addition:** `components/intune/intuneFetch.ts` — one JSON request helper (errors carry
  the BFF status, code, and message) and kit-token styles shared by the four pages instead of
  four copies.
- Structured bodies (template config, profile JSON) are edited as JSON, like the EPIC-016
  policy JSON mode; field-level editors can follow when operators ask for them.
