# T-0125 — Custom script registration and immutable version storage

## Report

EPIC-007 SPEC.md §5 defines `CustomScript` (`id`, `name`, `author`, `enabled`, `alertsEnabled`,
`currentVersionId`) and `CustomScriptVersion` (`id`, `scriptId`, `content`, `markdownTemplate`,
`parameters`, `createdAt`, `createdBy`) with the version row marked **immutable**. §3.3 says
"Saving creates a new version (never overwrites)."

Deliver:

- A numbered, forward-only migration (`0005_custom_scripts.sql`) for both tables.
- `portal/db/src/custom-script-repository.ts`: register a script, append an immutable version,
  advance `currentVersionId`, list versions, and toggle `enabled`/`alertsEnabled`; a version row
  cannot be updated or deleted. Mutations write audit events (`03-database.md` §6).
- Tests for version immutability, append-and-advance, and audit emission.

## Acceptance

- [ ] Saving a script creates a new version and never mutates an existing one.
- [ ] The current version pointer advances to the newly created version.
- [ ] Attempting to update or delete a version fails.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
