# T-0324 — App assignment with plan preview and audit

## Report

EPIC-017 SPEC.md §4.2 requires assignment to groups with intent
(required/available/uninstall) behind a **plan preview** before apply, and §9 names assignment
mistakes as a risk mitigated by preview + confirmation. §6 fixes
`POST /v1/tenants/{id}/apps/{appId}/assign`.

Deliver `Set-IntuneAppAssignment.ps1` + `set-intune-app-assignment.ps1` and the BFF route behind
the T-0108 gated-write seam. The worker resolves the requested group + intent changes into a plan
(added/removed assignments with current state), applies on confirm, and captures before/after.
The app is validated against the T-0321 app-type registry; every write is audited.

## Acceptance

- [x] The assign route returns a plan listing group intent changes before any write.
- [x] Apply creates/updates assignments and records before/after; the app must exist in the T-0321 registry.
- [x] Every assignment change is audited with actor and result.
- [x] Tests cover the worker and route and fail without them.
- [x] No file outside `scope` is modified.

## Resolution

- **Plan:** the worker reads the app with its assignments, checks its OData type against the
  T-0321 registry (404 missing, 501 unsupported), resolves each requested group /
  All users / All devices target to add, update, remove, or unchanged, and validates that
  groups exist. `merge` (default) keeps unnamed targets; `replace` removes them. Exclusion
  assignments are always kept. `available` to All devices is rejected (Intune offers it to users
  only).
- **Confirmation:** the plan carries a `planHash` (SHA-256 over app id and the after-set).
  Apply must echo it as `confirmPlan`; the worker re-plans against live Graph state and
  returns 409 `intune.app.assign.plan_changed` if it no longer matches, 422 if the plan is
  invalid. This is the SPEC §9 "preview + confirmation" guard, in place of an
  Idempotency-Key.
- **Apply:** Graph `/assign` replaces the whole set, so the worker posts the after-set once
  (existing targets keep their Graph `settings`). One audit event per changed target, with
  actor, before/after intent, and result; a failed write is audited and the route returns 502.
- **Not verified live:** Graph calls are mocked (beta `mobileApps/{id}/assign`).
