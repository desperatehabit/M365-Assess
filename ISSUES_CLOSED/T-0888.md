# T-0888 — Remove fabricated sample data from the test-packs and custom-tests pages

## Report

Three production pages fabricate data instead of rendering only live API responses:

- `portal/web/src/app/test-packs/page.tsx:51` defines `DEFAULT_PACKS` (a hardcoded CIS/E8 catalogue
  with invented check lists), seeds `useState` with it (`:73`), and retains it whenever
  `/v1/test-packs` fails (`:85-88` "Fallback to default catalogue").
- `portal/web/src/app/test-packs/[id]/page.tsx:55-67` ships a hardcoded sample `PackReport`
  containing fabricated "Fail" findings, used as the initial report and kept whenever the API returns
  no `results` (`:74-76`).
- `portal/web/src/app/custom-tests/page.tsx:139` defines `DEFAULT_CUSTOM_TESTS` with fabricated
  records and fixed dates, used as initial state (`:167`) and kept on fetch failure (`:184` "Use defaults").

These must be replaced with real empty/loading/error states; no fabricated data may be shown.

## Acceptance

- [ ] The three pages no longer define or fall back to fabricated data.
- [ ] Empty and error states render instead of sample content.
- [ ] A test asserts that an API failure shows the error state and no sample rows.
- [ ] No file outside `scope` is modified.
