# T-0326 — App upload wizard and Queued Applications page

## Report

EPIC-017 SPEC.md §3.2 fixes the upload `Wizard`: choose app type → provide source (package upload,
Store link) → detection/requirement rules → assignment → confirm. The **Queued Applications**
page shows queue progress and reuses the EPIC-003/EPIC-007 queue tracking. Per §11.1 the wizard
offers Win32 and Store sources in v1; other source types are shown disabled with a "not yet
supported" note.

Deliver the upload wizard page + `AppUploadWizard` component (multi-step, validating the package
against the signed-URL/size limits from T-0322) and the `QueuedApplications` page reading the
T-0323 queue status route, with re-run on failure. Kit tokens only.

## Acceptance

- [x] The wizard walks app type → source → rules → assignment → confirm and posts to the upload route.
- [x] Unsupported source types are visibly disabled, not silently accepted.
- [x] The Queued Applications page shows per-item progress and offers re-run for failed items.
- [x] Component tests cover the wizard steps and the queue view and fail without them.
- [x] No file outside `scope` is modified.

## Resolution

- **Wizard** (`AppUploadWizard`): type → source → rules → assignment → confirm. Office, Edge,
  MSP, and Choco are disabled radios marked "Not yet supported." Win32 takes a `.intunewin`
  checked for name, emptiness, and the 8 GiB artifact-tier cap before upload; Store takes the
  package identifier. Win32 rules: detection rules (file, registry, MSI, script),
  architectures, minimum Windows release. Confirm uploads the package to
  `POST .../apps/packages?fileName=` (the T-0842 route), previews through
  `POST .../apps/upload` with `preview: true`, and queues on submit. An unchanged package is
  not re-uploaded when stepping back and forth. Prefills from the T-0325 detected hand-off.
- **Assignment step:** the T-0323 upload API takes no assignments and the app has no id until
  the queue finishes, so the step explains that assignment follows the upload. The queue page
  offers Assign on succeeded items (the page is T-0843). Nothing the operator picks is
  silently dropped, because the step collects nothing.
- **Queued Applications** (`QueuedApplications`): state badge, progress as finished steps
  against the per-type plan (win32 7, store 1), expandable worker steps, Re-run for failed
  items, Assign for succeeded ones; polls every 5 s while any item is queued, uploading, or
  committing, and stops when all settle. Read-only callers (`canWrite={false}`) see state only.
- Kit tokens only (tests assert no hex literals in inline styles).
- The package ingest route (T-0842) and route mounting (T-0844) are still needed before this
  works against the running BFF.
