# T-0661 — DomainCheck history entity, migration, and repository

## Report

EPIC-034 SPEC.md §5 fixes the `DomainCheck` entity: `id`, `tenantId`, `domain`, `at`, `records`,
`health`, `recommendations[]`, stored as history/trend, plus an `AuditEvent` for domain
add/remove. §3.4 and §4.3 require scheduled analysis results to be stored and diffed to detect
changes, so the row must be append-only over time.

Add a numbered, forward-only migration under `portal/db/migrations/` and a
`domain-repository.ts` implementing the SPEC §5 shape behind the ADR-0015 repository interface;
extend the EPIC-001 repository index. Expose append of a check, latest-by-domain, list-by-domain
history for trend, and range queries for change detection. No DNS resolution or Graph calls
belong here.

## Acceptance

- [ ] The migration is forward-only, re-runnable, and creates `DomainCheck` with the SPEC §5
      columns.
- [ ] The repository appends checks and returns latest-per-domain plus an ordered history.
- [ ] Range queries used by change detection return the prior and current check for a domain.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
