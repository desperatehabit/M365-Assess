# T-0422 — Filter edit/create/delete/enable with plan preview

## Report

EPIC-022 SPEC.md §2 (US-1), §3.1, §4.1, and §8 require spam/anti-phish/malware/connection filter
create/edit/delete and enable/disable via a policy editor with a **plan preview** before apply.
§4.1 and §8 require **disabling a filter to be flagged as security-impacting**; §9 risk "filter
misconfiguration weakening protection" is mitigated by plan preview, warnings on disable, and
audit.

Deliver `domain/filters/policy-guard.ts`, which validates a proposed filter policy and classifies
disable/weakening changes as security-impacting. Add the write routes on `filters.ts` and the
`Set-Filter.ps1` worker job plus `set-filter.ps1` entrypoint. Every write routes through the
EPIC-006 gate (T-0107), captures before/after, and writes an `AuditEvent`; a disabling change
surfaces the warning before apply. Extend `portal.v1.yaml`. Tenant and credential records are
EPIC-002 (prose dependency).

## Acceptance

- [ ] Filter create/edit/delete and enable/disable apply through the EPIC-006 gate with before/after and audit.
- [ ] The plan preview shows the resulting policy before apply.
- [ ] Disabling a filter (or otherwise weakening protection) is flagged before apply.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
