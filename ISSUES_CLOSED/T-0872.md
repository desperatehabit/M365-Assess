# T-0872 — MFA reset web client path does not match the BFF route

## Report

`portal/web/src/lib/mfaApi.ts:149` posts to
`/v1/tenants/{tenantId}/users/{userId}/reset-mfa`, but the BFF route is
`MFA_RESET_PATH = "/v1/tenants/:tenantId/users/:userId/mfa/reset"` (`portal/bff/src/routes/mfa.ts:340`).

The bulk-reset call similarly targets `/mfa-reset` while the route is
`MFA_BULK_RESET_PATH = "/v1/tenants/:tenantId/users/mfa/reset"` (`mfa.ts:341`). The Next.js rewrite
is path-preserving (`portal/web/next.config.ts:22-24`), so the mismatch is not repaired in transit and
every reset/bulk-reset request 404s. The reset/TAP/push/default-method adapters are otherwise wired in
`portal/bff/src/app.ts:945-953`.

## Acceptance

- [ ] The web reset and bulk-reset calls target the BFF's `/mfa/reset` paths and return non-404.
- [ ] A client test asserts the exact URL for both calls.
- [ ] No file outside `scope` is modified.
