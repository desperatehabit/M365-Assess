# T-0890 — Implement or remove the Invoke-M365Remediation module stub

## Report

`src/M365-Assess/Remediate/Invoke-M365Remediation.ps1` is exported from the module
(`src/M365-Assess/M365-Assess.psm1:263`) but is a scaffold: both `-Plan` and `-Apply` throw
`[System.NotImplementedException]` (`:37`, `:41`), and the docstring says "scaffold stubs in T-0101
… raise NotImplementedException until the plan and apply tickets land". The module's own test asserts
the stub (`tests/Remediate/Invoke-M365Remediation.Tests.ps1:50,54` expect "*not implemented*"). EPIC-006
is marked closed and the portal implements planning/applying independently in
`portal/workers/M365Portal.Workers/`, so the public module function is a dead stub.

Decide and implement one of:

- Implement `Invoke-M365Remediation -Plan`/`-Apply` in the module (the domain layer the SPEC says the
  module owns), or
- Remove the function from the module's public surface (psm1 export + file + test) if the portal
  workers are the intended home, and update the SPEC/README accordingly.

## Acceptance

- [ ] No exported module function raises `NotImplementedException`.
- [ ] The chosen direction is recorded in the ticket, and the test suite asserts the new behavior.
- [ ] No file outside `scope` is modified.

## Resolution

Direction chosen: **implement**. `Invoke-M365Remediation -Plan` (read-only plan from failed findings) and `-Apply` (gated execution through `Invoke-RemediationAction`, behind ShouldProcess and the validation hard gate) now live in the module. No exported function raises `NotImplementedException`; the test suite asserts the new behaviour (94 Remediate tests passing).
