# T-0329 — Enrollment profiles (Apple ADE / Android) with token expiry

## Report

EPIC-017 SPEC.md §3.5 and §4.4 define Apple ADE (DEP) and Android Enterprise enrollment profiles:
CRUD, assignment to devices/groups, and Apple/Android **token status with expiry** surfaced as an
alert (EPIC-029). §5 adds `EnrollmentProfileTemplate` (`id`, `name`, `platform`, `profileJson`)
and §6 fixes `GET`/`POST`/`PATCH`/`DELETE /v1/tenants/{id}/enrollment-profiles`.

Deliver `Set-EnrollmentProfile.ps1` + entrypoint, migration
`0085_enrollment_profile_templates.sql`, an `enrollment-profile-templates.ts` repository, and the
CRUD routes behind the T-0108 gated-write seam. The profile payload is validated per platform and
token expiry is read from Graph and returned so EPIC-029 can raise the expiry alert; each write is
audited with before/after.

## Acceptance

- [x] Enrollment profile CRUD works for Apple ADE and Android Enterprise, validated per platform.
- [x] Apple/Android token status and expiry date are returned for alerting.
- [x] Each write is audited with before/after.
- [x] Tests cover the route and worker and fail without them.
- [x] No file outside `scope` is modified.

## Resolution

- **Migration** `0085_enrollment_profile_templates.sql` (the ticket named `0018` and `0043`;
  next free number), with a platform CHECK and case-insensitive unique name.
- **Per-platform validation** (`validateEnrollmentProfile`, used for templates and live writes):
  Apple ADE requires `depIOSEnrollmentProfile` or `depMacOSEnrollmentProfile`; Android
  Enterprise defaults `androidDeviceOwnerEnrollmentProfile` and requires a supported
  `enrollmentMode`; both need a `displayName` and may not carry Graph-managed fields or the
  enrollment secrets (`tokenValue`, `qrCodeContent`, `qrCodeImage`). The generic credential-key
  check from app deployments is deliberately not used: it would reject Android's legitimate
  `enrollmentTokenType`.
- **Worker** (`Set-EnrollmentProfile.ps1`): `list` returns every profile and every token (Apple
  ADE `depOnboardingSettings` and each Android profile's token) with expiry, days remaining, and
  `ok` / `expiring` (< 30 days) / `expired` / `unknown`. `create` / `update` / `delete` /
  `assign` preview a plan with before/after or apply and return an audit event with
  before/after. Delete needs the exact profile name. Apple profiles are assigned to device
  serials (`updateDeviceProfileAssignment`); Android profiles are not assignable (devices enroll
  with the token), so that is a 400. Enrollment secrets are stripped from every result, plan,
  and audit event.
- **Routes**: live CRUD at `/v1/tenants/{id}/enrollment-profiles` (+ `/:profileId/assign`), with
  create-from-template; template CRUD at `/v1/enrollment-profile-templates`. The list response
  adds `alerts` (tokens expiring or expired) for EPIC-029 to raise. Permissions reuse
  `Endpoint.Autopilot.Read` / `.ReadWrite` (SPEC §3 groups enrollment under Autopilot &
  Enrollment); writes also accept `Remediation.Apply`.
- **Not verified live:** Graph calls are mocked (beta for ADE and Android enrollment profiles).
