# T-0022 — Tenant CRUD API with exclude and error states

## Report

EPIC-002 SPEC.md §6 defines the tenant surface: `GET /v1/tenants` (filter status/source/group),
`POST /v1/tenants`, `GET /v1/tenants/{id}`, `PATCH /v1/tenants/{id}` (edit / exclude / include),
and `DELETE /v1/tenants/{id}` (soft). §4.4 fixes exclude/error semantics: `Exclude` sets
`excluded: true` + `excludeReason`/`excludeDate` and excluded tenants are skipped by runs while
remaining visible; repeated connect failures increment `errorCount` and crossing a threshold
flips `status: error` with `lastError`.

Deliver the route handlers against the T-0021 repository, with tenant-scoped reads and writes
intersected against the caller's RBAC scope (T-0013; `05-programming.md` §3), structured errors,
and an updated OpenAPI document matching the implementation. Every mutation writes an
`AuditEvent` (`03-database.md` §6).

## Acceptance

- [ ] All five endpoints are implemented and match the OpenAPI document.
- [ ] Exclude/include round-trips `excluded`/`excludeReason`/`excludeDate`; a failed connect
      increments `errorCount` and can flip `status` to `error`.
- [ ] A request for a tenant outside the caller's scope returns a structured error and is never
      widened.
- [ ] Every mutation writes an audit event; a test asserts it.
- [ ] No file outside `scope` is modified.
