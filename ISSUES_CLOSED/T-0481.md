# T-0481 — SharePointTemplate and SiteOperation persistence

## Report

EPIC-025 SPEC.md §5 fixes the persisted entities: `SharePointTemplate` (`id`, `name`,
`siteType`, `settings`, `variables`), `SiteOperation` (`id`, `tenantId`, `siteId`,
`operation`, `state`, `by`, `at`, `result`) as the audit trail, and `AuditEvent` for every
write; sites are read live from Graph/SPO. ADR-0015 and `03-database.md` §5 require a numbered,
forward-only migration behind the repository interface.

Deliver migration `0033_spo_site_operations.sql` extending the `0001_init` schema (do not reuse a
claimed lower number), storing `settings`/`variables` as JSON text, plus
create/get/update/list methods on `portal/db/src/repository.ts` and `sqlite-repository.ts` for
both entities. `SiteOperation` is append-forward (state transitions recorded in place). This
ticket adds no routes and no worker code.

## Acceptance

- [ ] Migration 0033 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes `SharePointTemplate` CRUD and `SiteOperation` create/get/update/list, tenant-scoped.
- [ ] `settings`/`variables` round-trip as JSON; no secret value is stored.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
