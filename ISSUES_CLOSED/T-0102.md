# T-0102 — Resolve-Remediation classification with sub-number stripping

## Report

EPIC-006 SPEC.md §4.1 steps 3-4: for each finding, `Resolve-Remediation` looks up the registry
entry, but the stored finding `CheckId` is sub-numbered by `SecurityConfigHelper`
(e.g. `CA-REPORTONLY-001.1`). The resolver must strip the `\.\d+$` suffix to key the registry
(`CA-REPORTONLY-001`) and classify the check: `remediation.powershell.command` present →
automated; else `remediation.portal` → manual; else `undetermined`, flagged for triage.

Build `Resolve-Remediation` in the `Remediate/` folder. Load
`src/M365-Assess/controls/registry.json` once, index it by `checkId`, and return the mode, the
stripped registry key, the command, `remediation.portal.path`/`steps`, `licensing.minimum`, and
`remediation.notes` so plan generation and gating can consume it. Unknown or unmatched ids
resolve to `undetermined` rather than throwing. Dot-source the new file from `M365-Assess.psm1`.

## Acceptance

- [ ] A sub-numbered id (`X-1`/`CA-REPORTONLY-001.1`) resolves to registry key `CA-REPORTONLY-001`; a test asserts it fails without the strip.
- [ ] Classification returns `automated`, `manual`, or `undetermined` per SPEC §4.1 step 4.
- [ ] An unknown id resolves to `undetermined`, not an exception.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
