# T-0322 — AppDeployment persistence and package storage with signed short-lived URLs

## Report

EPIC-017 SPEC.md §5 defines `AppDeployment` (`id`, `tenantId`, `appType`, `state`, `payload`,
`results`, `createdBy`) and §9 names large app packages / storage as a risk. §11.2 is resolved to
an **artifact tier with signed short-lived URLs**: packages are stored off the database
(filesystem artifact tier) per ADR-0015 and EPIC-003's artifact handling (T-0048), and handed to
the worker as a short-lived signed reference, never a raw path.

Deliver a numbered forward-only migration `0082_app_deployments.sql`, an `app-deployments.ts`
repository behind the ADR-0015 interface (no raw SQL outside `portal/db/`), and an
`app-packages.ts` storage helper that persists an uploaded package to the artifact tier and mints
a signed, short-lived URL with an expiry and size limit. No tenant writes occur here.

## Acceptance

- [x] A migration creates `AppDeployment`; the repository round-trips the §5 fields and is tenant-scoped.
- [x] Package storage writes to the artifact tier and issues a signed URL with a bounded TTL and size cap.
- [x] No package bytes or credentials are persisted in the database or returned in API responses.
- [x] Tests cover the repository and the signed-URL helper and fail without them.
- [x] No file outside `scope` is modified.

## Resolution

The migration is `0082_app_deployments.sql`: the ticket named both `0015` (sorts before applied
migrations, breaking forward-only order) and `0040` (already taken), so it takes the next free
number. `app_deployments` state runs `queued → uploading → committing → succeeded`, with
`failed → queued` as the re-run path; transitions are guarded in `WHERE` so a concurrent move
loses rather than overwrites. The repository refuses payload/results over 64 KiB and any
credential-like key (`secret`, `password`, `token`, …).

Packages stream to `<artifactPath>/app-packages/<tenantId>/<packageId>/package.bin` (+
`meta.json`) with the cap (default 8 GiB) enforced while writing. Signed URLs are HMAC-SHA256
over tenant, package, and expiry; default lifetime 15 minutes, maximum 1 hour; verified in
constant time (403 tampered, 410 expired). Wiring a signing secret into `config.ts` and the
download route belong to T-0323.
