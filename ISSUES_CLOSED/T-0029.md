# T-0029 — GdapTenantSource behind a feature flag

## Report

ADR-0017 scopes GDAP as an **optional, additive source behind a feature flag**: enabling it
never affects direct tenants, and Partner Center refresh-token handling, CPV consent, and GDAP
role mapping stay contained to this path. EPIC-002 SPEC.md §4.3 defines the workflow: enumerate
`tenantRelationships/delegatedAdminRelationships?$filter=status eq 'active'`, upsert tenants
with `source: gdap` and relationship metadata, mark excluded/unavailable relationships rather
than dropping them, and track `GdapRelationship.cpvConsentState`. §6 defines
`POST /v1/gdap/sync` (only when enabled).

Deliver `GdapTenantSource` implementing the T-0028 seam, a worker entrypoint that performs the
Partner Center enumeration, the gated route, and the `GdapRelationship` satellite persistence.
The source is disabled unless the feature flag is set; direct tenants are unaffected either way.

## Acceptance

- [x] With the flag off, no GDAP route is served and direct tenants are unchanged.
- [x] Sync upserts `source: gdap` tenants plus relationship/CPV metadata; excluded relationships
      are marked, not silently dropped.
- [x] A test asserts enabling/disabling GDAP leaves direct tenants untouched.
- [x] No file outside `scope` is modified.
