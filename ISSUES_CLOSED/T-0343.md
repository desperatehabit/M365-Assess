# T-0343 — DeviceAction persistence, append-only history

## Report

EPIC-018 SPEC.md §5 defines `DeviceAction` (`id`, `tenantId`, `deviceId`, `action`, `reason`,
`state`, `appliedAt`, `appliedBy`, `result`) as **append-only**, and §3.3 requires every action to
record actor, reason, and result. §6 fixes `GET /v1/tenants/{id}/devices/{deviceId}/actions` for
action history.

Deliver migration `0044_device_actions.sql` and a `device-actions.ts` repository behind the
ADR-0015 interface (append-only and tenant-scoped, enforced in the repository, not callers). Add
the read route for per-device action history. This ticket defines the record other action tickets
(T-0344, T-0345) write through; it performs no tenant writes itself.

## Acceptance

- [ ] A migration creates `DeviceAction`; the repository round-trips the §5 fields and is tenant-scoped.
- [ ] The repository enforces append-only (no update/delete API) and exposes query-by-device.
- [ ] `GET /v1/tenants/{id}/devices/{deviceId}/actions` returns history, newest first.
- [ ] Tests cover repository and route and fail without them.
- [ ] No file outside `scope` is modified.
