# T-0305 — IntuneTemplate persistence and template CRUD API

## Report

EPIC-016 SPEC.md §5 defines `IntuneTemplate` — `id`, `name`, `platform`, `policyType`,
`policyJson`, `assignments`, `source`. §6 fixes `GET`/`POST`/`PATCH`/`DELETE /v1/intune-templates`.
§3.1's `Clone to template` action and §3.2's deploy drawer both consume these templates; policies
are read live from Graph while templates persist (§5). The T-0301 registry provides the valid
`platform`/`policyType` pairs.

Deliver a numbered forward-only migration and repository for `IntuneTemplate`, plus the BFF CRUD
routes behind the RBAC `intune.templates` permission (§7). Template create validates
`platform`/`policyType` against the registry and `policyJson` as well-formed, and `source` is
constrained to `local` for v1 (community is deferred, mirroring EPIC-015). No tenant writes.

## Acceptance

- [ ] A migration creates the `IntuneTemplate` table; the repository round-trips the §5 fields.
- [ ] CRUD routes validate `platform`/`policyType` against the registry and validate `policyJson`.
- [ ] `Clone to template` can persist a policy's JSON and assignments as a template.
- [ ] A test covers the repository/routes and fails without them.
- [ ] No file outside `scope` is modified.
