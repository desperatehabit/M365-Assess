# T-0205 — Offboarding job/step model and v1 plan builder

## Report

EPIC-011 SPEC.md §5 fixes two entities: `OffboardingJob` (`id`, `tenantId`, `userIds[]`,
`options`, `state`, `createdAt`, `createdBy`) and `OffboardingStep` (`jobId`, `order`, `action`,
`state`, `result`, `error`, `appliedAt`). §4.4 builds a **plan of steps** before any execution,
and §11.1 resolves v1 to the **first-cut step set: disable sign-in + license removal + mailbox
conversion + group removal**, with the full CIPP parity set as a later expansion.

Add the next forward-only migration under `portal/db/migrations/`, a
`offboarding-repository.ts` implementing both entities (steps individually addressable and
re-runnable), and extend the repository interface/index. Build
`portal/bff/src/domain/offboarding/plan.ts` mapping wizard options to an ordered plan of steps
from the v1 catalogue, rejecting unknown option keys and recording the resolved mailbox access
mode. No tenant write happens here.

## Acceptance

- [ ] Migration is forward-only and creates `OffboardingJob`/`OffboardingStep` with the §5 columns.
- [ ] The plan builder emits ordered steps for the resolved v1 step set and is deterministic for the same options.
- [ ] An option outside the v1 catalogue is rejected, not silently ignored.
- [ ] Repository round-trips a job with its steps and updates one step's state/result.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
