# T-0061 — Dashboard read-model contracts and repository queries

## Report

EPIC-004 SPEC.md §4.1 and §5 make the dashboard a **read model over persisted rows**: widgets
read `Finding`/`Run` (EPIC-003) and `StandardCompare`/`DriftDeviation` (EPIC-008/009), and "no
live tenant calls originate from the browser" (§10). This ticket defines the typed payloads and
the repository queries that back them; it adds no new tenant-scoped tables (§5).

Deliver:

- `portal/contracts/src/dashboard.ts`: typed per-tenant `DashboardPayload` and all-tenants
  `FleetPayload` shapes (score/metrics/alerts/identity/compliance fields), explicit about the
  empty-state signal when a tenant has no completed run.
- `portal/db/src/dashboard-repository.ts`: aggregation queries over `Run`/`Finding` that return
  the per-tenant payload and the fleet list, filtering by the caller's tenant scope so the
  all-tenants view cannot leak out-of-scope tenants (§7, §9 risk "scope leakage"). It extends
  the repository seam from T-0009 without editing `repository.ts`.
- Unit tests covering empty data, scope filtering, and a populated tenant.

## Acceptance

- [x] Typed `DashboardPayload` and `FleetPayload` exist and are sourced only from persisted rows.
- [x] The all-tenants query returns only tenants in the caller's scope.
- [x] A tenant with no completed run produces a payload that signals "empty" rather than zeros.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
