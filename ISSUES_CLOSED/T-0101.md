# T-0101 — Remediate folder scaffold and read-only boundary guard

## Report

EPIC-006 SPEC.md §8 and [`06-remediation.md`](../../docs/portal-specs/00-guides/06-remediation.md)
§2.1 require remediation code to live in a new top-level `src/M365-Assess/Remediate/` folder,
deliberately **outside** the read-only collector scan, and require the scan's folder list plus
`tests/Smoke/Collector-ReadOnly.Tests.ps1` to be updated in the same ticket that introduces the
folder so the boundary is explicit and tested. `scripts/Test-CollectorReadOnly.ps1:92-102`
lists the nine collector folders; `Remediate` must **not** be added to it.

Deliver a folder entrypoint `Invoke-M365Remediation.ps1` — `[CmdletBinding(SupportsShouldProcess)]`,
with `-Plan`/`-Apply` switches and a not-implemented body for now — dot-sourced from
`M365-Assess.psm1` beside the other module helpers. Extend the smoke test so it asserts the
`Remediate/` folder is excluded from the scan (a mutating cmdlet there is not reported) while the
existing collector-fixture detection still fires. No collector may import remediation functions.

## Acceptance

- [ ] `src/M365-Assess/Remediate/Invoke-M365Remediation.ps1` exists and exposes `-Plan`/`-Apply` with `SupportsShouldProcess`.
- [ ] `Test-CollectorReadOnly` still scans the nine collector folders and never scans `Remediate/`; the smoke test asserts it.
- [ ] `Import-Module` loads the module with the new file dot-sourced.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
