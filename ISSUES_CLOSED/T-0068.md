# T-0068 — Custom dashboard tab and layout editing

## Report

EPIC-004 SPEC.md §3.4 defines the Custom tab as a configurable widget canvas: add/remove
widgets, reorder, and resize within the grid, with layout persisted per user (and tenant) and a
**Reset to default**. Widgets offered are those the caller's RBAC scope permits. §11.2 adopts per
user + tenant persistence and §11.4 adopts stock-widgets-only (no scripted widgets) for v1.

Deliver:

- `CustomDashboard` canvas that consumes `GET /v1/dashboard/widgets` (RBAC-filtered) and the
  layout from T-0063.
- `WidgetPicker` to add/remove widgets; drag-reorder and grid resize that emit a layout save.
- Save/reset wiring to `PUT /v1/dashboard/layout`, with an optimistic-then-revert UI on failure.
- Component tests for add/remove/reorder/save/reset.

## Acceptance

- [x] Adding, removing, reordering, and resizing widgets persists to the layout endpoint.
- [x] Reset to default restores the stock layout.
- [x] Widgets outside the caller's RBAC scope are not offered.
- [x] A test covers the change and fails without it.
- [x] No file outside `scope` is modified.
