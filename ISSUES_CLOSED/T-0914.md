# T-0914 — In-portal tenant onboarding fails on Windows

## Report

**Tenants → Add tenant** (create app registration) failed on a Windows machine with
Microsoft.Graph 2.41.2, in four successive ways:

1. `InteractiveBrowserCredential authentication failed: A window handle must be configured.`
   Graph SDK 2.34.0 and later always sign in through WAM on Windows. `MSAL_ALLOW_WAM=0` (which
   the script sets) and `Set-MgGraphOption -DisableLoginByWAM` are both ignored; tested from
   2.25.0 to 2.41.2 with a worker spawned like the BFF's (`windowsHide: true`): 2.33.0 and earlier
   fall back to the browser, 2.34.0 and later fail. WAM parents its prompt on the console window,
   and a hidden worker has none.
2. `The term 'Get-M365ConnectionProfile' is not recognized`. The script dot-sources
   `Save-M365ConnectionProfile.ps1` but not `Get-M365ConnectionProfile.ps1`. Inside the module
   both are loaded; the worker dot-sources the script alone.
3. A retry failed with `An app named 'M365-Assess-Reader' already exists`. Resuming an existing
   app was implemented only for PFX files (macOS/Linux); on Windows the key is in
   `Cert:\CurrentUser\My`.
4. Resume could never match on any platform: Entra stores a certificate key's
   `customKeyIdentifier` as the thumbprint text, which the Graph SDK returns base64-decoded
   (30 bytes). The helper compared it as raw SHA-1 bytes (20).

## Resolution notes

- `Invoke-TenantOnboarding.ps1`: when the worker is on Windows with no console window
  (`Test-WorkerHasConsoleWindow`), `Invoke-ConsentInSignInWindow` runs Grant-M365AssessConsent
  in a new, visible PowerShell window (`Start-Process -WindowStyle Normal -Wait`). Parameters
  and the result pass through JSON files in a private temp folder, removed afterwards. With a
  console window (a terminal), or off Windows, it runs in-process as before.
- Rejected: allocating a console inside the worker (`FreeConsole`/`AllocConsole`). The window
  is created hidden, and the PowerShell host keeps the old console handles, so the sign-in
  failed with "The handle is invalid".
- `Grant-M365AssessConsent.ps1` dot-sources `Get-M365ConnectionProfile.ps1`, and on Windows
  resumes an existing app through `Find-M365AssessStoreCertificate` (newest unexpired store
  certificate with the bootstrap subject, a private key, and a thumbprint registered on the app).
- `New-M365AssessCertificate.ps1`: `Get-M365AssessRegisteredThumbprint` reads a key identifier
  in both forms (base64 text and raw bytes); both resume helpers use it.
- Tests: 10 new in the onboarding worker suite (routing, the real runner via `Start-Process`
  without a new window, failure, cleanup), 5 for the store lookup including the real identifier
  format, 1 for the standalone load.

## Verification

2026-11-18, live, on the Phase 2 test tenant, Windows, Microsoft.Graph 2.41.2,
ExchangeOnlineManagement 3.7.2: onboarding from the portal opened the sign-in window, resumed
the app a failed earlier run had created (no duplicate), granted permissions and Exchange roles,
saved the connection profile, and stored the tenant credential. Before the retry, a read-only
app-only sign-in with the store certificate confirmed it was the key registered on the app, and
the lookup run against the app's real key credentials found it.
