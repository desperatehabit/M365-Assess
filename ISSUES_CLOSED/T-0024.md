# T-0024 — Test-connection endpoint and worker

## Report

EPIC-002 SPEC.md §4.1 step 5 and §4.2 step 3 require a **Test connection** action that runs a
live, read-only connect and shows pass/fail per service; §6 defines
`POST /v1/tenants/{id}/test-connection`. §10 makes "reports per-service pass/fail without
writing to the tenant" an acceptance criterion. This is a read-only operation and must stay on
the assessment path, never the remediation engine.

Deliver a worker entrypoint `Test-TenantConnection.ps1` that resolves the credential via the
T-0011 path, performs a read-only connect through the module's existing connect code, and
returns a per-service result envelope; plus the BFF route that enqueues it (T-0010) and records
`lastValidated` on success. Secrets materialize only in the child process.

## Acceptance

- [x] The endpoint returns per-service pass/fail and writes no tenant configuration.
- [x] A successful test records `lastValidated`; a failure increments the tenant error state.
- [x] A Pester test drives the worker with a stub credential and asserts the result shape and
      that no secret is echoed.
- [x] No file outside `scope` is modified.
