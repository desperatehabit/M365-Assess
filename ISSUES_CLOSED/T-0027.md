# T-0027 — Tenant variables and %var% substitution

## Report

EPIC-002 SPEC.md §3.5 and §5 define tenant variables as key/value rows per tenant (or global),
with `isSecret` masking in the UI, and §10 makes "tenant variables substitute in standards
templates" an acceptance criterion. The `%name%` placeholder syntax is fixed by
`03-database.md` §3.2.

Deliver variable CRUD (`GET`/`POST`/`PATCH`/`DELETE`) with secret values stored by reference and
masked in responses, plus a `variable-substitution.ts` helper that resolves `%name%` tokens
against global then tenant scope, fails clearly on an unknown token, and never emits a secret
value into logs. Every mutation writes an `AuditEvent`.

## Acceptance

- [ ] `%name%` tokens resolve global-then-tenant precedence; an unknown token yields a clear
      error rather than an empty string.
- [ ] Secret variable values are masked in every API response and audit record.
- [ ] Variable CRUD is tenant-scoped and audited.
- [ ] No file outside `scope` is modified.
