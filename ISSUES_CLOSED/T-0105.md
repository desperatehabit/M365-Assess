# T-0105 — Plan generation worker and remediation plans API

## Report

EPIC-006 SPEC.md §4.1 defines plan generation: load the run's findings where
`status ∈ {Fail, Warning, Review}` (configurable), resolve each with `Resolve-Remediation`
(T-0102), classify, evaluate gates (T-0104), persist a `RemediationPlan` + `RemediationAction`
rows (T-0103), and render — with **no tenant writes**. SPEC.md §6 exposes
`POST /v1/remediation/plans` to generate and `GET /v1/remediation/plans/{planId}` to read a plan
with its actions.

Following ADR-0014 the domain work runs in a PowerShell worker: add a `Plan-Remediation.ps1`
job handler plus a thin `plan-remediation.ps1` entrypoint that reads the job envelope, builds
the plan, and returns the result envelope. The BFF route validates RBAC/scope, enqueues the job
through the EPIC-001 queue (T-0010), persists via the repository (T-0009), and serves the plan;
extend `portal.v1.yaml` with both operations and the structured error shape. Depends on EPIC-002
for the run/tenant findings it reads, but that is a data dependency, not a code dependency.

## Acceptance

- [ ] `POST /v1/remediation/plans` enqueues a worker job and returns a persisted plan id; the worker performs no tenant writes.
- [ ] `GET /v1/remediation/plans/{planId}` returns the plan plus one action per finding with mode (`auto`/`manual`) and state.
- [ ] Findings are selected from `Fail`/`Warning`/`Review` only; sub-numbered check ids resolve correctly through T-0102.
- [ ] A test covers generation + read and fails without it.
- [ ] No file outside `scope` is modified.
