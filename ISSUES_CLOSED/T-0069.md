# T-0069 — Widget drill-through to the findings table

## Report

EPIC-004 SPEC.md §4.2: clicking a widget's metric sets the findings filter and navigates to the
findings table, preserving tenant and filter context. §3.1 says each widget carries a
drill-through affordance; §10 requires the drill-down to open findings with the correct filter.
EPIC-003 SPEC.md §3.3 notes EPIC-004 owns the full findings component while EPIC-003 embeds it.

Deliver:

- `findings-filter.ts`: a typed filter model (tenant + widget-derived predicate) that serializes
  to URL/query state so the findings view can restore it.
- `FindingsDrillThrough`: the shared findings table component (report grid + status/severity
  tokens) that accepts the filter, plus the click handler widgets use to navigate to it.
- Tests asserting a metric click produces the expected filter and that the table applies it.

Note: the runs-side embedding of this table is an EPIC-003 concern (cross-ref in prose); this
ticket delivers the component and filter contract.

## Acceptance

- [x] Clicking a widget metric navigates to findings with the tenant and filter preserved.
- [x] The filter round-trips through the URL so a reload restores the same view.
- [x] A test asserts the filter emitted for a known metric and fails without the code.
- [x] Findings render with the nine-status/severity token vocabulary.
- [x] No file outside `scope` is modified.
