# T-0082 — Headless Chromium PDF render worker over the existing HTML report

## Report

ADR-0016 fixes the PDF pipeline: reports are rendered **server-side by headless Chromium** from
the same self-contained HTML the module already produces (ADR-0008), with a render timeout and
memory cap, running as an EPIC-007 job so it can be scheduled and retried. EPIC-005 SPEC.md
§4.1 step 3 calls the PDF "rendered (pipeline choice — §11)". EPIC-001 SPEC.md §4.2 fixes the
worker envelope contract this handler consumes and produces.

Deliver:

- `portal/workers/render-report.ps1`, a worker entrypoint taking a job envelope and writing a
  result envelope, analogous to T-0006's `run-tenant.ps1`.
- `Invoke-ReportRender.ps1`: writes the builder/executive HTML to a temp path, invokes a **pinned**
  headless Chromium binary in headless print-to-PDF mode, enforces a timeout and memory bound,
  and writes the PDF to the artifact path (not into the DB).
- Reject renderer input that is not produced by our own HTML builders (ADR-0016 failure mode
  "render injection").
- A Pester test driving the handler with a stub Chromium and asserting the PDF artifact + result
  envelope, plus a timeout test.

## Acceptance

- [ ] The worker renders a given HTML file to a PDF artifact and returns a result envelope.
- [ ] A render past the timeout is killed and reported as a failed job.
- [ ] The Chromium version is pinned in configuration.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
