# T-0748 — API client client_credentials authentication and IP allow-list

## Report

EPIC-038 SPEC.md §4.3: a client authenticates via OAuth **client_credentials** against
`api://<appId>/.default`; the service identifies the client by app id, loads `ApiClient`
(role, IP ranges, rate limit, enabled), checks the IP allow-list (`Any` or CIDR; a
`Test-IpInRange` analogue), and then proceeds through the same `Test-PortalAccess` path as a
user. SPEC.md §9 requires hashed secrets and an explicit IP check.

Build `api-client-auth.ts`: validate the bearer token/audience, load the client, verify the
presented secret against `secretHash` (T-0747), reject disabled clients, and resolve the caller
to `Test-PortalAccess` (T-0743). Build `ip-range.ts` with an IPv4/IPv6-correct CIDR matcher.
An out-of-range request is denied and audited (T-0750). Extend the auth middleware introduced by
T-0013.

## Acceptance

- [ ] A valid client_credentials token authenticates and runs through T-0743 as the client's roles.
- [ ] A client outside its IP range is denied; inside is allowed.
- [ ] A disabled client and a bad secret are denied.
- [ ] IP matching handles `Any`, a single CIDR, and a CIDR list for both IPv4 and IPv6.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
