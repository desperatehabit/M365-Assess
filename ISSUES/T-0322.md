# T-0322 — AppDeployment persistence and package storage with signed short-lived URLs

## Report

EPIC-017 SPEC.md §5 defines `AppDeployment` (`id`, `tenantId`, `appType`, `state`, `payload`,
`results`, `createdBy`) and §9 names large app packages / storage as a risk. §11.2 is resolved to
an **artifact tier with signed short-lived URLs**: packages are stored off the database
(filesystem artifact tier) per ADR-0015 and EPIC-003's artifact handling (T-0048), and handed to
the worker as a short-lived signed reference, never a raw path.

Deliver a numbered forward-only migration `0040_app_deployments.sql`, an `app-deployments.ts`
repository behind the ADR-0015 interface (no raw SQL outside `portal/db/`), and an
`app-packages.ts` storage helper that persists an uploaded package to the artifact tier and mints
a signed, short-lived URL with an expiry and size limit. No tenant writes occur here.

## Acceptance

- [ ] A migration creates `AppDeployment`; the repository round-trips the §5 fields and is tenant-scoped.
- [ ] Package storage writes to the artifact tier and issues a signed URL with a bounded TTL and size cap.
- [ ] No package bytes or credentials are persisted in the database or returned in API responses.
- [ ] Tests cover the repository and the signed-URL helper and fail without them.
- [ ] No file outside `scope` is modified.
