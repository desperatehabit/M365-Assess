# T-0864 — Mount and deliver EPIC-034 Domains & DNS routes and worker

## Report

The EPIC-034 factories (`createDomainsRoute`, `createDomainsActionsRoutes`, `createDomainsDnsRoutes`,
`createDomainsRecommendationsRoutes`, `createDomainsScheduleRoutes`) exist under
`portal/bff/src/routes/` and are tested, but `portal/bff/src/app.ts` imports none of them and there is
no adapter under `portal/bff/src/adapters/`, so the endpoints 404.

Worker gap (SPEC §3.2, §4.2, §6): `portal/bff/src/routes/domains-dns.ts:41` names a DNS
record-resolution worker (`check-domain-dns` / T-0664) that does not exist in any form — no wrapper
under `portal/workers/` and no `M365Portal.Workers/Check-DomainDns.ps1` (only `Get-DnsRecommendations.ps1`
and `DnsSelectors.ps1` exist).

Migration `0057_domains_dns.sql`, `domain-repository.ts`, and the UI (`app/domains/page.tsx`,
`app/domains/analyser/page.tsx`, `DnsPanel`, `DnsRecommendations`, `DnsHistoryChart`, `AddDomainWizard`)
exist.

## Acceptance

- [x] Every EPIC-034 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] The DNS record-resolution worker exists and backs the check-dns/history endpoints.
- [x] Domain add/verify/remove/default and DNS analysis run their real workers.
- [x] No file outside `scope` is modified.

## Fix

`createDomainsProviders` binds every route seam to its worker: inventory reads
join the latest stored `DomainCheck` health and run `get-domains.ps1`; writes
run `domain-action.ps1` through the T-0007 envelope and re-check confirmation
before the Graph write; the analyser runs the new `check-domain-dns.ps1` with no
tenant credential (DNS resolution needs none), and recommendations run the new
`get-dns-recommendations.ps1` over the latest stored records.

`createApp` mounts the five route groups over a `SqliteDomainRepository`
(migration 0057) and the DNS TTL cache, with one idempotency store per route set
and the shared audit sink for worker-returned events. The new
`Test-DomainDns.ps1` resolves MX/SPF/DKIM/DMARC/MTA-STS/TLS-RPT, evaluates each
family into pass/warn/fail plus an overall status, excludes
`.onmicrosoft.com`, and emits recommendation explanations; its wrapper and the
recommendations wrapper are Pester-tested. All endpoints are registered in the
permission registry, published through their OpenAPI fragments, and the
checked-in contract is regenerated.
