# T-0727 — Logbook and diagnostics API

## Report

EPIC-037 SPEC.md §3.5 and §4.4 define **Logbook** as a searchable, exportable log of portal
operations (API calls, actions, errors) read from the audit/log tables with filters (actor,
action, tenant, result, date) and correlation IDs, and **Diagnostics** (Advanced) as
container/worker health, cache status, and timers; §6 defines `GET /v1/logbook` and
`GET /v1/diagnostics`; §7 gates both on `CIPP.Admin.*` (EPIC-038); §9 warns of logbook volume
(retention + filters).

Deliver `routes/logbook.ts` (cursor-paginated, filtered read over the append-only audit store,
with roles/tenants scoped by RBAC, plus a CSV/JSON export) and `routes/diagnostics.ts` (health,
cache status, and timer state, reusing the T-0016 health source and adding the diagnostics detail
EPIC-001 left as a stub). Update `portal.v1.yaml`. The UI is T-0729.

## Acceptance

- [ ] Logbook filters by actor, action, tenant, result, and date and paginates; export produces the filtered set.
- [ ] Diagnostics returns worker/container health, cache status, and timers without tenant data.
- [ ] Both endpoints are implemented and match the OpenAPI document; neither leaks secrets.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
