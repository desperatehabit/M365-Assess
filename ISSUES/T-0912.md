# T-0912 — Parked EPIC-041 pages are in the nav with no backend

## Report

EPIC-041 (Integrations, Copilot & Shadow AI) is parked, but three nav entries point at its
pages, and every API call they make returns `request.not_found` from a running BFF:

| Page | Call | BFF state |
|---|---|---|
| `/integrations` | `GET /v1/integrations` | No registry route. Only `/v1/integrations/github` exists. |
| `/copilot/settings` | `GET`/`POST /v1/tenants/{id}/copilot/settings[/apply]` | `copilot-settings-routes.ts` is written but never mounted in `app.ts`. |
| `/copilot/shadow-ai` | `GET`/`PATCH /v1/tenants/{id}/shadow-ai[/{findingId}]` | `shadow-ai-service.ts` exists but has no routes. |

This contradicts the Phase 1 exit condition ("every UI route in the nav has a mounted
backend"). A live operator would land on three broken pages.

## Fix direction

Decide one of the following:

1. Hide the three entries from `AppNav.tsx` while EPIC-041 is parked (smallest change).
2. Mount `createCopilotSettingsRoutes` (already written) and hide only Integrations and Shadow
   AI.

## Acceptance

- [ ] No nav entry leads to a page whose API calls are unmounted.
- [ ] The nav test asserts the chosen set.
- [ ] No file outside `scope` is modified.

## Resolution notes

- Decision: option 1 (hide all three). It is the smaller change, and it keeps EPIC-041 fully
  parked rather than un-parking Copilot settings alone. That needs a maintainer call, and it
  can still be made later by moving the entry back and mounting `createCopilotSettingsRoutes`.
- `AppNav.tsx`: `/copilot/settings`, `/copilot/shadow-ai` and `/integrations` move out of
  `NAV_GROUPS` into an exported `PARKED_NAV_ITEMS`, with a comment saying when to restore
  them. The pages themselves are untouched and still reachable by URL. Only the nav entries are
  gone. `app.ts` and `copilot-settings-routes.ts` are unchanged.
- New `AppNav.test.tsx` (3 tests) asserts the parked set and that none of it is in the nav.
  Nav, shell and settings tests: 35 passed.
- Not changed: `/integrations` is the only page that calls `GET /v1/integrations`. The Settings
  page's Integrations tab does not use it.
