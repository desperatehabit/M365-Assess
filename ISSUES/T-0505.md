# T-0505 — Team edit, archive, clone, and delete operations

## Report

EPIC-026 SPEC.md §2 US-2, §3.1, §4.1, and §8 define the lifecycle: edit, archive, clone, and
delete route through **EPIC-006**; delete requires confirmation. §6 exposes `PATCH`/`DELETE`
`/v1/tenants/{id}/teams/{teamId}`. §8 requires confirmation naming the team and audited writes;
§9 asks for archive-before-delete guidance. §5 records each operation as a `TeamOperation`.

Deliver an `Invoke-TeamAction.ps1` handler (entrypoint `invoke-team-action.ps1`) covering edit,
archive, clone, and delete, applying through the EPIC-006 gated executor (T-0108) and updating
`TeamOperation` (T-0501) with state and result. The routes validate `teams.write` +
`Remediation.Apply`, require explicit confirmation naming the team on delete, and audit each
operation. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Edit, archive, and clone apply through EPIC-006 and record a `TeamOperation`.
- [ ] Delete cannot proceed without an explicit confirmation naming the team; it is audited.
- [ ] Callers without `teams.write` are refused; results are tenant-scoped.
- [ ] A test covers delete confirmation and archive and fails without it.
- [ ] No file outside `scope` is modified.
