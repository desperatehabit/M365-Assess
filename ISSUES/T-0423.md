# T-0423 — Filter template storage, CRUD, and deploy

## Report

EPIC-022 SPEC.md §2 (US-2), §3.2, §4.1, §5, and §6 require filter templates with `View`, `Edit`,
`Clone`, `Deploy`, `Export`, and `Delete`, and a deploy that supports variables (domains, IPs,
action overrides). §5 defines `FilterTemplate` (`id`, `name`, `filterType`, `policyJson`,
`variables`, `source`). Resolved §11.1 uses EXO where it supports the operation; template deploy
applies a persisted policy through the EPIC-006 gate.

Deliver migration `0036_filter_templates.sql` and `filter-template-repository.ts`, plus
`filter-templates.ts` for the §6 `GET`/`POST`/`PATCH`/`DELETE` routes and the
`POST .../deploy` handler. Add `domain/filters/template-deploy.ts` to resolve variables and
validate required ones. Deploy routes through the EPIC-006 gate (T-0107) with before/after and an
`AuditEvent`; a missing required variable is a validation error, not a partial apply. Templates
persist with a local `source`. Extend `portal.v1.yaml`. Tenant and credential records are EPIC-002
(prose dependency).

## Acceptance

- [ ] Migration 0036 applies after the highest existing migration, is re-runnable, and advances `SchemaVersion`.
- [ ] Filter templates create, read, update, soft-delete, and clone.
- [ ] Deploy resolves variables, rejects a missing required variable, and applies through the EPIC-006 gate.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
