# T-0933 — SharePoint collector reads wrong property names and reports "could not verify" as Warning

## Report

About 7 of the 12 SharePoint Warnings in the walk's run come from collector problems rather
than tenant state.

## Causes

1. **Wrong property name.** The collector reads `isUnmanagedSyncClientRestricted`
   (`Get-SharePointSecurityConfig.ps1:205`, `:950`; `Get-SharePointOneDriveReport.ps1:81`). The
   Graph `sharepointSettings` property is believed to be `isUnmanagedSyncAppForTenantRestricted`.
   So **SPO-SYNC-001** and **SPO-ACCESS-002** are always "Not configured → Warning".
2. **Wrong status for "could not verify".** SPO-SHARING-005, SPO-SHARING-006, SPO-B2B-001,
   SPO-MALWARE-002 and SPO-SHARING-008 emit **Warning** for settings
   `/admin/sharepoint/settings` does not expose. They should be **Review**.
3. **Latent false negative in SPO-SITE-001.** It reads `sharingCapability` from `/v1.0/sites`
   (`:86`, `:764`), which the `site` resource does not carry. Any returned site would pass. In
   this run 0 sites came back, which gave "Could not retrieve site list → Warning". Why 0 sites
   were returned with `Sites.Read.All` granted is unexplained.

## Fix direction

- Confirm the property names against a raw response, then correct them.
- Make every "could not verify" or "not exposed by API" path emit Review.
- Read site sharing from a source that has it, or downgrade SPO-SITE-001 to Review. Investigate
  the empty site list.

## Acceptance

- [ ] SPO-SYNC-001 and SPO-ACCESS-002 reflect the tenant's real sync setting.
- [ ] No SharePoint check emits Warning for an unverifiable setting.
- [ ] SPO-SITE-001 never passes on a property that does not exist.
- [ ] No file outside `scope` is modified.
