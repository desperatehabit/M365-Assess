# T-0933 — SharePoint collector reads wrong property names and reports "could not verify" as Warning

## Report

About 7 of the 12 SharePoint Warnings in the walk's run come from collector problems rather
than tenant state.

## Causes

1. **Wrong property name.** The collector reads `isUnmanagedSyncClientRestricted`
   (`Get-SharePointSecurityConfig.ps1:205`, `:950`; `Get-SharePointOneDriveReport.ps1:81`). The
   Graph `sharepointSettings` property is believed to be `isUnmanagedSyncAppForTenantRestricted`.
   So **SPO-SYNC-001** and **SPO-ACCESS-002** are always "Not configured → Warning".
2. **Wrong status for "could not verify".** SPO-SHARING-005, SPO-SHARING-006, SPO-B2B-001,
   SPO-MALWARE-002 and SPO-SHARING-008 emit **Warning** for settings
   `/admin/sharepoint/settings` does not expose. They should be **Review**.
3. **Latent false negative in SPO-SITE-001.** It reads `sharingCapability` from `/v1.0/sites`
   (`:86`, `:764`), which the `site` resource does not carry. Any returned site would pass. In
   this run 0 sites came back, which gave "Could not retrieve site list → Warning". Why 0 sites
   were returned with `Sites.Read.All` granted is unexplained.

## Fix direction

- Confirm the property names against a raw response, then correct them.
- Make every "could not verify" or "not exposed by API" path emit Review.
- Read site sharing from a source that has it, or downgrade SPO-SITE-001 to Review. Investigate
  the empty site list.

## Acceptance

- [ ] SPO-SYNC-001 and SPO-ACCESS-002 reflect the tenant's real sync setting.
- [x] No SharePoint check emits Warning for an unverifiable setting.
- [x] SPO-SITE-001 never passes on a property that does not exist.
- [x] No file outside `scope` is modified.

## Fix

- `Get-SharePointSecurityConfig.ps1`
  - Added the same local `Get-SettingProperty` presence helper used by the Forms
    collector.
  - SPO-SYNC-001 and SPO-ACCESS-002 now read
    `isUnmanagedSyncAppForTenantRestricted` first, falling back to
    `isUnmanagedSyncClientRestricted`. When neither is returned the status is
    `Review` (`Not returned by API`); a real `false` still reports `Warning`.
  - Unverifiable / not-exposed paths now emit `Review` instead of `Warning`:
    SPO-SHARING-005 (including a missing expiration-days property),
    SPO-SHARING-006 (including a missing reauthentication-days property),
    SPO-B2B-001, SPO-MALWARE-002, SPO-SHARING-008, and the SPO-SESSION-001 catch
    path (the activity-based timeout read now uses `-ErrorAction Stop` so a failed
    read is distinguishable from "not configured").
  - Missing properties cannot produce a false pass/fail for SPO-SHARING-002,
    SPO-SYNC-001, SPO-SYNC-002, SPO-LOOP-001 or SPO-ACCESS-002; each now reports
    `Review`.
  - Site prefetch no longer requests `sharingCapability` in `$select` on
    `/v1.0/sites`. The Graph site resource does not carry it; requesting it makes
    Graph reject the request, which is the likely cause of the empty site list in
    the walk. The read result is tracked explicitly.
  - SPO-SITE-001 only evaluates sites whose response actually contains
    `sharingCapability`. With no such property it reports `Review` with the reason;
    partial responses report `Review` unless a real violation is found, and only a
    fully readable site list can `Pass`. An empty/failed site list is `Review`.
  - SPO-SITE-002 applies the same missing-property guard and reports `Review`
    when sensitive sites exist but their sharing capability is not returned.
- `Get-SharePointOneDriveReport.ps1`
  - `IsUnmanagedSyncClientRestricted` is now populated from
    `isUnmanagedSyncAppForTenantRestricted` with the legacy name as fallback, and
    stays `$null` when neither is returned.
- `tests/Collaboration/Get-SharePointSecurityConfig.Tests.ps1`
  - Replaced the old inline "Warning" simulation with real collector runs:
    beta unavailable -> Review for SPO-B2B-001/SPO-MALWARE-002 and Review for
    SPO-SHARING-008.
  - Added documented-property-name pass tests, missing-property Review tests,
    sites-without-sharingCapability Review tests, empty-site-list Review tests,
    zero-CA-policy Fail / failed-CA-read Info tests, and missing
    guest-expiration/reauth Review tests.
- `tests/Collaboration/Get-SharePointOneDriveReport.Tests.ps1`
  - Added documented-property-name and missing-property fixtures.
- Tests run:
  - `Invoke-Pester -Path './tests/Collaboration/Get-SharePointSecurityConfig.Tests.ps1'`
    -> 48 passed, 0 failed.
  - `Invoke-Pester -Path './tests/Collaboration/Get-SharePointOneDriveReport.Tests.ps1'`
    -> 11 passed, 0 failed.
  - PSScriptAnalyzer (project settings, Severity Warning) clean on all changed files.

Not verified: no live tenant, so the sync property names were not confirmed against a
raw response; both documented and legacy names are supported. The empty site list was
not reproduced live; removing the invalid `$select` property is the supported code fix
and the check now degrades to Review rather than Warning/Pass.
