# T-0663 — Domain add, verify, remove, and set-default through the remediation engine

## Report

EPIC-034 SPEC.md §3.1 lists the row actions `Verify`, `Set as default`, `Remove` and the primary
button `Add domain`; §4.1 describes add as "add → get verification records → verify", and says
domain removal is a write routed through EPIC-006. §6 exposes `POST /v1/tenants/{id}/domains`,
`POST /v1/tenants/{id}/domains/{domain}/verify`, and
`DELETE /v1/tenants/{id}/domains/{domain}`. SPEC §7 requires `domains.write` with
`Remediation.Apply` semantics; tenant auth is Graph `Domain.ReadWrite.All`.

Build the `Invoke-DomainAction.ps1` worker job + `domain-action.ps1` entrypoint for add, verify,
remove, and set-default, and the BFF routes that execute the writes through the EPIC-006 apply
contract (T-0108: confirmation, gates, audit, `Idempotency-Key`). `add` returns the required
verification records so the UI can present the DNS TXT/MX steps. Every add/remove/set-default
writes an `AuditEvent`. No public DNS record is written here (SPEC §8). Extend `portal.v1.yaml`.

## Acceptance

- [ ] Add returns the verification records and leaves the domain in an unverified state until
      `verify` succeeds.
- [ ] Verify, remove, and set-default execute through the EPIC-006 contract and write an
      `AuditEvent`.
- [ ] A write for a tenant outside the caller's scope or without `domains.write` is refused.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
