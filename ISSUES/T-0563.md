# T-0563 — Custom alert criteria model, operators, and script-mode gating contract

## Report

EPIC-029 SPEC.md §3.2 defines the custom alert builder's **dynamic condition rows**
(Property / Operator / Input) with operators `eq/ne/like/match/gt/in/contains`, plus preset
autocomplete and a **script mode** (alerting script, recurrence, dynamic inputs, post-execution
actions). §7 and §8 state that script-mode alerts are high privilege, gated like EPIC-007 custom
scripts (T-0126 sandbox, admin gate, audit), and that post-execution actions route through EPIC-006.

Deliver `portal/contracts/src/alert-conditions.ts` (condition row and action shapes) and
`conditions.ts`, which validates a criteria document, rejects unknown operators, encodes script-mode
as a gated action type that only an authorized caller may persist, and evaluates a condition set
against a provided property bag (used by the T-0564 evaluator and the builder preview). The
evaluator is pure and side-effect-free; this ticket does not execute scripts.

## Acceptance

- [ ] A condition document with the §3.2 operators validates; an unknown operator is rejected.
- [ ] Script mode is representable but flagged as high-privilege and refused for callers without the admin gate.
- [ ] `evaluate(conditions, propertyBag)` returns a deterministic match result covered by tests.
- [ ] Tests cover validation, operator semantics, and script-mode gating and fail without the code.
- [ ] No file outside `scope` is modified.
