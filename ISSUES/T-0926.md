# T-0926 — Exchange Online and Purview connections pass the tenant GUID as `-Organization`, so 10 collectors never run

## Report

In the walk's portal-started run, every Exchange Online and Purview collector was skipped. The
assessment log has two ERROR lines:

```
Failed to connect to ExchangeOnline: Organization cannot be a Guid, please enter the name of the tenant instead.
Failed to connect to Purview: Organization cannot be a Guid, please enter the name of the tenant instead.
```

What was skipped: 5 Email collectors, Defender Policies, Defender Security Config, DLP,
Compliance Security Config and Purview Retention. The run has no CSV for any of them, and it
still finished `succeeded` (see T-0929).

## Cause

- `Common/Connect-Service.ps1:313` (EXO) and `:351` (IPPS) set `Organization = $TenantId`.
- On the Windows certificate-**thumbprint** path, `Set-ExchangeAppOnlyAuth` (around line 194)
  never replaces it with the tenant's initial domain. `Resolve-InitialDomain` runs only on the
  certificate-object path.
- `Orchestrator/Connect-RequiredService.ps1:195` overwrites `$ctx.Tenant.TenantId` with the
  GUID, although `InitialDomain` is available.
- The portal worker passes `Context.Tenant.TenantId` (the GUID) as `-TenantId`
  (`M365Portal.Workers.psm1:270`), although the context already carries `DefaultDomain` (the
  `.onmicrosoft.com` domain).

## Fix direction

- Always resolve `-Organization` to the initial `.onmicrosoft.com` domain for EXO and IPPS app-only
  connections, on every certificate path. Use `InitialDomain` or `DefaultDomain` when known, and
  otherwise look it up from Graph `/organization` after the Graph connection.
- Never use a GUID for `-Organization`. Check for one and fail early with a clear message.

## Acceptance

- [ ] A portal run with certificate-thumbprint auth connects to EXO and IPPS, and every Email,
      Defender and Purview collector produces output.
- [x] Tests cover the thumbprint, certificate-object and CLI paths: `-Organization` is a domain,
      never a GUID.
- [x] No file outside `scope` is modified.

## Fix

**`Common/Connect-Service.ps1`**
- Added `Resolve-OrganizationDomain`, which resolves `-Organization` to the tenant's initial
  (`*.onmicrosoft.*`) domain, preferring `-TenantId` when it already is a domain and otherwise
  querying Graph `/organization` (relative URI, so sovereign clouds are honoured).
- Added `Test-DomainValue`; a GUID or other non-domain value now fails early with an actionable
  message instead of reaching `Connect-ExchangeOnline` / `Connect-IPPSSession`.
- `Set-ExchangeAppOnlyAuth` now resolves and sets `Organization` on **every** certificate path
  (thumbprint, certificate object, certificate file), not just the certificate-object path.
- Interactive / managed-identity EXO and Purview paths no longer pass a raw `-TenantId` GUID as
  `Organization`; they use the same resolver and fall back to a supplied domain unchanged.

**`Orchestrator/Connect-RequiredService.ps1`**
- For `ExchangeOnline` and `Purview`, threads `Tenant.InitialDomain` (then `DefaultDomain`, then
  the caller's tenant id) as the connect script's `TenantId`, so a resolved domain is used when
  the context has one.
- No longer overwrites `Tenant.TenantId` with the Graph organization GUID; it also fills
  `Tenant.DefaultDomain` from `Get-MgOrganization` when a default verified domain is reported.

**`portal/workers/M365Portal.Workers/M365Portal.Workers.psm1`**
- `Invoke-WorkerAssessment` passes `Tenant.DefaultDomain` (then `InitialDomain`) as `-TenantId`
  when present, and keeps the previous `TenantId` behaviour when no domain is known.

**Tests**
- `tests/Common/Connect-Service.Tests.ps1`: thumbprint (EXO + Purview) and certificate-object
  paths assert `-Organization` is the resolved domain and never a GUID; a separate describe
  asserts the early-failure messages when Graph cannot resolve a domain or the value is not a
  domain.
- `tests/Orchestrator/Connect-RequiredService.Tests.ps1`: EXO and Purview receive the context
  initial domain (never the GUID), DefaultDomain fallback works, and the Graph connection no
  longer replaces the caller tenant id with the GUID.
- `tests/Portal/Workers/Connect-WorkerTenant.Tests.ps1`: `Invoke-WorkerAssessment` passes
  DefaultDomain / InitialDomain and preserves the tenant id when no domain is known.
