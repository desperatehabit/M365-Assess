# T-0185 — Baseline rollout evaluation and BaselineRollout state

## Report

EPIC-010 SPEC.md §4.2 (US-3): a **Baseline system timer** (EPIC-007) evaluates each assigned
tenant against its current stage; when the tenant satisfies the stage conditions it becomes
eligible to advance, and the operator (or a later auto-advance policy) moves it. Each evaluation
records a `BaselineRollout` update plus a history event, and trend points accumulate. §5 defines
`BaselineRollout` (`baselineId`, `tenantId`, `stage`, `state`, `lastRunAt`). §9 mitigates "long
fleet runs" with per-tenant jobs and single-flight.

Deliver `baseline-rollout.ts` and extend the repository to upsert `BaselineRollout` and mark stage
eligibility. History and trend writes are appended by T-0188 (prose cross-ref).

## Acceptance

- [ ] The evaluator computes per-tenant stage satisfaction from the stage conditions.
- [ ] A satisfied tenant is marked eligible to advance; an unsatisfied one is not.
- [ ] Each evaluation upserts `BaselineRollout` and is single-flight per baseline.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
