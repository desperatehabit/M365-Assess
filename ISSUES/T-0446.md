# T-0446 — Contact template CRUD worker, API, and editor

## Report

EPIC-023 SPEC.md §2 US-2, §3.2, and §5 define **Contact Templates**: define contact properties
and deploy variables (name, address) per target, persisted as `ContactTemplate`. §6 exposes
`GET`/`POST`/`PATCH`/`DELETE` on `/v1/contact-templates`.

Deliver an `Invoke-ContactTemplate.ps1` handler (entrypoint `invoke-contact-template.ps1`) that
validates template shape and persists through the repository (T-0441), plus the CRUD route and
the editor page rendering the properties/variables form. Templates carry no tenant writes;
deployment is T-0447. Extend `portal.v1.yaml` with the operations.

## Acceptance

- [ ] Templates create, read, update, and soft-delete through the API.
- [ ] The editor renders `properties` and `variables` and round-trips them unchanged.
- [ ] Invalid template shapes are rejected with a structured error and never persisted.
- [ ] A test covers CRUD and fails without it.
- [ ] No file outside `scope` is modified.
