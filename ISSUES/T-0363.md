# T-0363 — DefenderDeploymentTemplate persistence and CRUD API

## Report

EPIC-019 SPEC.md §5 defines `DefenderDeploymentTemplate` (`id`, `name`, `policyAreas[]`,
`policyJson`) as the setup-wizard output, and §11.4 is resolved so that output is **optionally**
saved as Intune templates. This ticket persists the Defender-side template; the wizard toggle and
the Intune cross-write live in T-0364/T-0365.

Deliver migration `0048_defender_deployment_templates.sql`, a
`defender-deployment-templates.ts` repository behind the ADR-0015 interface (tenant-scoped), and
CRUD routes behind RBAC `defender.write`. Each `policyArea` is validated against the T-0361
registry and `policyJson` as well-formed. No tenant writes.

## Acceptance

- [ ] A migration creates `DefenderDeploymentTemplate`; the repository round-trips the §5 fields.
- [ ] CRUD validates `policyAreas` against the T-0361 registry and validates `policyJson`.
- [ ] Templates are tenant-scoped and soft-deletable through the repository.
- [ ] Tests cover repository and routes and fail without them.
- [ ] No file outside `scope` is modified.
