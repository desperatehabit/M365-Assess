# T-0567 — Alert queue/history API with snooze and auto-return

## Report

EPIC-029 SPEC.md §2 US-3 and US-6, §3.3, and §3.5 define the alert queue: fired events with state
(open/snoozed/resolved), source, tenant, and time; snoozing an alert/rule for a duration moves it to
the Snoozed tab and auto-returns it. §4.4 requires snooze/disable to be audited. §6 fixes
`GET /v1/alert-events`, `POST /v1/alert-rules/{id}/snooze`, and `POST /v1/alert-rules/{id}/toggle`.
§3.5 notes the queue integrates with EPIC-028's Check Alerts (data integration, not a code path).

Deliver the events queue (cursor-paginated, tenant-scoped, filterable by state/source/severity) and
the snooze/toggle operations. Snooze sets `snoozeUntil` and a scheduler-aware resolution flips
snoozed events back to open once elapsed; every change writes an audit event.

## Acceptance

- [ ] `GET /v1/alert-events` lists events with state/source/tenant/time, paginated and tenant-scoped.
- [ ] `POST .../snooze` sets `snoozeUntil`; the event auto-returns to open after the duration.
- [ ] `POST .../toggle` enables/disables the rule and is audited.
- [ ] Snoozed events are excluded from the open queue and surfaced in the snoozed view.
- [ ] A test covers queue, snooze, and auto-return and fails without the code.
- [ ] No file outside `scope` is modified.
