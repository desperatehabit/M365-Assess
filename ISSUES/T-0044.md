# T-0044 — Progress SSE stream and event fan-out

## Report

EPIC-003 SPEC.md §4.2 requires the API to fan structured progress events to subscribers and to
update `Run`/`RunSection`; §6 defines `GET /v1/runs/{runId}/events`. Resolved §11.2 adopts
**SSE** as the transport (simpler, one-way). The versioned progress-event contract was defined
by EPIC-001 T-0014 (`portal/contracts/src/events.ts`); this ticket builds the server side that
carries it.

Deliver an SSE route and a hub that subscribes to queue/worker progress (T-0010), emits the
T-0014 event shape with a monotonic sequence, updates `Run`/`RunSection` through the T-0041
repository, and closes the stream on terminal state. Streams are tenant-scoped and audited; no
secret or tenant PII appears in an event.

## Acceptance

- [ ] `GET /v1/runs/{runId}/events` streams ordered, versioned events until the run is terminal.
- [ ] Subscribing to a run outside the caller's scope is refused.
- [ ] A test drives a stubbed job and asserts event ordering and terminal close.
- [ ] No file outside `scope` is modified.
