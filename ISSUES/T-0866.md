# T-0866 — Mount EPIC-036 Compliance Test Packs and Custom Tests routes

## Report

The EPIC-036 factories (`createTestPacksRoutes` at `portal/bff/src/routes/test-packs.ts:110`,
`createCustomTestsRoutes` at `portal/bff/src/routes/custom-tests.ts:202`) exist and are tested, but
`portal/bff/src/app.ts` imports neither and `portal/bff/src/adapters/` has no adapter for the
TestPack/TestRun/CustomTest repositories, so the endpoints 404. Migrations `0044`/`0045`, the pages
(`app/test-packs`, `app/test-packs/[id]`, `app/custom-tests`), and the sandbox worker
`run-custom-script.ps1` exist.

This ticket mounts the routes with real storage and removes the fabricated fallbacks (tracked here
because they live in the same pages):

- `portal/web/src/app/test-packs/page.tsx:51` seeds `DEFAULT_PACKS` (a fabricated CIS/E8 catalogue)
  and keeps it whenever the API fails.
- `portal/web/src/app/test-packs/[id]/page.tsx:55-67` ships a hardcoded sample `PackReport` with fake
  Fail findings and keeps it whenever the API returns no `results`.
- `portal/web/src/app/custom-tests/page.tsx:139` seeds `DEFAULT_CUSTOM_TESTS` with fabricated records
  and fixed dates.

The fabricated backend dispatcher is handled by T-0889.

## Acceptance

- [x] Every EPIC-036 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Test packs, test runs, and custom tests persist through SQLite.
- [x] The three pages render only live API data; no fabricated catalogue/report/records remain.
- [x] No file outside `scope` is modified.

## Fix

`createApp` mounts `createTestPacksRoutes` and `createCustomTestsRoutes` over the
shared `SqliteRepository` (migrations 0044/0045). Pack runs reuse the
already-wired create-run route (`runsCreateRoute`, extracted so the same instance
is mounted and handed to the pack service), and the pack report reads the run
store. Test-pack listing serves the shipped catalogue (`cis`, `e8`) with its
check counts. Custom tests create, edit, version, list, and soft-delete through
the repository, which already emits the audit event at the persistence boundary.

The pages were already free of the fabricated records described in the report
(T-0888 landed those removals), but they read the raw response as arrays while
the mounted routes wrap them as `{ packs }` / `{ items }`, and the pack list
expected `checks` where the API sends `checkCount`. Those three mismatches are
fixed, and the pack report now passes the tenant id the detail endpoint requires.
All endpoints are registered, published through their OpenAPI fragments (the
test-pack fragment was moved to the standard `paths` shape), and the checked-in
contract is regenerated.
