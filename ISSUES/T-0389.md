# T-0389 — Mailbox administration UI

## Report

EPIC-020 SPEC.md §3 fixes the UI surfaces under *Email & Exchange → Administration*: the
**Mailboxes** list with its filters and row actions (§3.1), the off-canvas detail (§3.1), the
settings/convert dialogs (§3.2), **Mailbox Permissions** (§3.3), rules & forwarding (§3.4),
**Vacation Mode** (§3.5), and **Retention Policy/Tag Management** (§3.6). Theme and components
follow `02-ui-design.md` and the `DataTable`/`ActionDialog` patterns.

Deliver the Next.js pages above using the read APIs (T-0381) and write routes (T-0382–T-0388):
the list/search/filter table, the detail drawer, the `ActionDialog` forms with plan preview and
confirmation for each write, the forwarding security flag (T-0385), the vacation schedule list
with **End now**, and retention assignment. No browser call reaches a tenant directly; every page
reads the BFF. RBAC-gated actions hide or disable controls the caller cannot use.

## Acceptance

- [ ] The Mailboxes table renders the §3.1 columns, filters, and row actions from the BFF read API.
- [ ] Each write action opens a plan-preview/confirmation dialog before apply.
- [ ] Permissions, rules/forwarding, vacation, and retention pages render and act through the BFF.
- [ ] Forwarding changes and other security-sensitive actions are visibly flagged.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
