# T-0323 — App upload queue worker and queue status API

## Report

EPIC-017 SPEC.md §3.2 and §4.1 describe the upload path: the wizard stores the package and
queues a job; the queue performs the Graph content upload and commit in the tenant's process;
progress is visible on the Queued Applications page; failures are re-runnable. §6 fixes
`POST /v1/tenants/{id}/apps/upload` and `GET /v1/tenants/{id}/apps/queue`, and §3.2 says queue
tracking reuses EPIC-003/EPIC-007's job progress.

Deliver `Queue-IntuneAppUpload.ps1` + `queue-intune-app-upload.ps1`, a job handler that resolves
the T-0032 signed package source, uploads and commits the app to Graph, and records state on the
`AppDeployment` row (T-0322). The BFF route enqueues through the EPIC-001 queue (T-0010) and
serves queue status from persisted deployment records, so a failed item can be re-run. Graph
writes route through EPIC-006's gated executor semantics; each transition is audited.

## Acceptance

- [ ] `POST /v1/tenants/{id}/apps/upload` enqueues a job and returns a deployment id; `GET .../apps/queue` reports per-item state.
- [ ] The worker uploads and commits the package and records `state`/`results`; a failed item is re-runnable.
- [ ] Progress is observable through the existing queue/progress contract; no secret or package bytes appear in events.
- [ ] Tests cover the route and worker and fail without them.
- [ ] No file outside `scope` is modified.
