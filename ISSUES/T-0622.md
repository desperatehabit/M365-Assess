# T-0622 — Audit search worker with per-workload routing, manual search and directory audits API

## Report

EPIC-032 SPEC.md §6 defines `POST /v1/tenants/{id}/audit/search` (manual search) and
`GET /v1/tenants/{id}/audit/directory` (directory audits); §3.1 and §3.4 fix their result
columns and filters. §4.1 says a manual search "runs against Graph audit logs (EXO/Purview for
some workloads)". Resolved §11.1 adopts **per-workload routing**: Graph `directoryAudits` and
`signIns` where those endpoints cover the workload, and Purview audit search for content
workloads (Exchange/SharePoint/OneDrive). §4.1 also says results are ephemeral by default and
exports are audited.

Build the worker job handlers `Search-AuditLog.ps1` (filters: date range, user, activity,
workload, IP) and `Get-AuditDirectory.ps1` (filters: category, date) plus a thin
`search-audit.ps1` entrypoint, and the BFF routes over the T-0621 repository. The worker selects
the backend per workload and returns a normalised result shape; the directory route exposes
Graph `directoryAudits`. Every search and export writes an `AuditEvent` (SPEC §8). Extend
`portal.v1.yaml`.

## Acceptance

- [ ] A manual search routes each requested workload to the correct backend and returns the §3.1
      columns; results are not persisted except as an audit event.
- [ ] Directory audits render the §3.4 columns and support category/date filters.
- [ ] Search and export both write an `AuditEvent`; a test asserts the search path fails without it.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
