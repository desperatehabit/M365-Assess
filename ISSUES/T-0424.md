# T-0424 — Quarantine list, preview, release, and delete

## Report

EPIC-022 SPEC.md §2 (US-3), §3.3, §4.2, §5, and §8 require quarantine to be listed (Email, Files,
Teams Messages tabs) with reason/direction/date/recipient/state filters and `Preview`, `Release`,
`Release to all`, `Download`, `Block sender`, and `Delete` actions. §4.2 and §8 make quarantine
release a security action audited with actor, message, and recipient; §9 risk "releasing malicious
mail" is mitigated by preview plus explicit confirmation.

Resolved §11.1 resolves the data source: **use EXO quarantine cmdlets where they support
release/submit, else fall back to Graph for metadata only**. Deliver migration
`0037_quarantine_actions.sql` for the §5 `QuarantineAction` audit record and
`quarantine-repository.ts`, plus `quarantine.ts` for the §6 `GET /quarantine` list and
`POST /quarantine/{messageId}/{action}` release/delete/block routes. The
`Invoke-QuarantineAction.ps1` worker job plus `invoke-quarantine-action.ps1` entrypoint performs
release/delete through the EPIC-006 gate (T-0107), requiring confirmation and writing a
`QuarantineAction` plus an `AuditEvent`. Extend `portal.v1.yaml`. Tenant and credential records are
EPIC-002 (prose dependency).

## Acceptance

- [ ] Quarantine lists with the §3.3 columns, filters, and Email/Files/Teams tabs.
- [ ] Preview and release (to recipient or all) work via EXO where supported, else Graph metadata.
- [ ] Release and delete require confirmation and write a `QuarantineAction` plus an `AuditEvent`.
- [ ] The worker chooses EXO vs Graph per the resolved §11.1 rule and documents the choice.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
