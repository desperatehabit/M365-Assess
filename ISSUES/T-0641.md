# T-0641 — Licence pricing and change entities, migration, and repository

## Report

EPIC-033 SPEC.md §5 fixes two persisted entities: `LicensePricing` (`skuId`, `skuPartNumber`,
`unitPrice`, `currency`, `updatedAt`, editable) and `LicenseChange` (`id`, `tenantId`, `userId`,
`skuId`, `action`, `state`, `by`, `at`, audit), plus `AuditEvent` for pricing and assignment
changes. Pricing is global with a per-tenant override (resolved §11.2), so the pricing row needs
a nullable `tenantId` (null = global seed) with a unique key on `(tenantId, skuId)`.

Add a numbered, forward-only migration under `portal/db/migrations/` and a
`licensing-repository.ts` implementing the SPEC §5 shapes behind the ADR-0015 repository
interface; extend the EPIC-001 repository index. Expose pricing read/upsert (global and
per-tenant, per-tenant winning), and `LicenseChange` append + list by tenant/user. Enforce tenant
scoping and append-only audit in the repository layer. No Graph calls belong here.

## Acceptance

- [ ] The migration is forward-only, re-runnable, and creates both entities with the SPEC §5
      columns.
- [ ] Upserting a per-tenant price overrides the global seed for that tenant; an absent override
      falls back to the global row.
- [ ] A `LicenseChange` is append-only and writes an `AuditEvent`; no update/delete mutator is exposed.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
