# T-0021 — Tenant, credential, group, variable, and GDAP schema and repository

## Report

EPIC-002 SPEC.md §5 extends EPIC-001's minimal `Tenant` stub into the full entity set:
`Tenant` (dual-shape identity per module ADR-0012), `TenantCredential` (secret by reference
only), `TenantGroup`, `TenantGroupMember`, `TenantVariable`, and the optional
`GdapRelationship` satellite. ADR-0015 and `03-database.md` §5 require numbered, forward-only
migrations behind the repository interface; every tenant-scoped row carries `tenantId`, soft
delete applies to tenant/group, and secrets never live with data (`03-database.md` §4).

Deliver migration `0002_tenants.sql` extending the `0001_init` schema, plus repository
methods on `portal/db/src/repository.ts` / `sqlite-repository.ts` to list/filter, get, upsert,
and soft-delete these entities. No route or UI code belongs in this ticket.

## Acceptance

- [ ] Migration 0002 applies after 0001, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes tenant/credential/group/variable/GDAP methods; no raw SQL appears
      outside `portal/db/`.
- [ ] A test proves tenant scoping and soft delete for tenants/groups and asserts no column
      stores a secret value.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
