# T-0523 — Permissions report worker and API

## Report

EPIC-027 SPEC.md §2 US-2, §3.2, §4.1, and §6 define the permissions report: Site · Principal ·
Role · Inherited · Scope, filtered by role and principal type, and explicitly read-only. §6
exposes `GET /v1/tenants/{id}/sharing/permissions`; data is read live from Graph/SPO per §7.

Deliver a `Get-PermissionsReport.ps1` handler (entrypoint `get-permissions-report.ps1`) that
reads site/OneDrive permissions (using the site list from T-0482) and returns a
`ResultEnvelope`, plus the read route validating `sharing.read` and tenant scope with cursor
pagination and role/principal-type filters. This ticket performs no writes. Extend
`portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/sharing/permissions` returns the §3.2 columns, filtered and paginated.
- [ ] Role and principal-type filters are honored; results are tenant-scoped.
- [ ] The surface is read-only; a caller without `sharing.read` is refused.
- [ ] A test covers listing and filtering and fails without it.
- [ ] No file outside `scope` is modified.
