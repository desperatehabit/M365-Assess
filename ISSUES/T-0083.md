# T-0083 — Generated report metadata and artifact-tier storage

## Report

EPIC-005 SPEC.md §5 defines `GeneratedReport` (`id`, `templateId`, `tenantId`, `status`,
`artifactRef`, `createdAt`, `createdBy`, `scheduleId?`). §11.5 resolves storage to the artifact
tier: the rendered bytes live on the artifact path, the DB holds only metadata
(`03-database.md` §2). EPIC-005 SPEC.md §10 requires generation to be audited.

Deliver:

- A numbered, forward-only migration (`0003_generated_reports.sql`) with `createdAt`/`updatedAt`
  and soft delete (`03-database.md` §5).
- `portal/db/src/report-repository.ts`: CRUD for `GeneratedReport`, tenant-scoped, recording an
  `AuditEvent` on create/status change, and storing only `artifactRef` (never file bytes).
- Tests for tenant scoping, status transition, and audit emission.

## Acceptance

- [ ] A generated report round-trips metadata with an `artifactRef`, never inline bytes.
- [ ] All queries are tenant-scoped and soft delete is enforced by the repository.
- [ ] Generation writes an audit event.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
