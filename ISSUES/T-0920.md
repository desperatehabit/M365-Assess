# T-0920 — The sidebar lists about 120 pages with no collapsing, so it takes four screens to scroll

## Report

The sidebar is too long to use. Reaching the bottom takes about four screens of scrolling. Many
of the items either should not be in the nav or belong in collapsible groups.

## Cause

`NAV_GROUPS` in `AppNav.tsx` holds **119 links in 14 groups**. By design it lists every top-level
page ("Lists every top-level page", line 4). Every group is always expanded, there is no search,
and nothing is filtered by RBAC or feature flags (EPIC-038 is noted as not done).

## Fix direction

**Collapse, don't remove** (operator decision, 2026-11-19). Every page stays in the nav. The
nav shows only the group headings until one is opened.

- Make each group heading a toggle that collapses to the heading alone. By default, open only
  the group that holds the active page. Remember each viewer's open and closed groups.
- Review the grouping so collapsing works: each item sits under the heading an operator would
  look for it under. Split oversized groups (Email, Security & compliance and Intune each hold
  roughly 15 to 20 items) into sub-headings, and move items that sit under the wrong heading.
- Optional: a nav search box or command palette (Ctrl+K) for jumping to a page directly.

## Acceptance

- [x] With default state (one group open), the whole nav fits on one screen at 1080p.
- [x] Every page in today's `NAV_GROUPS` is still reachable from the nav.
- [x] The group that holds the active page opens automatically, including on a deep link.
- [x] Groups can be opened and closed from the keyboard, and expose `aria-expanded`.
- [x] No file outside `scope` is modified.

## Fix

**Status: fixed-unverified** (2026-11-20)

### Changes

- `portal/web/src/components/shell/AppNav.tsx`
  - Kept all 116 existing links (the report said ~119; the source had 116). Added a regression
    test that matches the old href list exactly.
  - `NAV_GROUPS` now carries optional `sections` (sub-headings) while `items` stays flat, so
    `gateNavGroups` and the feature-flags preview keep working unchanged.
  - Regrouped: split `Email` into Mailboxes / Transport & protection / Directory / Mail tools,
    `Security & compliance` into Compliance / Posture / Audit / Monitoring, and `Intune` into
    Policies / Templates & settings / Devices & enrollment / Applications. Added sections to
    Identity, Collaboration and Platform admin. Moved the three test-authoring pages
    (`/test-packs`, `/custom-tests`, `/catalog`) from Security & compliance to Assessments and
    renamed the `Devices` group to `Defender` (it only held Defender pages).
  - Every group heading is now a `<button>` with `aria-expanded` and `aria-controls`; the panel
    is hidden when closed. Native button semantics cover Enter and Space.
  - Initial state opens only the group holding the active page. Open groups are remembered in
    `localStorage` (`m365_assess_nav_open_groups`); a navigation to a page always reopens its
    group, so deep links and freshly opened tabs land with the right group visible.
  - Optional jump: a nav filter (`Ctrl+K` / `Cmd+K` to focus, `Escape` to clear) searches labels,
    descriptions and routes across every group and announces the match count.
- `portal/web/src/app/portal.css`
  - Styles for the group toggles/panels, sub-headings, the filter, focus-visible rings and the
    hover/focus tooltip. Compacted section and item spacing so the default view (one group open,
    including the 16-item Email group) fits a 1080p viewport with the sidebar's own scroll as a
    fallback.
