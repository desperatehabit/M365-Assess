# T-0581 — Compliance template and policy-change storage

## Report

EPIC-030 SPEC.md §5 defines two persistent entities: `ComplianceTemplate` (`id`, `name`,
`area(dlp|retention|label|sit|safelinks)`, `payload`, `variables`, `source`) — one table, area-typed —
and `CompliancePolicyChange` (`id`, `tenantId`, `area`, `policyId`, `at`, `by`, `before`, `after`)
as change history. §5 states policies are read live from Purview/Graph/EXO while templates and
change records persist. §8 requires every write to be audited, and
[`03-database.md`](../../docs/portal-specs/00-guides/03-database.md) §5/§6 require soft delete and
an audit event per mutation.

Deliver migration `0051_purview_compliance.sql` (numbered, forward-only, advancing `SchemaVersion`)
plus a repository for both entities and the shared contract types in `portal/contracts/src/purview.ts`.
`tenantId` references the EPIC-002 tenant table (data dependency, prose only). `source` is constrained
to `local` for v1 per resolved §11.3.

## Acceptance

- [ ] Migration 0051 applies after prior migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository round-trips the §5 `ComplianceTemplate` and `CompliancePolicyChange` fields.
- [ ] `area` is constrained to the five allowed values; `source` allows `local` only in v1.
- [ ] Change records capture before/after and are append-only; templates soft-delete.
- [ ] A test covers the repository and fails without it.
- [ ] No file outside `scope` is modified.
