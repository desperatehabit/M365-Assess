# T-0384 — Mailbox and calendar permissions

## Report

EPIC-020 SPEC.md §2 (US-4), §3.3, §4.2, and §6 require mailbox and calendar permission tables
(principal, access rights, automap, inherited) with add/edit/remove, grounded in the module's
`Get-MailboxPermissionReport`. Resolved §11.1 pairs the first-cut shared-mailbox conversion with
**permissions**, so this ticket completes that cut.

Deliver `mailbox-permissions.ts` exposing the §6 `GET`/`POST`/`DELETE` permission routes and the
`Set-MailboxPermission.ps1` worker job plus `set-mailbox-permission.ps1` entrypoint. Each add/edit/
remove is a gated write (T-0107); the plan preview shows the effective permission change; grants
are security-sensitive and audited with before/after plus a `MailboxOperation` (T-0382). Extend
`portal.v1.yaml`. Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Mailbox and calendar permissions list with principal, access rights, automap, and inherited.
- [ ] Add/edit/remove each produce a plan preview showing the effective change and apply through the EPIC-006 gate.
- [ ] Every grant or removal captures before/after and writes an `AuditEvent`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
