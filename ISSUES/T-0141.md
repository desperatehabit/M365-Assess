# T-0141 — StandardDefinition model derived from the control registry

## Report

EPIC-008 SPEC.md §5 defines `StandardDefinition` with `id`, `checkId`, `name`, `category`, and
`licensePreset` mapping each standard to registry checks. Resolved §11.1 adopts **1:1 with
registry checks** for v1 (grouping later), and resolved §11.4 puts the definition **derived from
the registry at load, with an optional curated override**. §9 risk "registry/standard drift"
requires standards keyed by checkId so a registry sync can be re-validated.

Deliver a `StandardDefinition` contract type, a forward-only migration (`0006`), and a repository
that loads definitions from `src/M365-Assess/controls/registry.json` (read-only) keyed 1:1 by
`checkId`, with an optional curated `StandardDefinitionOverride` row winning when present. No HTTP
or UI code belongs in this ticket.

## Acceptance

- [ ] `StandardDefinition` definitions are derived from the control registry 1:1 by `checkId` at load; a curated override row wins when present.
- [ ] Migration `0006` applies after the current head, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository resolves a standard by `checkId` and lists standards by category.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
