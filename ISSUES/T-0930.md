# T-0930 — Sentinel rows with no CheckId are dropped from the HTML, JSON, XLSX and portal

## Report

The Power BI CSV for the walk's run has 12 rows. The JSON, the DB and the XLSX have 11. The
missing row is the collector's failure sentinel:

```
| Warning | Power BI Tenant Settings | Could not verify -- API unavailable: … 404 (Not Found)
```

Warnings are undercounted by one everywhere downstream, and the failure the sentinel was
meant to show is invisible.

## Cause

- `PowerBI/Get-PowerBISecurityConfig.ps1:76-85` adds the sentinel with an empty CheckId.
- `Common/Build-SectionHtml.ps1:95` and `Common/Export-ComplianceMatrix.ps1:132` skip rows that
  have an empty CheckId. The JSON bridge (and so the portal) ends up with the same filtered set.

## Fix direction

Do one of the following:
- Give sentinels a real CheckId, for example a per-collector `<PREFIX>-COLLECTOR-000`
  "Collector health" entry in `local-extensions.json`.
- Or route empty-CheckId rows into the issues log (T-0929) instead of dropping them.

Either way, the CSV, the HTML, the JSON, the XLSX and the portal should agree on the row count.

## Acceptance

- [x] Collector failure sentinels appear in the HTML, the JSON and the portal, either as a
      finding or as a run issue.
- [x] The CSV and JSON row counts match for every section.
- [x] No file outside `scope` is modified.

## Fix

The Power BI collector's failure sentinel now carries a stable check id,
`POWERBI-COLLECTOR-000`, instead of an empty CheckId, so the existing
empty-CheckId guard in `Build-SectionHtml.ps1` and `Export-ComplianceMatrix.ps1`
no longer drops it. The CSV, HTML, JSON bridge and XLSX all receive the same row.

- `src/M365-Assess/PowerBI/Get-PowerBISecurityConfig.ps1` — sentinel uses
  `CheckId = 'POWERBI-COLLECTOR-000'`; message and remediation updated for the
  Fabric admin API.
- `src/M365-Assess/controls/local-extensions.json` — registered
  `POWERBI-COLLECTOR-000` ("Power BI Collector Health", collector `PowerBI`,
  empty frameworks) so the weekly CheckID sync preserves it. `registry.json`
  will pick it up on the next sync; until then the report falls back to the
  default Medium risk severity and no framework mapping, which does not affect
  inclusion or row counts.
- `src/M365-Assess/Common/Build-SectionHtml.ps1` — comment documents that
  collectors must supply a real check id for sentinels. The filter itself is
  unchanged.

Tests run:

  `POWERBI-COLLECTOR-000.1` (Status Warning, Section Power BI) and assert the

- `tests/PowerBI/Get-PowerBISecurityConfig.Tests.ps1` — 26 passed. Sentinels are

Verified the sentinel reaches `$allCisFindings`, the input to

Swept the other collectors for sentinel rows: the only empty-CheckId `Add-Setting`
call was the Power BI one. The Intune mobile-encryption sentinels and the other
