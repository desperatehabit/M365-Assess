# T-0930 — Sentinel rows with no CheckId are dropped from the HTML, JSON, XLSX and portal

## Report

The Power BI CSV for the walk's run has 12 rows. The JSON, the DB and the XLSX have 11. The
missing row is the collector's failure sentinel:

```
| Warning | Power BI Tenant Settings | Could not verify -- API unavailable: … 404 (Not Found)
```

Warnings are undercounted by one everywhere downstream, and the failure the sentinel was
meant to show is invisible.

## Cause

- `PowerBI/Get-PowerBISecurityConfig.ps1:76-85` adds the sentinel with an empty CheckId.
- `Common/Build-SectionHtml.ps1:95` and `Common/Export-ComplianceMatrix.ps1:132` skip rows that
  have an empty CheckId. The JSON bridge (and so the portal) ends up with the same filtered set.

## Fix direction

Do one of the following:
- Give sentinels a real CheckId, for example a per-collector `<PREFIX>-COLLECTOR-000`
  "Collector health" entry in `local-extensions.json`.
- Or route empty-CheckId rows into the issues log (T-0929) instead of dropping them.

Either way, the CSV, the HTML, the JSON, the XLSX and the portal should agree on the row count.

## Acceptance

- [ ] Collector failure sentinels appear in the HTML, the JSON and the portal, either as a
      finding or as a run issue.
- [ ] The CSV and JSON row counts match for every section.
- [ ] No file outside `scope` is modified.
