# T-0629 — Webhooks and exclusion windows UI

## Report

EPIC-032 SPEC.md §3.5 defines the **Pending Webhooks** / **Subscriptions** surfaces: Resource,
Tenant, Expires, State, with row actions `Renew`, `Recreate`, `Delete`, `Test`, and an expiry
alert (EPIC-029). §3.6 defines **Exclusion Windows**: active/upcoming windows with a create
action. Both live under *Tenant Administration → Audit Logs*.

Build the two routes and the `WebhooksTable` / `ExclusionWindowsTable` components against the
T-0625 webhook and T-0626 window endpoints, extending the T-0627 `auditApi.ts` client. Expiry
within the alert threshold renders as a warning `.status-badge`; `Renew`/`Recreate`/`Delete`/
`Test` call the webhook API, and window creation validates `startsAt < endsAt`. Use report theme
tokens only.

## Acceptance

- [ ] The webhooks table renders every column and all four row actions; a near-expiry row shows
      the alert state.
- [ ] The exclusion-windows table lists active/upcoming windows and creates a new window with a
      rejected invalid range.
- [ ] A test covers the component states and fails without it; only theme tokens are used.
- [ ] No file outside `scope` is modified.
