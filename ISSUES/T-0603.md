# T-0603 — Improvement action to registry check mapping with curated overrides

## Report

EPIC-031 SPEC.md §4.1 matches improvement actions to registry checks by control/action id; §4.3
states an unmapped action is shown honestly as "no automated remediation" with a portal link; §9
warns the mapping is imperfect. §11.1 is resolved to **derive the mapping from registry control ids,
with a curated override where needed**.

Deliver `mapping.ts` that builds an action→`checkId`/`standardKey` map from the module control
registry (read-only `src/M365-Assess/controls/registry.json`; no `src/` change) plus
`mapping-overrides.json` for actions the derivation cannot resolve. Expose `resolveFixTarget(action)`
returning either the mapped checkId/standardKey, a portal standard reference, or an explicit
"unmapped" result, and persist resolved mappings via the T-0601 repository with an audit event on
change. Pure domain logic; no routes or UI here.

## Acceptance

- [ ] The derived map links improvement actions to registry checkIds where an id relationship exists.
- [ ] A curated override resolves at least one action the derivation cannot, and is data-driven.
- [ ] Unmapped actions resolve to an explicit "no automated remediation" result, not an error.
- [ ] Persisting a mapping writes an audit event.
- [ ] A test covers derivation, override, and unmapped cases and fails without the code.
- [ ] No file outside `scope` is modified.
