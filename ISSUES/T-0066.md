# T-0066 — Per-tenant dashboard and all-tenants fleet view pages

## Report

EPIC-004 SPEC.md §3.3 shows the all-tenants view "when no tenant is selected": a fleet
table/card grid with score, compliance, open alerts, and last run, sortable and filterable, with
click-through to a tenant dashboard. §4.1 says widgets read persisted rows and that missing data
renders an **empty-state card prompting a run** (hand-off to EPIC-003, not authored here).

Deliver:

- `/dashboard` (fleet view) and `/dashboard/[tenantId]` (per-tenant) routes.
- `FleetTable` over the `FleetPayload`, with `DataTable`-style sorting/filtering and row
  click-through to the tenant dashboard.
- `EmptyState` prompting a run, with a disabled/placeholder action referencing the EPIC-003 run
  entry point until that epic's new-run dialog exists.
- Route-level tests with a stubbed fetch layer.

Note: the findings table and run-creation dialog live in EPIC-003; this ticket only links to
them, it does not implement them.

## Acceptance

- [ ] The fleet view lists tenants with sortable/filterable columns and links to each dashboard.
- [ ] A tenant with no completed run shows the empty-state prompt to start a run.
- [ ] No browser-side call reaches a tenant directly; all data comes from the BFF routes.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
