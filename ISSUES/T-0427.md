# T-0427 — Tenant allow/block list read, writes, and expiry

## Report

EPIC-022 SPEC.md §2 (US-5), §3.4, §4.3, §5, and §6 require tenant allow/block entries (sender,
domain, URL, file) to be listed with type/value/action/expiry/notes and added, edited, or removed
with optional expiry and bulk import. §4.3 also surfaces entries in quarantine **Block sender**;
§9 risk "allow-list abuse" is mitigated by audit, expiry, and admin gating.

Resolved §11.3 adopts **reading allow/block entries live from EXO and storing only action
audit** — there is no local `AllowBlockEntry` mirror. Deliver `allow-block.ts` for the §6
`GET`/`POST`/`PATCH`/`DELETE` routes and the `Set-AllowBlockEntry.ps1` worker job plus
`set-allow-block-entry.ps1` entrypoint. Entries read live from EXO; each write routes through the
EPIC-006 gate (T-0107) with before/after and an `AuditEvent`; expiry is applied on the EXO entry.
Extend `portal.v1.yaml`. Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Allow/block entries list live from EXO with the §3.4 columns.
- [ ] Add/edit/remove apply through the EPIC-006 gate with before/after and an `AuditEvent`; no entry is mirrored locally.
- [ ] An entry with an expiry carries it to EXO; bulk import reports per-row results.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
