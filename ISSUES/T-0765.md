# T-0765 — Clone template into a tenant via the EPIC-006 plan path

## Report

EPIC-039 SPEC.md §3.3, §4.1, §6, §8 (US-3): `POST /v1/template-library/{id}/clone` takes a
template id plus target tenant(s) and opens the **target epic's** deploy flow with a plan
(CA deploy drawer, Intune policy deploy, standards template, etc.). Apply routes through
**EPIC-006**; library/catalog browsing stays read-only.

Build `clone-routes.ts`/`clone-service.ts` that resolve the item's type to the owning epic's
deploy-plan builder and produce a plan (targets, actions, diff) without writing. The
`CloneToTenantDrawer` shows the plan and defers confirmation to the target flow. Reuse the
EPIC-006 plan/permission boundary (T-0101) rather than issuing tenant writes directly.
Cross-epic: the CA and Intune deploy flows are EPIC-015 (T-0285) and EPIC-016 (T-0301); those
dependencies are described here in prose because their tickets are not referenced directly.

## Acceptance

- [ ] `POST /v1/template-library/{id}/clone` returns a plan naming target tenants and actions; no tenant write occurs.
- [ ] Clone requires `templates.clone` and is tenant-scoped (EPIC-038).
- [ ] The clone drawer renders the plan and routes confirmation through the owning epic's deploy flow.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
