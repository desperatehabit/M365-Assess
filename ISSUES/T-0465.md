# T-0465 — Historical search as a cancellable EXO compliance-search job

## Report

EPIC-024 SPEC.md §2 US-2, §3.2, §4.1, and §9 define historical search across mailboxes: scoped
parameters, a long-running cancellable job with progress, results with a download option for
permitted callers, tenant-scoped and audited. §6 exposes
`POST /v1/tenants/{id}/mail/historical-search`. §11 item 1 is resolved (adopted): the backend is
**EXO/Purview compliance search** (`New-ComplianceSearch`/`Start-ComplianceSearch`/
`Get-ComplianceSearch`) run inside the per-tenant EXO process, and callers need high privilege
plus the compliance/eDiscovery roles. §11 item 4 is resolved (adopted): results are
**ephemeral** — not persisted.

Deliver a `Start-HistoricalSearch.ps1` handler (entrypoint `start-historical-search.ps1`) that
runs the compliance search as an async job with progress and a cancel path, returning matches
and the download reference without persisting message data; the route validates the elevated
`mailtools.search` permission plus tenant scope and audits start/cancel/finish. Persist only job
and audit records. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Start enqueues a cancellable search job that emits progress.
- [ ] Results are returned but never persisted; only job and audit records are stored.
- [ ] A caller lacking the compliance-level permission is refused with a structured error.
- [ ] A test covers progress, cancel, and the no-persistence rule and fails without it.
- [ ] No file outside `scope` is modified.
