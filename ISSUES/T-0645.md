# T-0645 — Per-user licence assign and remove through the remediation engine

## Report

EPIC-033 SPEC.md §3.4 defines per-user licence assignment from the user detail (EPIC-011) or the
licence report, single and bulk, with confirmation, and §4.3 requires a plan preview, per-row
results for bulk, and auditing. §8 states licence assignment/removal **routes through EPIC-006**
(confirmation + audit). §6 exposes `POST /v1/tenants/{id}/licenses/assign` and
`POST /v1/tenants/{id}/licenses/remove`. Tenant auth is Graph `User.ReadWrite.All`; RBAC is
`licenses.write` (SPEC §7). SPEC §9 names the risk of removing a licence a user depends on.

Build the `Update-UserLicense.ps1` worker job + `update-user-license.ps1` entrypoint that applies
the change per user, and the BFF routes that execute through the EPIC-006 apply contract (T-0108:
`Idempotency-Key`, confirmation, gates, audit). `license-plan-preview.ts` computes the plan
preview (`before`/`after` per user) shown for confirmation. Every change writes a `LicenseChange`
and an `AuditEvent`. Bulk returns a per-row result and stops on first failure by default, reusing
the EPIC-006 batch semantics. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Single and bulk assign/remove succeed and return per-row results; a removal requires the
      plan preview and confirmation.
- [ ] Execution goes through the EPIC-006 apply contract and writes `LicenseChange` +
      `AuditEvent` per row.
- [ ] A repeated `Idempotency-Key` does not re-execute.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
