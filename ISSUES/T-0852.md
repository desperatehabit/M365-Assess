# T-0852 — Mount and deliver EPIC-022 Spam, Quarantine & Allow/Block routes and workers

## Report

The EPIC-022 factories (`createQuarantineRoutes`, `createQuarantineBulkRoutes`,
`createQuarantinePoliciesRoutes`, `createAllowBlockRoutes`, `createFilterRoutes`,
`createFilterTemplateRoutes`) exist under `portal/bff/src/routes/` and are tested, but
`portal/bff/src/app.ts` imports none of them and `portal/bff/src/adapters/` has no provider, so the
endpoints 404.

Three read worker entrypoints that the routes name are absent from `portal/workers/`:

- `get-quarantine.ps1` — quarantine list/preview read (`quarantine.ts:226`).
- `get-allow-block.ps1` — allow/block read (`allow-block.ts:149`); only `set-allow-block-entry.ps1` exists.
- `get-quarantine-policies.ps1` — policy read (`quarantine-policies.ts:142`); only `set-quarantine-policy.ps1` exists.

Pages exist: spam-filter tabs (`app/email/spamfilter/page.tsx`), quarantine, allow/block, and templates.

## Fix direction

Author the three missing read worker wrappers (with their `M365Portal.Workers` implementations),
add the quarantine/allow-block/filter adapter on `runFeatureWorker`, and mount the route groups in
`app.ts`.

## Acceptance

- [ ] Every EPIC-022 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [ ] `get-quarantine.ps1`, `get-allow-block.ps1`, and `get-quarantine-policies.ps1` exist and are tested.
- [ ] Quarantine release/deny, allow/block, and filter writes run through their real workers.
- [ ] No file outside `scope` is modified.
