# T-0684 — Tenant-scoped portal configuration backup

## Report

EPIC-035 SPEC.md §2 US-2 and §4.1 step 1: a **tenant** backup covers a tenant's portal
configuration — standards assignments, drift triage, and schedules — recorded with
`type = tenant` and a `tenantId`. §7 makes tenant backups tenant-scoped (EPIC-038).

Deliver `portal/bff/src/backup/tenant.ts` on top of the T-0683 collector: resolve the tenant's
configuration tables, dump **only rows for that `tenantId`**, serialize via the T-0682 archive,
store the archive, and record the tenant `Backup` row plus audit. The standards/drift/schedule
tables are owned by EPIC-014 and EPIC-007 and are consumed through the repository by name; a
missing table is skipped and noted in the manifest. No restore and no route code here.

## Acceptance

- [ ] A tenant backup contains only rows matching the requested `tenantId`; instance rows never leak in.
- [ ] The `Backup` row records `type = tenant` and the `tenantId`.
- [ ] Creating a tenant backup writes an audit event.
- [ ] A test covers cross-tenant isolation and fails without it.
- [ ] No file outside `scope` is modified.
