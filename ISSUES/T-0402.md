# T-0402 — Transport rule CRUD, enable/disable, and priority

## Report

EPIC-021 SPEC.md §2 (US-1), §3.1, §4.1, §4.3, §6, and §8 require transport-rule create/edit/
delete, enable/disable, and explicit priority changes, each *condition/action builder → plan
preview → apply* through the EPIC-006 gate. Resolved §11.1 adopts the **common condition/action
set first, with full EXO parity later**; §9 risk "rule priority conflicts" is mitigated by
explicit priority control plus preview.

Deliver `domain/transport/rule-builder.ts` with the common condition/action/exceptions model and
its validation, plus the write routes on `transport-rules.ts` and the `Set-TransportRule.ps1`
worker job plus `set-transport-rule.ps1` entrypoint. Priority changes and enable/disable are
explicit gated writes (T-0107) with before/after and an `AuditEvent`; an unsupported condition or
action is rejected with a structured error, never silently dropped. Extend `portal.v1.yaml`.
Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Create/edit/delete, enable/disable, and priority changes apply through the EPIC-006 gate with before/after and audit.
- [ ] The builder rejects conditions/actions outside the adopted common set with a structured error.
- [ ] The plan preview shows the rule JSON before apply, and priority changes are explicit.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
