# T-0548 — Alert list and triage worker and API

## Report

EPIC-028 SPEC.md §2 US-4, §3.3, §4.1, and §6 define alert triage: a list with Title · Service
source (Defender/MDO/Graph) · Severity · Status · Entity · Created and row actions (`View`, `Set
status`, `Assign`, `Comment`, `Create incident` where supported). §6 exposes `GET
/v1/tenants/{id}/alerts` and `POST /v1/tenants/{id}/alerts/{alertId}/{action}`; §7 uses Graph
`SecurityAlert.ReadWrite.All`. §11 item 1 is resolved (adopted): **write-back where the API
supports it**, read-only elsewhere; every change persists via T-0541.

Deliver a `Get-Alerts.ps1` handler (entrypoint `get-alerts.ps1`) returning normalized alerts
(T-0542) from Defender/MDO/Graph and an `Invoke-AlertAction.ps1` handler (entrypoint
`invoke-alert-action.ps1`) for status/assign/comment/create-incident-where-supported, applying
writes through the EPIC-006 gated executor (T-0108). The list route validates `incidents.read`;
the action route validates `incidents.triage` + `Remediation.Apply` and records an
`AlertStateChange`. Extend `portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/alerts` returns normalized alerts with the §3.3 columns, paginated.
- [ ] Status/assign/comment apply where supported; unsupported writes are refused with a clear error.
- [ ] Create-incident appears only when the source supports it; every change is audited.
- [ ] A test covers listing, a supported action, and an unsupported-write refusal and fails without it.
- [ ] No file outside `scope` is modified.
