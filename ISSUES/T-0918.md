# T-0918 — Runs list shows the tenant ID instead of the tenant's name

## Report

**Assessments > Runs** shows the tenant ID (a GUID) in the Tenant column. The tenant was
onboarded with a display name, and the operator does not know the tenant ID. The operator
expects the name, and is fine with the ID appearing as well.

## Cause

`RunsTable.tsx` already renders `run.tenantDisplayName || run.tenantId` (lines 628 and 794), and
the tenant filter matches on both. The BFF never sends `tenantDisplayName`: `RunListItem` in
`routes/runs-list.ts` has only `tenantId`, and the run store does not join the tenants table.
The table always falls back to the ID. Only the demo dataset sets the name.

## Fix direction

- Add `tenantDisplayName` to `RunListItem` (and the run detail response), resolved from the
  tenant store's `displayName`. Fall back to the ID only when the tenant has been removed.
- Show the name as the main text, with the ID as secondary text or a tooltip, for example
  *Test Tenant* on top and the GUID in small grey text.
- Sweep the other pages for the same pattern (raw tenant IDs, run IDs or object IDs shown where a
  readable name exists) and list what was found here.

## Acceptance

- [ ] The Runs list and run detail show the tenant's display name, with the ID as secondary text.
- [x] Filtering by tenant name still works.
- [x] A run whose tenant was deleted still renders (ID fallback).
- [x] No file outside `scope` is modified, unless the sweep adds to `scope`.

The first box stays open: the Runs list shows the name as main text and the ID as
secondary text, and the run detail shows the name, but `RunDetailTabs` (out of this
ticket's scope) does not render the ID as secondary text next to it.

## Fix

- `portal/bff/src/adapters/runs.ts` — the run store resolves the tenant name from the
  tenant store (`repo.getTenant` / `repo.listTenants`) and attaches it as
  `tenantDisplayName` to:
  - every `GET /v1/runs` list row (`listRuns` loads the tenant map once per page; it
    sweeps `listTenants({ includeDeleted: true })` so a deleted tenant's historical run
    still lists, but resolves names only for live tenants);
  - `getRunById`, which the run-detail route spreads into `GET /v1/runs/{runId}`, so the
    detail response (and its page) shows the name as well;
  - `listChildRuns`, so the run detail's per-tenant progress rows have names.
  A tenant that has been removed (soft-deleted, or absent) yields no name and the record
  keeps only `tenantId`, which is the ID fallback. `all` (the system-job wildcard) is
  skipped.
- `portal/bff/src/routes/runs-list.ts` — `RunListItem.tenantDisplayName` added and passed
  through untouched; the multi-tenant roll-up row clears it because a parent spans several
  tenants.
- `portal/web/src/components/RunsTable.tsx` —
  - Tenant column: display name is the main text (`getTenantLabel`), the tenant ID is a
    small mono line underneath with `title={run.tenantId}`; card view shows the same pair.
  - A row without a name falls back to the tenant ID (deleted tenant).
  - A multi-tenant parent with no single name shows `Multiple tenants`.
  - The tenant filter matches the name **or** the ID, for the row and for any of its
    per-tenant children.
