# T-0918 — Runs list shows the tenant ID instead of the tenant's name

## Report

**Assessments > Runs** shows the tenant ID (a GUID) in the Tenant column. The tenant was
onboarded with a display name, and the operator does not know the tenant ID. The operator
expects the name, and is fine with the ID appearing as well.

## Cause

`RunsTable.tsx` already renders `run.tenantDisplayName || run.tenantId` (lines 628 and 794), and
the tenant filter matches on both. The BFF never sends `tenantDisplayName`: `RunListItem` in
`routes/runs-list.ts` has only `tenantId`, and the run store does not join the tenants table.
The table always falls back to the ID. Only the demo dataset sets the name.

## Fix direction

- Add `tenantDisplayName` to `RunListItem` (and the run detail response), resolved from the
  tenant store's `displayName`. Fall back to the ID only when the tenant has been removed.
- Show the name as the main text, with the ID as secondary text or a tooltip, for example
  *Test Tenant* on top and the GUID in small grey text.
- Sweep the other pages for the same pattern (raw tenant IDs, run IDs or object IDs shown where a
  readable name exists) and list what was found here.

## Acceptance

- [ ] The Runs list and run detail show the tenant's display name, with the ID as secondary text.
- [ ] Filtering by tenant name still works.
- [ ] A run whose tenant was deleted still renders (ID fallback).
- [ ] No file outside `scope` is modified, unless the sweep adds to `scope`.
