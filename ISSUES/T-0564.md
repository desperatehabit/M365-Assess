# T-0564 — Batched per-tenant alert evaluation with dry-run and sandboxed script mode

## Report

EPIC-029 SPEC.md §4.1 defines evaluation: the alert orchestrator (EPIC-007 system timer, T-0123)
evaluates rules per tenant, reads each rule's log source, and fires an `AlertEvent` on a match;
§4.2 requires `Test` to evaluate against current data **without delivering**; §6 exposes
`POST /v1/alert-rules/{id}/test`. §11.4 is resolved to **batched-per-tenant rule evaluation** so
Graph calls are bounded.

Following ADR-0014, add `Invoke-AlertEvaluation.ps1` (job handler) plus `evaluate-alerts.ps1`
(entrypoint) that load the tenant's enabled rules once, fetch each distinct log source once per
batch, rehydrate conditions via T-0563, and emit fired events. Script-mode rules must not run
arbitrary code here: they are dispatched only to the EPIC-007 sandbox (T-0126) and audited.
Implement the dry-run route in `alert-rules-test.ts`, which returns the would-fire result and
performs no delivery. EPIC-002 supplies channel credentials only when a real delivery path is used
(prose dependency).

## Acceptance

- [ ] The worker evaluates enabled rules per tenant and emits `AlertEvent`s for matches only.
- [ ] Each distinct log source is queried once per tenant batch, not once per rule.
- [ ] `POST /v1/alert-rules/{id}/test` returns matched/not-matched and never delivers.
- [ ] Script-mode rules are dispatched to the EPIC-007 sandbox and audited; no in-process script execution occurs.
- [ ] Tests cover evaluation and dry-run and fail without the code.
- [ ] No file outside `scope` is modified.
