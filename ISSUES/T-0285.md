# T-0285 — CaTemplate persistence and template CRUD API

## Report

EPIC-015 SPEC.md §5 defines `CaTemplate` — `id`, `name`, `policyJson`, `source(local|community)`,
`category`. §6 fixes `GET`/`POST`/`PATCH`/`DELETE /v1/ca-templates`. §11.3 is resolved to **local
templates first**, with the community catalog deferred to EPIC-039; §9 warns of template drift and
requires templates to be **versioned** with deploy showing the diff.

Deliver a numbered forward-only migration and repository for `CaTemplate`, and the BFF CRUD
routes behind RBAC `ca.deploy` (or an admin scope). Templates carry a version field so the T-0286
deploy can diff; `source` is constrained to `local` for now (community rows are reserved for
EPIC-039). `policyJson` is validated as a well-formed CA policy object before save. No tenant
writes.

## Acceptance

- [ ] A migration creates the `CaTemplate` table with versioning; the repository round-trips the §5 fields.
- [ ] CRUD routes list, create, edit, and delete templates and validate `policyJson`.
- [ ] `source` is `local` in v1; community is not accepted.
- [ ] A test covers the repository/routes and fails without them.
- [ ] No file outside `scope` is modified.
