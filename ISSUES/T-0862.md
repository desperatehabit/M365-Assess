# T-0862 — Mount and deliver EPIC-032 Audit Logs & Webhooks routes

## Report

The EPIC-032 factories (`createAuditSearchRoutes`, `createAuditSearchScheduleRoutes`,
`createAuditCoverageRoutes`, `createAuditExclusionWindowRoutes`, `createWebhooksRoutes`,
`createWebhookNotifyRoute`) exist under `portal/bff/src/routes/` and are tested, but
`portal/bff/src/app.ts` imports none of them and there is no adapter under `portal/bff/src/adapters/`,
so the endpoints 404. `search-audit.ps1`, `start-historical-search.ps1`, `manage-webhooks.ps1`, and
migration `0040_audit_logs_webhooks.sql` exist.

Functional/UI gaps:

- The Saved Log Searches page (SPEC §3.2) does not exist: `components/audit/SavedSearchesTable.tsx`
  is referenced only by `AuditLogs.test.tsx`, and no page under `app/audit-logs/` renders it.
- `portal/bff/src/routes/webhooks.ts:233-239` returns 501 when `notificationUrl` is unset
  (SPEC §3.5, §6).
- `portal/db/src/audit-repository.ts:98-108` exposes only create/get/list/listExpiring for webhooks;
  there is no delete or update method despite SPEC §6 DELETE and §3.5 Renew/Recreate/Delete, and
  `webhook_subscriptions` has no `deletedAt` column (`0040_audit_logs_webhooks.sql:39-50`).

## Acceptance

- [x] Every EPIC-032 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Audit search/schedule/coverage/exclusion and webhook CRUD run their real workers and storage.
- [x] Webhook delete/update/renew/recreate are supported by the repository.
- [x] The Saved Log Searches page exists and renders saved searches.
- [x] No file outside `scope` is modified.

## Fix

`createAuditProviders` binds the route seams to their existing workers. Manual search and
directory audits call `search-audit.ps1` through the T-0007 envelope; a saved search's Run
re-dispatches the same filter and returns the worker's completed job; coverage calls
`get-audit-coverage.ps1` with the portal-computed `lastSearchAt` and finding; webhook
create/renew/recreate/delete/test call `manage-webhooks.ps1` with the flat action job.

`createApp` mounts all §6 route groups behind `resolveCaller`, the shared authorizer, and
the audit repository over migration 0040. Saved searches and exclusion windows persist
through that repository, and the saved-search Run/Schedule routes use the EPIC-007
`ScheduleStore`. Webhook writes now pass the configured notification URL
(`${workerBaseUrl}/v1/webhooks/notify`), so create no longer answers 501. Each lifecycle
result is mirrored into `webhook_subscriptions`, and migration 0129 adds the `deletedAt`
marker; the repository gains `updateWebhookSubscription` and
`softDeleteWebhookSubscription` (both write an audit event) and every read hides deleted
rows. The new Saved Log Searches page under `app/audit-logs/searches/` renders the existing
table and wires Run, Edit, Schedule, and Delete to the saved-search API.

The unauthenticated notification receiver stays unmounted: the repository does not store
the subscription `clientState` it needs to validate notifications, and content-bundle
processing is explicitly deferred by SPEC §11.2. All mounted endpoints are registered in
the EPIC-038 permission registry, published through their OpenAPI fragments, and the
checked-in contract is regenerated.
