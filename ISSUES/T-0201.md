# T-0201 — User directory read API with filters and built-in reports

## Report

EPIC-011 SPEC.md §3.1, §3.2, §4.1 and §6 (US-1, US-8) require `GET /v1/tenants/{id}/users` to
list, search, and filter tenant users and to back the inactive/guest/sign-in reports. SPEC.md §5
says user objects are **not mirrored**: the portal reads Graph live and stores only operation
records and audit. §11.2 resolves the caching question — **live Graph reads for detail and list
v1; a list/report cache is deferred.**

Deliver a read-only `Get-TenantUsers` worker job plus a `get-tenant-users.ps1` entrypoint that
reads the job envelope (T-0007), runs through the EPIC-001 worker/queue path (T-0010) using
child-process credential materialization (T-0011), and returns display name, UPN, type, licenses,
MFA state, last sign-in, status (enabled/disabled), and department with cursor pagination. The
BFF route validates RBAC/tenant scope, enqueues the job, and serves results; extend
`portal.v1.yaml` with the operation and its filters. Tenant and credential records come from
EPIC-002 (not yet authored) — that is a data dependency, not a code dependency here.

## Acceptance

- [ ] `GET /v1/tenants/{id}/users` returns filtered, cursor-paginated users with the §3.1 columns.
- [ ] The inactive, guest, and sign-in report views derive from the same read path.
- [ ] The worker performs no tenant write and the BFF route holds no M365 SDK call.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
