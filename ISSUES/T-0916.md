# T-0916 — In-portal onboarding needs someone at the BFF machine's desktop

## Report

Onboarding signs in as an admin three times (Graph twice, Exchange Online once). Since T-0914
this works on Windows by opening a PowerShell window on the BFF machine, where Windows shows the
sign-in prompts. That holds for local development, where the operator sits at that machine. A
deployed BFF (a server, a container, a service account) has no interactive desktop, so the
prompts would appear to nobody, and the job waits until its 30-minute timeout. Off Windows, the
browser fallback has the same problem.

## Fix direction

Use the device-code flow for the admin sign-ins (`Connect-MgGraph -UseDeviceCode`,
`Connect-ExchangeOnline -Device`) when there is no interactive desktop, and relay each code to
the wizard (job progress event, displayed with the verification URL) so the operator signs in
from their own browser. Keep the sign-in window for local Windows use.

- [ ] The wizard shows each device code and URL while the job waits for it.
