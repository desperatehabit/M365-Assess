# T-0404 — Connectors read, write, enable/disable, and secret handling

## Report

EPIC-021 SPEC.md §2 (US-3), §3.2, §4.1, §4.3, §5, and §8 require connectors to be listed and
managed (create/edit/delete, enable/disable, clone to template). §3.2 fixes the columns (name,
type inbound/outbound, state, from/to, TLS, last modified); §4.3 requires disabling a connector
that carries production mail flow to be flagged with a warning.

Resolved §11.2 resolves connector secrets (e.g. partner TLS certificates): **store them by
reference in the credential store, never in the database**. Deliver
`domain/transport/connector-secret.ts`, which exchanges a secret reference for material only
inside the tenant child process (T-0011) and guarantees no secret value is returned to the BFF or
persisted. Add `connectors.ts` for the §6 `GET`/`POST`/`PATCH`/`DELETE` routes and the
`Set-Connector.ps1` worker job plus `set-connector.ps1` entrypoint. Every write routes through the
EPIC-006 gate (T-0107) with before/after and an `AuditEvent`; disabling a mail-flow connector
surfaces the warning before apply. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Connectors list with the §3.2 columns and create/edit/delete/enable/disable through the gate.
- [ ] A connector secret is stored only as a reference; no secret value appears in the database or an API response.
- [ ] Disabling a mail-flow-carrying connector warns before apply and is audited.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
