# T-0956 — Status and wording fixes from the live result validation

## Report

The live validation found these checks report correct data with a misleading status or message:

1. **DNS-SPF-001, DNS-DKIM-001, DNS-DMARC-001** report **Review** with "No authoritative domains
   found" for a tenant whose only domain is `*.onmicrosoft.com`
   (`Get-DnsSecurityConfig.ps1` lines 91 and 101). Nothing can be reviewed; the status should be
   Info / not applicable, with the reason.
2. **CA-EXCLUSION-001** reports **Warning**, "No enabled Conditional Access policies found",
   while security defaults are enabled (`Get-StrykerIncidentReadiness.ps1`). With no CA
   policies there are no exclusions; report Info and point at security defaults.
3. **ENTRA-SOD-001** fails with "Global Admins: 1, Priv Role Admins: 0, Overlap: 0". The rule
   needs at least one Privileged Role Administrator, but the message reads like a pass. Say
   why it failed ("No Privileged Role Administrator assigned").
4. **ENTRA-PASSWORD-005** reports Review, "Password Rule Settings not available", when no
   directory settings exist. ENTRA-PASSWORD-002 reports the same state as Info ("using Entra
   defaults"). Use the same status and wording.

## Acceptance

- [ ] Each of the four cases reports the status above with a message that states the reason.
- [ ] Tests cover each case and fail without the change.
