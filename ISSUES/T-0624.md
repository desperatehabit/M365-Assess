# T-0624 — Audit search coverage API

## Report

EPIC-032 SPEC.md §3.3 defines the **Search Coverage** view: which tenants have audit-log
ingestion enabled, their search windows, and gaps, tying to the module's `COMPLIANCE-AUDIT-001`
check. §4.2 says coverage is computed from tenant audit config plus search history, and gaps link
to the audit-enablement remediation. §6 exposes `GET /v1/tenants/{id}/audit/coverage`.

Resolved §11.3 adopts a **live-first** computation (query tenant audit configuration at request
time) with an explicit seam for the reporting-DB cache later. Build the
`Get-AuditCoverage.ps1` worker job + `get-audit-coverage.ps1` entrypoint that reports
`auditEnabled`, `lastSearchAt`, and `gaps[]`, and the BFF route that upserts the T-0621
`AuditCoverage` row. Gaps reference the `COMPLIANCE-AUDIT-001` finding from T-0046's run results
and link to EPIC-006 remediation (prose). Extend `portal.v1.yaml`.

## Acceptance

- [ ] The endpoint reports per-tenant `auditEnabled`, `lastSearchAt`, and `gaps[]`, computed
      live and cached via the T-0621 repository.
- [ ] A tenant with audit logging disabled yields a gap linked to `COMPLIANCE-AUDIT-001`.
- [ ] The reporting-cache seam is a named function so the cache can be swapped in later without
      changing the route contract.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
