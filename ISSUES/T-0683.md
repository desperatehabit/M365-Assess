# T-0683 — Instance configuration backup collection

## Report

EPIC-035 SPEC.md §2 US-1 and §4.1 step 1: an **instance** backup collects the instance-wide tables
(tenants, roles, templates, alerts, settings), serializes them with the T-0682 archive, stores the
archive on the artifact tier, and records a `Backup` row with its manifest (T-0681). §9 requires
credential **references only** and encryption at rest.

Deliver `collect.ts` (a generic table-dump collector driven by the repository, excluding
secret-bearing columns) and `instance.ts` (the instance scope: the table allow-list above,
artifact write, `Backup` row creation, audit event). The role/template/alert/settings tables are
owned by other epics (EPIC-038 roles, EPIC-014 templates, EPIC-029 alerts, EPIC-037 settings) and
are consumed here through the repository interface by name — this ticket does not create them; if a
table is absent it is skipped and recorded as such in the manifest. No restore and no route code
here.

## Acceptance

- [ ] An instance backup writes an archive plus a `Backup` row carrying `schemaVersion`, `artifactRef`, and `checksum`.
- [ ] The collector excludes credential/secret columns and records which tables were included or skipped.
- [ ] Creating a backup writes an audit event.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
