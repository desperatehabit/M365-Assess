# T-0467 — Mailbox restore worker and progress API with plan preview

## Report

EPIC-024 SPEC.md §2 US-4, §3.4, §4.2, and §5 define mailbox restore: select mailbox → choose
scope (mailbox/items/date) → target → confirm; a plan shows what will be restored and where; on
confirm the restore runs and is audited with before/after item counts, tracked as a
`RestoreJob`. §6 exposes `POST /v1/tenants/{id}/mail/restores` and `GET
/v1/tenants/{id}/mail/restores/{jobId}`. §11 item 3 is resolved (adopted): **mailbox-only first,
then item-level**. §9 requires a plan preview, confirmation, and audit to avoid overwriting data.

Deliver a `Start-MailboxRestore.ps1` handler (entrypoint `start-mailbox-restore.ps1`) that
builds a plan preview, restores a whole mailbox first and item-level mailboxes only when
targeted, applies through the EPIC-006 gated executor (T-0108), updates the `RestoreJob` state
through the repository (T-0461), and records before/after item counts. The route validates
`mailtools.restore` + `Remediation.Apply`, requires confirmation, and serves progress. Extend
`portal.v1.yaml`.

## Acceptance

- [ ] Restore returns a plan preview before any write; nothing is restored on preview.
- [ ] Mailbox-only restore works; item-level restore is accepted when explicitly scoped.
- [ ] Progress is served from the persisted `RestoreJob`; before/after counts are audited.
- [ ] A test covers preview, mailbox-only apply, and the audit record and fails without it.
- [ ] No file outside `scope` is modified.
