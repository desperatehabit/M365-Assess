# T-0025 — Onboarding worker wrapping Grant-M365AssessConsent

## Report

EPIC-002 SPEC.md §4.1 defines direct onboarding with app registration: the portal calls the
existing `Grant-M365AssessConsent` setup cmdlet
(`src/M365-Assess/Setup/Grant-M365AssessConsent.ps1`), which creates the app registration,
assigns the 24 Graph + 3 EXO + 1 Purview permissions, grants admin consent, and assigns the 3
directory roles + 2 EXO RBAC groups. §8 classifies this as a tenant-mutating **setup write**:
confirmation required, `before`/`after` recorded, and an `AuditEvent` written; the cmdlet is
`ConfirmImpact: High` and the portal must never call it with `-Force` from an unconfirmed path.

Deliver a worker entrypoint that **invokes the existing cmdlet via the worker pool** (T-0010)
rather than reimplementing it, and the gated, audited `POST /v1/tenants/{id}/onboard` route
(T-0013 admin-only). The result stores the credential by reference (T-0023) and creates the
tenant row. This ticket does not edit `src/**`; it wraps the cmdlet.

## Acceptance

- [ ] Onboarding runs `Grant-M365AssessConsent` in a worker; the portal never reimplements it.
- [ ] The route requires explicit confirmation and `tenants.onboard`; an unconfirmed path is
      refused and never passes `-Force`.
- [ ] Success records an audit event with before/after and stores a credential reference.
- [ ] A half-provisioned failure still leaves an audit record and a precise error.
- [ ] No file outside `scope` is modified.
