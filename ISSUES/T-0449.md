# T-0449 — Resource CRUD, room-list membership, and management page

## Report

EPIC-023 SPEC.md §2 US-3, §3.3, and §4.3 define resource management: CRUD rooms/equipment,
add/remove room-list membership, and capacity/location edits. §6 exposes
`POST`/`PATCH`/`DELETE` on `/v1/tenants/{id}/resources/{kind}`; §8 requires all writes through
EPIC-006 with confirmation on deletes.

Deliver an `Invoke-ResourceAction.ps1` handler (entrypoint `invoke-resource-action.ps1`) that
applies create/edit/delete and membership add/remove through the EPIC-006 gated executor
(T-0108) with before/after and audit, plus the write route (validates `resources.write` +
`Remediation.Apply`) and the **Rooms** / **Equipment** / **Room Lists** page with row actions
and membership editing. Extend `portal.v1.yaml` with the write operations.

## Acceptance

- [ ] Rooms and equipment create/edit/delete; deletes require confirmation.
- [ ] Room-list membership can be added and removed through the API and UI.
- [ ] All writes route through EPIC-006 and are audited.
- [ ] A test covers a write and a duplicate-membership rejection and fails without it.
- [ ] No file outside `scope` is modified.
