# T-0744 — Portal users CRUD, base-role assignment, and /v1/me

## Report

EPIC-038 SPEC.md §6: `GET`/`POST`/`PATCH`/`DELETE /v1/users` for portal user CRUD and
`GET /v1/me` for caller identity, roles, effective permissions, and scope. SPEC.md §3.1: `Add
user` opens an `ActionDialog` (UPN, role, scope); users are federated identities with no
passwords (`PortalUser`, §5). Admin-surface changes require `CIPP.Admin.*`; role changes must be
authorized through T-0743.

Add the `users.ts` and `me.ts` routes. `POST /v1/users` creates a `PortalUser` and assigns one
base role; `PATCH` updates display name/status and reassigns a base role; `DELETE` removes.
`GET /v1/me` returns the caller's identity, roles, effective permissions (from T-0743), and scope
summary. Every mutation checks `CIPP.Admin.*` via T-0743 and writes an access `AuditEvent`
(T-0750 provides the writer). Extend `portal.v1.yaml`.

## Acceptance

- [ ] `/v1/users` supports list/create/update/delete; `/v1/me` returns identity, roles, permissions, and scope.
- [ ] A user can be assigned one of the four base roles; an invalid role is rejected.
- [ ] Mutations require `CIPP.Admin.*` and are denied otherwise.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
