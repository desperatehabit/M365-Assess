# T-0688 — Retention pruning, replication, and backup settings API

## Report

EPIC-035 SPEC.md §2 US-4, §3.3, and §4.3: retention prunes old backups, replication copies the
latest archive to a secondary target, and the schedule comes from EPIC-007; §6 defines
`GET`/`PUT /v1/backup-settings` over the `BackupConfig` entity. §11.2 is resolved to a JSON
archive and §11.3 is resolved to **same storage tier first, external later**.

Deliver `retention.ts` (prune backups and their artifacts older than `retentionDays`, audited),
`replication.ts` (copy the latest successful archive to the configured secondary location **on the
same storage tier**; an external/regional target is deferred), and the `backup-settings.ts` route
reading/writing `BackupConfig`. Scheduled invocation reuses the EPIC-007 scheduler (T-0124) seam;
this ticket defines the prunable/replicable units, not the cron parser.

## Acceptance

- [ ] Retention prunes expired backups and their artifacts and leaves unexpired ones untouched.
- [ ] Replication copies the latest archive to the secondary same-tier location and is idempotent.
- [ ] `GET`/`PUT /v1/backup-settings` persist and return `retentionDays` and `replicationTarget`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
