# T-0011 — Resolve and materialize tenant credentials inside the child process

## Report

EPIC-001 SPEC.md §4.4: `Resolve-TenantCredential` loads the tenant's credential **by reference**
from storage and materializes it only inside the child process, passing it through
`$ctx.Auth`; secrets must never enter parent-process memory, `context.json`, logs, or API
responses (SPEC §10; §9 risk "secret leakage in child-process transport").

Deliver:

- A worker-side `Resolve-TenantCredential` that reads the `TenantCredential` row
  (`portal/db/src/repository.ts`) by `secretRef`, resolves it from the credential store, and
  returns material suitable for `$ctx.Auth` (`Certificate`/`CertificatePath`/thumbprint or
  client secret; environment).
- The job envelope carries only the credential reference; `context.json` for the child carries a
  reference too (the child resolves it).
- Log redaction for this path.

## Acceptance

- [ ] Given a stored credential reference, the child resolves and connects; the parent never
      sees secret material.
- [ ] A test asserts `context.json` and every API response contain no secret value.
- [ ] A test asserts an unsupported credential combination (e.g. EXO with a client secret)
      fails with a clear, non-secret error.
- [ ] No file outside `scope` is modified.
