# T-0121 — 6-field cron parser with TZOffset and schedule contracts

## Report

EPIC-007 SPEC.md §4.1 says "Cron format follows CIPP's **6-field** cron (seconds included) with
an optional timezone offset; the UI renders a human-readable description." §11.1 resolves to
adopt the 6-field format with `TZOffset`. §9 risk "cron/timezone bugs" is mitigated by reusing a
vetted parser and storing the timezone explicitly.

Deliver:

- `portal/contracts/src/schedules.ts`: the `Schedule` shape (`id`, `name`, `type`, `cron`,
  `timezone`, `targetScope`, `command`, `parameters`, `enabled`, `isSystem`, `lastRunAt`,
  `nextRunAt`) and the job-type enum from §4.2.
- `portal/bff/src/scheduler/cron.ts`: parse/validate a 6-field cron (seconds, minutes, hours,
  day-of-month, month, day-of-week) plus `TZOffset`, compute the next fire time in the stored
  timezone, and produce a human-readable description.
- Tests for next-fire computation across DST/offset boundaries, and rejection of a 5-field or
  malformed expression.

## Acceptance

- [ ] A valid 6-field expression with `TZOffset` computes the correct next fire time.
- [ ] A 5-field or malformed expression is rejected with a clear error.
- [ ] A human-readable description is produced for the Scheduler UI.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
