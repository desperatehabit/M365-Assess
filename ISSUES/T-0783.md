# T-0783 — Graph presets persistence and CRUD API

## Report

EPIC-040 SPEC.md §3.1, §5, §6 (US-2): saved **presets** (`GraphPreset`: `id`, `name`,
`method`, `url`, `body`, `createdBy`) with `GET`/`POST`/`DELETE /v1/graph-presets`. §11 open
question 3 is **resolved (adopted): per-user first, instance-wide later**, so every row carries
`createdBy` and read/list is scoped to the caller unless an instance-wide flag is later added.

Add migration `0125_graph_presets.sql` and `graph-preset-repository.ts`, extending the T-0009
repository interface/index. `graph-preset-service.ts` enforces that a user may only see and
delete their own presets (admins may delete any), and validates `method` against the T-0781
allowlist. A preset stores no tenant credential and no secret.

## Acceptance

- [ ] Migration `0125_graph_presets.sql` is forward-only and creates `GraphPreset` with `createdBy`.
- [ ] `GET`/`POST`/`DELETE /v1/graph-presets` are per-user scoped; deleting another user's preset is denied for non-admins.
- [ ] Preset methods are validated against the T-0781 allowlist.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
