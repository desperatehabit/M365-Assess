# T-0545 — Incident detail worker and API

## Report

EPIC-028 SPEC.md §2 US-2 and §3.2 define the incident detail: **Overview** (severity, status,
classification, assignee), **Alerts** (linked alerts), **Entities** (users/devices/mailboxes
involved), **Timeline** (events + comments), and **Notes** (portal comments). §6 exposes `GET
/v1/tenants/{id}/incidents/{incidentId}`. Incidents/alerts are read live from Graph/Defender per
§5; portal notes and state changes are merged from persistence (T-0541).

Deliver a `Get-IncidentDetail.ps1` handler (entrypoint `get-incident-detail.ps1`) that reads one
incident with its linked alerts (normalized via T-0542), entities, and timeline, and merges
persisted portal notes/state changes, returning a `ResultEnvelope`; plus the read route
validating `incidents.read` and tenant scope. Extend `portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/incidents/{incidentId}` returns alerts, entities, and timeline.
- [ ] Persisted portal notes and state changes are merged into the timeline/notes.
- [ ] A caller without `incidents.read` is refused; unknown incident ids return a structured 404.
- [ ] A test covers detail assembly and note merge and fails without it.
- [ ] No file outside `scope` is modified.
