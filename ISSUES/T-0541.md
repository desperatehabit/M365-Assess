# T-0541 — IncidentNote and AlertStateChange persistence

## Report

EPIC-028 SPEC.md §5 fixes the persisted entities: `IncidentNote` (`id`, `tenantId`,
`incidentId`, `body`, `author`, `at`) for portal-side comments and `AlertStateChange` (`id`,
`tenantId`, `alertId`/`incidentId`, `from`, `to`, `by`, `at`, `reason`) as the triage audit,
with `AuditEvent` for every write. Incidents/alerts are read live from Graph/Defender; only
portal notes and state changes persist. ADR-0015 and `03-database.md` require a numbered,
forward-only migration behind the repository interface.

Deliver migration `0052_incident_triage.sql` (do not reuse a claimed lower number) with
`incident_notes` and `alert_state_changes` tables, plus create/get/list methods on
`portal/db/src/repository.ts` and `sqlite-repository.ts` for both entities, tenant-scoped. This
ticket adds no routes and no worker code.

## Acceptance

- [ ] Migration 0052 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes `IncidentNote` and `AlertStateChange` create/get/list, tenant-scoped.
- [ ] State changes record from/to/by/at/reason; no secret value is stored.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
