# T-0722 — Application settings API (GET/PUT) with audit

## Report

EPIC-037 SPEC.md §6 defines `GET`/`PUT /v1/settings`; §4.1 requires changes to be instance writes
that **validate → preview where impactful → apply → audit**; §7 gates settings on
`CIPP.AppSettings.*` (RBAC owned by EPIC-038).

Deliver `routes/settings.ts`: `GET` returns settings grouped by the §3.1 tab schema with
sensitive values masked where applicable; `PUT` validates every key against the T-0721 typed schema
before applying atomically and writing an audit event. Invalid or unknown keys return the
structured error shape. Enforce the `CIPP.AppSettings.*` permission seam by contract and stub it
in tests. Update `portal.v1.yaml`. The settings UI is T-0728.

## Acceptance

- [ ] `GET`/`PUT /v1/settings` are implemented and match the OpenAPI document.
- [ ] A PUT with an unknown or ill-typed key is rejected atomically; nothing is partially written.
- [ ] Every accepted change writes an audit event.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
