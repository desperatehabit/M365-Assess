# T-0104 — Remediation gate evaluation and audited allowlist governance

## Report

EPIC-006 SPEC.md §4.1 step 5 and §7, plus
[`06-remediation.md`](../../docs/portal-specs/00-guides/06-remediation.md) §4, require every
automated action to pass six gates and record the unmet reason:
`license-missing` (from `licensing-overlay.json` / registry `licensing.minimum`),
`service-unavailable`, RBAC (`403`), tenant-in-caller-scope (`403`), `tenant-readonly`, and
`not-allowlisted`. SPEC.md §11 item 3 resolves allowlist governance as **config-managed,
admin-only, audited**.

Build `Test-RemediationGate` to evaluate all six gates against a caller context passed in from
the BFF (the minimal RBAC seam is T-0013) and the stripped registry key from T-0102, returning
a per-action decision (`planned` or `skipped` + reason, or a rejection for RBAC/scope). Build
`Get-RemediationAllowlist` to load the admin-managed allowlist file and emit an access/audit
record on every decision, including the allowlist membership result. Dot-source both files from
`M365-Assess.psm1`.

## Acceptance

- [ ] A non-allowlisted check and a license-missing check both evaluate to `skipped`, with distinct reasons.
- [ ] RBAC and tenant-scope failures evaluate to a rejection, not a silent skip.
- [ ] The allowlist is load-only config; a gate decision is recorded for audit.
- [ ] A test covers each gate and fails without it.
- [ ] No file outside `scope` is modified.
