# T-0643 — Licence optimization (unused and overused) API

## Report

EPIC-033 SPEC.md §3.2 defines the **Licence Optimization** view: unused licences (assigned but
inactive), overused (assignment errors), and expiring, each row linking to affected users. §4.2
cross-references assignments with activity. Resolved §11.1 adopts the unused-licence heuristic:
**assigned-but-inactive over an inactivity window (default 30 days), using Graph per-user
activity/usage reports as the activity source**. Results are advisory, never auto-remove (SPEC
§9 risk of false positives). §6 exposes `GET /v1/tenants/{id}/licenses/optimization`.

Build the `Get-LicenseOptimization.ps1` worker job that gathers assignments and per-user activity
and the `license-optimization.ts` domain function that classifies a user as unused past the
window; surface overused as Graph assignment errors and expiring as upcoming SKU expiry. Each row
links to the affected users. The BFF route validates RBAC/scope and returns the grouped result.
Extend `portal.v1.yaml`.

## Acceptance

- [ ] Unused users are those assigned a SKU with no activity inside the window; the window is
      configurable and defaults to 30 days.
- [ ] Overused reflects assignment errors and expiring reflects upcoming SKU expiry; each row
      lists the affected users.
- [ ] Results are advisory: no licence is removed by this endpoint.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
