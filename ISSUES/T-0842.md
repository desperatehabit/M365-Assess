# T-0842 — App package ingest and signed download routes

## Report

T-0322's `AppPackageStore` streams a package onto the artifact tier and mints signed,
short-lived URLs; T-0323's upload route takes an already-stored `packageId` and its job runner
hands the worker a signed URL on `/v1/app-packages/:packageId`. Neither end has an HTTP route,
because `server.ts` reads every body as JSON (capped at `MAX_JSON_BODY_BYTES`) and a
`RouteResponse` carries only a buffered `raw` payload.

1. **Streaming seam in `server.ts`.** Let a route opt in to the raw request stream (skipping JSON
   parsing and its body cap) and return a `Readable` response body with a content length.
2. **`POST /v1/tenants/:tenantId/apps/packages`** (`app-packages.ts`): stream an
   `application/octet-stream` body into `AppPackageStore.storePackage`, honouring
   `Content-Length` as the declared size, behind `Endpoint.Application.ReadWrite` or
   `Remediation.Apply`. Return `{ packageId, fileName, size, sha256 }`; never a path.
3. **`GET /v1/app-packages/:packageId`**: authenticated only by the signed query
   (`verifySignedUrl`); 403 when tampered, 410 when expired; stream via `openPackage`.
4. **Config:** `M365_BFF_APP_PACKAGE_SECRET` (≥ 32 bytes; refuse to start the package routes
   without one), `M365_BFF_APP_PACKAGE_MAX_BYTES`, and the base URL workers use to reach the BFF.
5. **Job type:** add `app-upload` to `JOB_TYPES` so the T-0323 runner can go through the
   EPIC-001 queue and emit the standard `ProgressEvent`s.

## Acceptance

- [ ] A package upload streams to the artifact tier without buffering the whole body, and the size cap cuts it off with 413.
- [ ] The download route serves a package only for a valid, unexpired signature and streams it.
- [ ] The signing secret is required configuration and never appears in logs, responses, or events.
- [ ] `app-upload` is a valid job type in the contracts.
- [ ] Tests cover the seam and both routes and fail without them.
- [ ] No file outside `scope` is modified.
