# T-0444 — Bulk contact CSV import with per-row results and duplicate detection

## Report

EPIC-023 SPEC.md §3.1 and §4.1 require bulk CSV import with per-row results, and §9 names the
risks: malformed addresses and duplicate contacts, with duplicate detection as the mitigation.
§6 exposes `POST /v1/tenants/{id}/contacts/import`. §8 requires per-row reporting and the
EPIC-006 write path.

Deliver an `Import-Contacts.ps1` job handler (entrypoint `import-contacts.ps1`) that validates
each row's address, detects duplicates against existing contacts (and within the file), applies
valid rows through the EPIC-006 gated executor, and returns one result per row (`created`,
`skipped-duplicate`, `invalid`, `failed` with a reason). The route accepts the CSV payload,
validates `contacts.write`, and returns the per-row report. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Import returns one result row per input row; no silent partial success.
- [ ] A malformed address and a duplicate are both reported without aborting the whole file.
- [ ] Valid rows are applied through EPIC-006 and audited.
- [ ] A test covers per-row results and duplicate detection and fails without it.
- [ ] No file outside `scope` is modified.
