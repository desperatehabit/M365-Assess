# T-0880 — Single-user PATCH (edit) route is missing

## Report

EPIC-011 SPEC §6 lists `PATCH /v1/tenants/{id}/users/{userId}` for editing a user, but
`portal/bff/src/routes/users.ts:300-305` registers only GET, POST, actions, and bulk-patch; there is
no per-user PATCH. `portal/web/src/lib/usersApi.ts` has no single-user update call. Users can be
created, acted on, and bulk-patched, but not individually edited.

## Acceptance

- [ ] `PATCH /v1/tenants/:tenantId/users/:userId` exists, is authorized, and applies the edit via the
      user worker.
- [ ] A route test covers the edit and fails without it.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `TENANT_USER_PATH` (`/v1/tenants/:tenantId/users/:userId`) now has a PATCH handler sharing the
  bulk wizard's `validatePatchProperties` / `computeUserPatchDiff` and `users.patch` provider, so a
  single edit validates and reports identically to a bulk row. It requires `Identity.User.ReadWrite`
  and tenant scope, supports `preview`, and writes one `users.patch` audit record per apply.
- `updateTenantUser` is exposed from `portal/web/src/lib/usersApi.ts` with the same patchable
  property catalogue.
- Tests in `users-patch.test.ts` cover apply, preview, validation, authorization, scope, an
  unwired provider (501), and worker failure.
