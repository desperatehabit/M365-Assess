# T-0507 — Teams activity report (worker, API, and page)

## Report

EPIC-026 SPEC.md §2 US-3, §3.2, and §4.2 define the **Teams Activity** page: usage per team and
per user (active users, messages, meetings) as report-style tables with drill-through. §6
exposes `GET /v1/tenants/{id}/teams/activity`; §9 requires pagination and date filters. §11 item
2 is resolved (adopted): the activity data source is **Graph usage reports**, with Teams admin
reports as a fallback where Graph lacks a metric.

Deliver a `Get-TeamsActivity.ps1` handler (entrypoint `get-teams-activity.ps1`) that reads Graph
usage reports and falls back to Teams admin reports for missing metrics, returning a
`ResultEnvelope`; plus the read route validating `teams.read` and tenant scope with pagination
and date filters, and the activity page rendering `TeamsActivityTable` with per-team/per-user
drill-through. Extend `portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/teams/activity` returns per-team and per-user usage, paginated.
- [ ] Missing Graph metrics fall back to Teams admin reports; the source is indicated.
- [ ] A caller without `teams.read` is refused; the BFF performs no reporting call directly.
- [ ] A test covers the report mapping and the fallback and fails without it.
- [ ] No file outside `scope` is modified.
