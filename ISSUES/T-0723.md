# T-0723 — Branding schema, repository, and upload validation

## Report

EPIC-037 SPEC.md §5 defines `BrandingConfig` (`colors`, `logoRef`, `coverRef`, `watermark`,
`footer`, `pageNumbers`, `perReportDefaults`) and §9 names **branding upload security** (SVG/logo)
as a risk; §11.2 resolves the allowed branding upload formats and size limits here. ADR-0016 makes
branding a render-time injection consumed by EPIC-005's report rendering (T-0086 reads it).

Deliver `branding/schema.ts` (typed `BrandingConfig` with the §3.2 fields: primary/secondary
colour, footer text, cover footer text, show footer, show page numbers, watermark, presets,
per-report-type defaults), migration `0111_branding.sql`, repository get/upsert storing only
`logoRef`/`coverRef` references, and `branding/uploads.ts` validating uploads by an explicit
allow-list of raster formats (PNG/JPEG/WebP) with a maximum byte size and dimension cap, rejecting
SVG and any script-bearing content, and storing the sanitized asset on the artifact tier. The
branding HTTP route and live preview are T-0724.

## Acceptance

- [ ] `BrandingConfig` round-trips through the repository; only asset references are stored, never blobs.
- [ ] Uploads outside the allowed formats or over the size/dimension limit are rejected with stable codes.
- [ ] An SVG or script-bearing upload is rejected and never stored.
- [ ] Migration `0111` applies, is re-runnable, and advances `SchemaVersion`.
- [ ] Tests cover the change and fail without them.
- [ ] No file outside `scope` is modified.
