# T-0927 — Run options chosen in the portal never reach the assessment

## Report

The walk's run was started with `{quickScan: false, skipPurview: true, redact: false,
evidence: true}`. The assessment log still shows "Connecting to Purview…". The worker's
`context.json` has no QuickScan, SkipPurview, Evidence or Redact.

## Cause

- `portal/bff/src/adapters/runs.ts:224-235` writes only `Scope.Sections` into the job context. The
  other options are dropped.
- `Invoke-WorkerAssessment` in `M365Portal.Workers.psm1` maps only `QuickScan` (around line 307)
  to `Invoke-M365Assessment` parameters. `SkipPurview`, `Evidence` and `Redact` are never mapped.

## Fix direction

- Carry every run option into the job context.
- Map each one in `Invoke-WorkerAssessment` to its `Invoke-M365Assessment` parameter.
- Reject unknown options at run creation, so new wizard options cannot be silently ignored.
- Record the options the assessment actually received in the run's provenance.

## Acceptance

- [x] With `skipPurview: true` set, the run does not connect to Purview.
- [x] `evidence` and `redact` change the output as they do on the CLI.
- [x] `context.json` and provenance show every option.
- [x] No file outside `scope` is modified.

## Fix

- `portal/bff/src/adapters/runs.ts`
  - `RUN_OPTION_KEYS` / `validateRunOptions` define the option set the wizard sends
    (`quickScan`, `skipPurview`, `redact`, `evidence`). Every value must be boolean;
    any other key throws an `AppError` `run.unknown_option` (400) and a non-boolean
    throws `run.invalid_options` (400). `createRun` / `createRunWithChildren` validate
    before persisting, so an unknown option is rejected at `POST /v1/runs` instead of
    being stored and silently ignored later.
  - `createRunQueue.enqueue` reads the persisted run's `options` and writes them into
    `context.json` as an `Options` block (`QuickScan`, `SkipPurview`, `Redact`,
    `Evidence`), plus `Scope.QuickScan` for the orchestrator's severity filter. The same
    set is merged into the run's `provenance.assessmentOptions`, recording what the
    worker actually received.
- `portal/workers/M365Portal.Workers/M365Portal.Workers.psm1`
  - `Read-WorkerRunContext` attaches the `Options` block from `context.json` as a note
    property; `RunContext.ps1` has no Options member, so this keeps the typed context
    intact.
  - `Invoke-WorkerAssessment` maps `QuickScan`, `SkipPurview`, `Redact` and
    `Evidence` (to `-EvidencePackage`) onto `Invoke-M365Assessment` switches. When
    `SkipPurview` is set the orchestrator removes the Purview collectors before it
    connects, so no Purview connection is attempted.
