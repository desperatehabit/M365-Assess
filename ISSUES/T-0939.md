# T-0939 — Small check-logic and label problems in Entra and CA findings

## Report

From the accuracy spot-check of the walk's run:

1. **ENTRA-SOD-001** fails unless there is at least one Privileged Role Administrator *and* at
   least 2 Global Admins (`Get-EntraSoDConfig.ps1:89`, `praCount -ge 1`). The Global Admin part
   duplicates ENTRA-ADMIN-001, and the recommended-value text does not mention the Privileged
   Role Administrator requirement.
2. **ENTRA-AUTHMETHOD-003** treats the Authenticator `default` state as *on* for number matching
   but *off* for app context (`EntraPasswordAuthChecks.ps1:436-437`). This may be a false Fail.
   Microsoft now enables both by default.
3. **ENTRA-TENANT-001**'s label reads "…Restricted", but CurrentValue shows `True`, which is the
   raw `allowedToCreateTenants`. The evidence reads as the opposite of the status. The status
   itself is correct.
4. **CA-DEVICE-002** is a Fail with severity `info`. Check its `risk-severity.json` entry.
5. `_PermissionDeficits.json` records `authMode: "Delegated"` for a certificate app-only run.

## Fix direction

1. Make ENTRA-SOD-001 test only separation of duties, and state the rule in the recommendation.
2. Treat `default` the same way for both settings.
3. Show the value in the label's terms ("Restricted: No").
4. Set a severity that fits a Fail.
5. Record the real auth mode.

## Fix

Five independent items, all fixed and individually tested:

1. **ENTRA-SOD-001** (`src/M365-Assess/Entra/Get-EntraSoDConfig.ps1`)
   - Pass criteria reduced to separation of duties only:
     `$praCount -ge 1 -and $overlapCount -eq 0`. The `Global Admins >= 2` clause was
     removed because ENTRA-ADMIN-001 owns it.
   - `RecommendedValue` now states the actual rule: "At least 1 Privileged Role Admin,
     no user holding both Global Admin and Privileged Role Admin" (also in the
     insufficient-permissions branch), and the synopsis/comment were corrected.
   - Test: `Get-EntraSoDConfig.Tests.ps1` adds a fixture with one Global Admin and a
     different single Privileged Role Admin asserting `Pass`, plus an assertion on the
     recommended-value wording.

2. **ENTRA-AUTHMETHOD-003** (`src/M365-Assess/Entra/EntraPasswordAuthChecks.ps1`)
   - `default` is now on for application context as well as number matching
     (`$appInfoOn = $appInfo -in @('enabled','default')`), so Microsoft-managed
     defaults no longer produce a false Fail. Explicit `disabled` still Fails.
   - Test: the existing `default states` fixture in
     `EntraPasswordAuthChecks.Tests.ps1` now sets both `numberMatchingRequiredState`
     and `displayAppInformationRequiredState` to `default` and asserts `Pass`
     (the explicit-disable Fail guard remains).

3. **ENTRA-TENANT-001** (`src/M365-Assess/Entra/EntraUserGroupChecks.ps1` is the emitter)
   - `CurrentValue` now shows the label's terms: `Restricted: No` when
     `allowedToCreateTenants` is true, `Restricted: Yes` when false. Status logic is
     unchanged.
   - Tests: `EntraUserGroupChecks.Tests.ps1` asserts `Restricted: Yes`/`Pass` for the
     restricted fixture and `Restricted: No`/`Warning` for the allowed fixture.

4. **CA-DEVICE-002** (`src/M365-Assess/controls/risk-severity.json`)
   - Severity changed `Info` -> `Medium`, so a Fail no longer carries an
     informational rating. CA-DEVICE-001 (managed device for all apps) remains High;
     registration-only device coverage has a smaller blast radius, so Medium fits.
   - Test: `Get-CASecurityConfig.Tests.ps1` asserts the no-policy run Fails and that
     the `risk-severity.json` entry is not `Info`.

5. **_PermissionDeficits.json auth mode** (`src/M365-Assess/Orchestrator/Test-GraphPermissions.ps1`)
   - App-only detection now also honours `$context.AuthType -eq 'AppOnly'`; certificate
     app-only connections that surface granted scopes no longer fall through to the
     delegated branch. The delegated branch records `AuthMode 'Delegated'`, the app-role
     validator records `'AppOnly'`.
   - Tests: `Write-PermissionDeficitsFile.Tests.ps1` adds a certificate app-only context
     (`AuthType = 'AppOnly'`, non-`.default` scopes) asserting `authMode = "AppOnly"`,
     plus a delegated control case asserting `"Delegated"`.
