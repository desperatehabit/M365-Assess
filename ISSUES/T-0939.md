# T-0939 — Small check-logic and label problems in Entra and CA findings

## Report

From the accuracy spot-check of the walk's run:

1. **ENTRA-SOD-001** fails unless there is at least one Privileged Role Administrator *and* at
   least 2 Global Admins (`Get-EntraSoDConfig.ps1:89`, `praCount -ge 1`). The Global Admin part
   duplicates ENTRA-ADMIN-001, and the recommended-value text does not mention the Privileged
   Role Administrator requirement.
2. **ENTRA-AUTHMETHOD-003** treats the Authenticator `default` state as *on* for number matching
   but *off* for app context (`EntraPasswordAuthChecks.ps1:436-437`). This may be a false Fail.
   Microsoft now enables both by default.
3. **ENTRA-TENANT-001**'s label reads "…Restricted", but CurrentValue shows `True`, which is the
   raw `allowedToCreateTenants`. The evidence reads as the opposite of the status. The status
   itself is correct.
4. **CA-DEVICE-002** is a Fail with severity `info`. Check its `risk-severity.json` entry.
5. `_PermissionDeficits.json` records `authMode: "Delegated"` for a certificate app-only run.

## Fix direction

1. Make ENTRA-SOD-001 test only separation of duties, and state the rule in the recommendation.
2. Treat `default` the same way for both settings.
3. Show the value in the label's terms ("Restricted: No").
4. Set a severity that fits a Fail.
5. Record the real auth mode.

## Acceptance

- [ ] Each of the five items is fixed and covered by a test.
- [ ] No file outside `scope` is modified.
