# T-0090 — Scheduled report generation and delivery hand-off

## Report

EPIC-005 SPEC.md §4.3: `Schedule` (EPIC-007) of type `report` fires, the job renders the report,
stores a `GeneratedReport`, and delivery uses EPIC-029 channels. §11.4 resolves delivery to
**reuse EPIC-029 only** (no report-specific email). §9 risk "render cost on a schedule" is
mitigated by per-report jobs and timeouts.

Deliver:

- `Invoke-ScheduledReport.ps1`: a worker handler for the `report` job type that resolves the
  schedule's template/tenant, calls the render path (T-0084), stores the `GeneratedReport`
  metadata (T-0083), and emits a delivery request to the EPIC-029 channel by contract.
- Idempotency so a retried job does not produce duplicate `GeneratedReport` rows.
- Pester tests with stubbed render/delivery asserting the stored record and the delivery request;
  a failing render marks the job failed without a partial record.

Note: the `Schedule` entity, cron tick, and queue are EPIC-007's scope (not yet authored); this
ticket implements only the `report` job handler and reads the schedule via the repository seam.

## Acceptance

- [ ] A fired `report` schedule produces one `GeneratedReport` with an artifact reference.
- [ ] Delivery is requested through the EPIC-029 channel contract, not a bespoke email.
- [ ] A retried job does not duplicate the generated report.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
