# T-0646 — Licence gate endpoint backed by licensing-overlay.json

## Report

EPIC-033 SPEC.md §3.5 requires every licence-gated feature to show a consistent **license
missing** state that explains the required plan rather than failing silently, and names the
module's `licensing-overlay.json` as the source. §6 exposes
`GET /v1/tenants/{id}/licenses/gates`. ADR-0004 keeps the licensing overlay separate from the
check registry; SPEC.md §9 says gating must be surfaced consistently.

Build the `Get-LicenseGates.ps1` worker job that reads the module's
`src/M365-Assess/controls/licensing-overlay.json` (the E3/E5 minimum plus exact service plan ids
per CheckID) and resolves it against the tenant's subscribed SKUs from T-0642, returning a
per-feature `available`/`gated` result with the required plan. The BFF route validates
RBAC/scope and returns the map so UI surfaces render the shared license-missing state. Extend
`portal.v1.yaml`. This ticket reads the module's overlay file; it does not edit `src/**`.

## Acceptance

- [ ] The endpoint resolves each overlay entry against subscribed SKUs and reports
      `available`/`gated` with the required plan.
- [ ] A feature whose minimum plan is absent returns `gated`, not an error.
- [ ] The overlay is read from the module path and never duplicated or mutated at runtime.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
