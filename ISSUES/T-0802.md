# T-0802 — GitHub integration adapter (opt-in for EPIC-039)

## Report

**PARKED / optional,** but this is the **first integration named for un-parking**: SPEC §11 open
question 1 is **resolved (adopted):** EPIC-041 stays parked until demand is confirmed, and the
first integration to un-park for is **GitHub**, because it is the opt-in dependency for
EPIC-039's save-to-GitHub flow (T-0767). Question 4 is **resolved (adopted):** GitHub is an
opt-in integration for EPIC-039, not a general-purpose connector.

EPIC-041 SPEC.md §3.1, §4, §6, §9: implement a GitHub adapter through the T-0801 registry:
`PUT /v1/integrations/github` config, `POST …/test`, and a commit operation used by EPIC-039.
Credentials (PAT or app token) are stored **by reference** only; the adapter requests the
minimum scope (repo contents write) and audits each commit. Auth/conflict failures return
structured errors; the adapter is disabled unless explicitly enabled.

## Acceptance

- [ ] The GitHub adapter registers with T-0801 and exposes config, test, and commit operations.
- [ ] Credentials are stored by reference; no token appears in logs, errors, or audit payloads.
- [ ] A commit writes the template file and records the commit ref in the audit log.
- [ ] Auth/conflict failures return structured errors; the adapter is a no-op until enabled.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
