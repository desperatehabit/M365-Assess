# T-0701 — Pack catalog derived from module framework JSONs and shared scoring

## Report

EPIC-036 SPEC.md §1 and §5 require packs (`CIS`, `CISA`, `ORCA`, `E8`, …) derived from the
module's existing framework mappings rather than duplicated check logic; §9 names overlap with the
existing 15 framework JSONs as a risk. §11.1 resolves the v1 pack set to **CIS + Essential Eight
first**, §11.2 resolves the relationship as **derive from the framework files**, and §11.3
resolves scoring to **per-pack scores with one shared normalization**.

Deliver `catalog.ts`: load the module framework JSONs in `src/M365-Assess/controls/frameworks/`
plus the check registry, build a `TestPack` view (`{ id, name, description, frameworkId, checkIds }`)
without redefining any check, and expose the catalogue. Deliver `scoring.ts`: the single shared
normalization (pass/fail counts → score) that every pack uses. Reading module data is fine; no
module file is modified and no check logic is copied into the BFF.

## Acceptance

- [ ] The catalogue exposes the CIS and E8 packs with check counts equal to their framework mappings.
- [ ] No check definition is duplicated; the catalogue references framework/check ids only.
- [ ] `scoring.ts` normalizes results identically for two packs with different check totals.
- [ ] Tests cover the catalogue and the shared scoring and fail without them.
- [ ] No file outside `scope` is modified.
