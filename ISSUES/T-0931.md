# T-0931 — Portal summary counts drop Info findings, so the buckets don't add up to the total

## Report

The DB `summaryCounts` for the walk's run is pass 47, fail 46, warning 26, review 33, info 15,
skipped 0, total 167. The run summary the BFF serves adds up to **152** against `total: 167`,
because the 15 Info findings are not represented.

## Cause

- `SummaryCounts` and `normalizeSummaryCounts` in `portal/bff/src/routes/runs-detail.ts:28-51`
  have no `info` field. The parent-run aggregation (around line 225) inherits the omission.
- The JSON bridge's `domainSummary` also has no info bucket, although its totals include Info.

## Fix direction

- Add `info` to `SummaryCounts`, the normaliser, the parent rollup and the web summary cards.
- Add a check, in a test, that the buckets sum to `total`.

## Acceptance

- [x] The run summary shows Info, and the buckets sum to the total for the walk's run.
- [x] Parent-run rollups include Info.
- [x] No file outside `scope` is modified.

## Fix

- `portal/bff/src/routes/runs-detail.ts` — `SummaryCounts` and `normalizeSummaryCounts`
  carry `info`; the fallback `total` now sums pass + fail + warning + review + info +
  skipped + notLicensed; the parent aggregation in `GET /v1/runs/{runId}` adds each
  child's `info` bucket. Walk run 1e05ddc5 (47/46/26/33/15/0, total 167) now reports all
  167 across the buckets instead of 152.
- `portal/web/src/components/RunDetailTabs.tsx` — `RunSummaryCounts.info` (optional, for
  older payloads) and a seventh KPI card, `kpi-info`, in the Summary strip.
- `portal/web/src/components/RunsTable.tsx` — no findings change: the list row shows
  pass/fail only by design; the file is touched for the T-0929 partial badge (warn
  tokens).
