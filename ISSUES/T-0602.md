# T-0602 — Secure score read worker and current-score API

## Report

EPIC-031 SPEC.md §2 US-1 and §4.1 define the score read: read Secure Score + improvement actions
from Graph, aggregate categories, and match actions to registry checks. §6 fixes
`GET /v1/tenants/{id}/secure-score`; §7 lists Graph `SecurityEvents.Read.All`; §8 states Secure
Score is **read-only**. The module already reads Secure Score (`Get-SecureScoreReport`,
`Get-DefenderSecureMonConfig`).

Following ADR-0014, add a read-only `Get-SecureScore.ps1` job handler + `get-secure-score.ps1`
entrypoint that returns the result envelope (current, max, percentage, category split, and the
improvement-action list), and the BFF route behind RBAC `secure-score.read` + tenant scope. The
action→check mapping is produced by T-0603; this ticket returns actions unmapped if that mapping is
absent.

## Acceptance

- [ ] `GET /v1/tenants/{id}/secure-score` returns current, max, percentage, and category split.
- [ ] Improvement actions are returned with points achieved/available and impact.
- [ ] The worker is read-only and performs no tenant writes.
- [ ] A caller without `secure-score.read` receives a structured error.
- [ ] A test covers the read and fails without the code.
- [ ] No file outside `scope` is modified.
