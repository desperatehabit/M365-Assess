# T-0521 — Sharing links report worker and API

## Report

EPIC-027 SPEC.md §2 US-1, §3.1, §4.1, and §6 define the sharing report: Site/OneDrive · Item ·
Link type (anonymous/organization/people) · Permissions (view/edit) · Created by · Created ·
Expires, with filters by link type, permissions, site, created date, and anonymous-only. §6
exposes `GET /v1/tenants/{id}/sharing/report`; data is read live from Graph/SPO per §4.1 and §7
(`Sites.ReadWrite.All`). §11 item 1 is resolved (adopted): reports read **live first**; the
optional cache is added only when measured latency demands it.

Deliver a `Get-SharingReport.ps1` handler (entrypoint `get-sharing-report.ps1`) that enumerates
sharing links across sites/OneDrive (using the site list from T-0482) and returns a
`ResultEnvelope`, plus the read route validating `sharing.read` and tenant scope with cursor
pagination and the §3.1 filters. Filtering (including anonymous-only) is pushed to the worker.
Extend `portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/sharing/report` returns the §3.1 columns, filtered and paginated.
- [ ] The anonymous-only filter is honored; results are tenant-scoped.
- [ ] A caller without `sharing.read` is refused; the BFF performs no Graph/SPO call directly.
- [ ] A test covers listing and the anonymous-only filter and fails without it.
- [ ] No file outside `scope` is modified.
