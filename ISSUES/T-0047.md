# T-0047 — Cancel and retry API

## Report

EPIC-003 SPEC.md §4.3 defines cancel: a queued job is removed from the queue; a running job is
signalled so the worker terminates the child process tree and marks the run `cancelled`, with
partial artifacts retained. §4.4 defines retry: re-enqueue only the failed tenants (or failed
sections), producing a new run linked to the original via `Run.parentRunId`. §6 defines
`POST /v1/runs/{runId}/cancel` and `POST /v1/runs/{runId}/retry`; §7 adds `runs.retry`.

Deliver the cancel/retry routes and a `run-retry.ts` that selects failed children/sections,
creates a new run under the original parent, and enqueues only those jobs. Cancel reuses the
T-0010 supervisor's process-tree kill and T-0044 event stream.

## Acceptance

- [ ] Cancel stops queued and running jobs and marks the run `cancelled`; partial artifacts
      remain.
- [ ] Retry re-runs only failed tenants/sections and links the new run via `parentRunId`.
- [ ] Tests cover both paths and fail without the code.
- [ ] The OpenAPI document matches the implementation.
- [ ] No file outside `scope` is modified.
