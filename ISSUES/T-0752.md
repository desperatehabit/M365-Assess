# T-0752 — Portal Users page and nav/action permission filtering

## Report

EPIC-038 SPEC.md §3.1: page **Portal Users** with a table of display name, UPN, role, tenant
scope summary, status, last seen, and row actions `Edit`, `Assign role`, `Edit scope`,
`Disable`, `Remove`; `Add user` opens an `ActionDialog` (UPN, role, scope). SPEC.md §3.4 and
[`02-ui-design.md`](../../docs/portal-specs/00-guides/02-ui-design.md) §5.1: nav items and action
buttons carry permission attributes and a component hides itself when the caller lacks the
permission.

Build the `portal-users/page.tsx` + `PortalUsersTable` against the T-0744 API, and a reusable
`PermissionGate` component that reads the caller's effective permissions (`/v1/me`, falling back
to the `/v1/access/check` preflight from T-0750) and hides nav items/buttons it does not permit.
Use `PermissionGate` for the page's row actions and the nav entry; the same component is reused
by T-0753.

## Acceptance

- [ ] The table renders the §3.1 columns and row actions; `Add user` opens the dialog.
- [ ] `PermissionGate` hides its children when the permission is absent and shows them when present.
- [ ] Nav/action visibility reflects the caller's effective permissions, not a static list.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
