# T-0585 — Safe Links policy read and change API

## Report

EPIC-030 SPEC.md §2 US-5 and §3.5 define **Safe Links Policies** (Name · State · key settings —
URL rewriting, scan on click, detonation · Last modified) with row actions `View`, `Edit`,
`Enable/Disable`, `Clone to template`, `Delete`. §6 fixes `GET`/`POST`/`PATCH`/`DELETE
/v1/tenants/{id}/safelinks`. §11.1 is resolved to ship Safe Links in the **first wave**; §7 notes
Safe Links uses **EXO** auth (not Purview), so it runs in the per-tenant EXO process and does not
collide with the Purview session constraint.

Deliver an EXO read worker + entrypoint and the BFF read + change routes behind
`purview.read`/`purview.write`. Changes go through the EPIC-006 gated path (T-0108); disable/delete
is compliance-impacting and records `CompliancePolicyChange` (T-0581).

## Acceptance

- [ ] `GET /v1/tenants/{id}/safelinks` returns the §3.5 columns, paginated and tenant-scoped.
- [ ] Create/edit/enable/disable/delete apply only through the EPIC-006 gated path.
- [ ] Safe Links reads use the EXO connection and never share a session across tenants.
- [ ] Disabling a policy warns before apply and records an audit + change row.
- [ ] A test covers read and change gating and fails without the code.
- [ ] No file outside `scope` is modified.
