# T-0743 — Test-PortalAccess include/exclude resolution

## Report

EPIC-038 SPEC.md §4.1: `Test-PortalAccess` resolves a caller's effective permission. A portal
user's actor uses their assigned role(s); an API client uses the client's role(s). Base and
custom roles resolve via wildcard **include/exclude** patterns (the `cipp-roles.json` model): a
permission is granted if it matches an include and no exclude. `Public` bypasses; a deny returns
a structured `403` with a stable `code` and is audited.

Build `test-portal-access.ts` on top of the T-0741 base roles and T-0742 registry. Resolve
wildcards with an explicit, anchored matcher (no glob injection), evaluate include-then-exclude,
and return `{allowed, code, matchedRole(s)}`. It must be reusable from both the HTTP middleware
and the UI preflight (`POST /v1/access/check`, T-0750). Test the full §4.1 base-role table,
including that `editor` cannot call `Remediation.Apply` while `admin` can.

## Acceptance

- [ ] Base-role include/exclude resolution matches the SPEC §4.1 table; a test asserts each row.
- [ ] `editor` is denied `Remediation.Apply`; `admin` is allowed.
- [ ] A permission with no matching include, or a matching exclude, is denied with a stable code.
- [ ] `Public` is allowed without a role.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
