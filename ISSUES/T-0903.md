# T-0903 — Implement the cleanup system timer

## Report

T-0876 found that the `cleanup` system timer (`portal/bff/src/scheduler/system-timers.ts`)
names `Invoke-PortalCleanup`, which no worker or runner implements. It used to be enqueued as a
`backup` job that no runner could execute, so every tick threw 501. T-0876 marked it
`unavailableReason`, so it is now listed as disabled and skipped.

Decide what cleanup covers (expired artifacts under the storage root, finished job rows past retention, soft-deleted records), write that down in EPIC-007 SPEC §4.1, and implement it. This needs a product decision on retention periods before code.

Then remove `unavailableReason` from the timer so the tick runs it again.

## Acceptance

- [x] The behaviour described in the report is implemented and the timer runs on its cron.
- [x] A test covers the timer's run and fails without the fix.
- [x] No file outside `scope` is modified.

## Fix

Decided and documented in EPIC-007 SPEC §4.1 (operational timers): cleanup removes artifact
folders under the artifact root (default 90 days), terminal `done`/`failed` job rows
(default 30 days), and soft-deleted `scheduled_tasks` rows (default 30 days). Each window is
configurable through `M365_BFF_CLEANUP_*_RETENTION_DAYS`; a missing or non-positive value is
a startup error. `createCleanupCommand` writes `cleanup.json` into the job's output folder;
`createCleanupPorts` performs the filesystem and SQLite deletes.

The timer runs daily at 03:00 UTC through the `maintenance` job type and the persisted
`system_timer_state` next-run (migration 0127), so it no longer fires on every tick.
