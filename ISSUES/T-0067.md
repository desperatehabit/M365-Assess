# T-0067 — Tenant switcher and per-tenant view preference

## Report

`99-reference/cipp-ui-patterns.md` §1 describes the core tenant-selection UX: a header selector
that persists the current tenant and drives every tenant-scoped call, plus a multi-select form
control for tenant/group targeting. `02-ui-design.md` §7.4 requires per-tenant view state
persistence under `<key>-<tenantId>`, and the `TenantSelector` / `TenantMultiSelect` components
are named in §6.

Deliver:

- `TenantSelector` (header) with current-tenant persistence and a recent/favorite list.
- `TenantMultiSelect` (forms) with `{label, value, type}` options for tenant/group/global.
- `portal/web/src/lib/tenant-preference.ts` storing the selection per user (mirrored to
  `localStorage` for first paint, per `02-ui-design.md` §2).
- Component tests for selection persistence and scope-driven option filtering.

Note: the tenant list endpoint belongs to EPIC-002 (tenants/onboarding), which is not yet
authored; this ticket consumes the tenants API by contract and stubs it in tests.

## Acceptance

- [ ] Selecting a tenant persists across reloads and drives tenant-scoped requests.
- [ ] The multi-select emits tenant/group/global typed options and honours RBAC scope.
- [ ] Options are limited to tenants in the caller's scope.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
