# T-0907 — Fix pre-existing PowerShell lint findings in Invoke-DomainAction and Linux-only tests

## Report

Two pre-existing `PSScriptAnalyzer` issues remain across PowerShell sources:

1. `portal/workers/M365Portal.Workers/Invoke-DomainAction.ps1` uses `$Error` as a parameter name and exports `Verify-Domain` (unapproved verb; cannot be renamed silently because `tests/Portal/Workers/Invoke-DomainAction.Tests.ps1` asserts `Get-Command Verify-Domain` and invokes it directly).
2. Linux-only Pester tests use `ps` aliases instead of full `Get-Process` / native invocation conventions per `.claude/rules/powershell.md`.

## Fix direction

Update `Invoke-DomainAction.ps1`, module exports (if applicable), and `tests/Portal/Workers/Invoke-DomainAction.Tests.ps1` in lockstep (e.g., rename `$Error` parameter to `$ErrorMessage` / `$ErrorDetail`, replace `Verify-Domain` with `Confirm-Domain` or `Test-DomainVerification` and update tests/callers), and eliminate `ps` alias lint findings in Linux-only tests.

## Acceptance

- [ ] `Invoke-DomainAction.ps1` has zero `PSScriptAnalyzer` automatic-variable or unapproved-verb warnings.
- [ ] `tests/Portal/Workers/Invoke-DomainAction.Tests.ps1` and module exports remain green with updated function/parameter names.
- [ ] Linux-only tests pass `PSScriptAnalyzer` alias checks.
- [ ] No file outside `scope` is modified.
