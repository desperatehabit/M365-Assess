# T-0569 — Custom alert builder and Notification settings UI

## Report

EPIC-029 SPEC.md §3.2 defines the **custom alert builder** as cards: Tenant selector → Alert
criteria → Notification settings, with preset autocomplete, dynamic condition rows
(Property / Operator / Input, add/remove), and actions (channels, custom subject, alert comment) or
**script mode**. §3.4 defines the **Notifications** settings page (email recipients, webhook URLs,
PSA, Slack) with per-channel enablement and test-send. Nav: *CIPP → Application Settings →
Notifications* per [`cipp-ui-inventory.md`](../../docs/portal-specs/99-reference/cipp-ui-inventory.md) §3.

Deliver the builder page against the T-0563 criteria contract and T-0562 rule API, surfacing script
mode with the high-privilege/admin-gate warning (execution is sandboxed in T-0564), and the
Notifications page against the T-0566 config/test-send API. Theme per
[`02-ui-design.md`](../../docs/portal-specs/00-guides/02-ui-design.md). No new server logic.

## Acceptance

- [ ] The builder composes tenant + criteria rows + notification actions and saves a working rule.
- [ ] Add/remove condition rows validate operators via the shared contract and reject invalid input.
- [ ] Script mode renders the high-privilege warning and is disabled for non-admin callers.
- [ ] The Notifications page edits channel config and triggers a test-send, showing the result.
- [ ] A test covers builder save and channel config and fails without it.
- [ ] No file outside `scope` is modified.
