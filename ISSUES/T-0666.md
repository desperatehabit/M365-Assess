# T-0666 — Actionable DNS recommendations

## Report

EPIC-034 SPEC.md §3.3 requires actionable items (e.g. "DMARC policy is `none`", "SPF exceeds 10
lookups") each with a remediation link (portal instructions or automated where safe); §4.2 step 2
produces the health and recommendations. Resolved §11.2 confirms **recommend-only** for v1: DNS
changes are never auto-applied. The module already emits DNS checks with CheckIDs, so a
recommendation maps to the matching check and its EPIC-006 remediation.

Build the `Get-DnsRecommendations.ps1` worker job that turns an analysed record set into a
ranked recommendation list (record family, severity, plain-language explanation, and a
remediation link), and the BFF route that serves recommendations for a domain, mapping to the
module's DNS check ids where one exists and to a portal instruction otherwise. Extend
`portal.v1.yaml`. No DNS record is written.

## Acceptance

- [ ] A domain with a `none` DMARC policy or an over-limit SPF yields a recommendation with an
      explanation and a working remediation link.
- [ ] Recommendations map to the module's DNS CheckIDs where one exists; the route exposes no
      write action.
- [ ] A clean domain yields no recommendations (not an error).
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
