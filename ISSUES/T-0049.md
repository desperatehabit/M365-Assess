# T-0049 — Runs list and history UI

## Report

EPIC-003 SPEC.md §3.1 defines the **Runs** page: a `DataTable` with run ID (mono), tenant(s),
trigger, sections, status `status-badge` (queued/running/succeeded/failed/cancelled/partial),
progress bar (`--bar-glow`), findings counts, started, and duration; filters by
status/trigger/tenant/date range/section; row actions `View`, `Cancel`, `Retry failed`,
`Download artifacts`, `Compare to previous` (hands to EPIC-010 drift); and a card view for
mobile. §4.6 requires history with the storage retention policy. All components use report
theme tokens (`02-ui-design.md` §5.1) with no colour literals (`05-programming.md` §4).

Deliver the runs list route and `RunsTable` wired to the T-0042 list API, including the
`Compare to previous` hand-off link. The tenants/groups picker is owned by EPIC-002 and is
consumed here in prose, not re-implemented.

## Acceptance

- [ ] The table renders every §3.1 column, supports the named filters, and exposes the row
      actions.
- [ ] Cancel/Retry/Download actions are wired (or disabled) by run status.
- [ ] A test covers the table states and fails without it; only theme tokens are used.
- [ ] No file outside `scope` is modified.
