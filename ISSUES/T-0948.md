# T-0948 — SOC2 Graph failures report the request URL but not the HTTP status or reason

## Report

Four SOC2 issues on run `b4d11871-d1c2-4857-8b91-b7c79282af21` read only, for example:

> S-07: Failed to check Defender alerts: GET https://graph.microsoft.com/v1.0/security/alerts_v2?$top=10

- The catch blocks interpolate the whole error record: `Write-Warning "S-07: ... $_"`
  (`Get-SOC2SecurityControls.ps1` lines 387 and 429; `Get-SOC2AuditEvidence.ps1` lines 156
  and 195).
- An `Invoke-MgGraphRequest` error renders as several lines: the request line first, then the
  HTTP status and the JSON error body. The issue log keeps the first line, so the status
  (`403 Forbidden`) and Graph's error code are lost.
- The same text goes into the control's `CurrentValue` (`"Error: $_"`).

The underlying failures are missing `SecurityAlert.Read.All` / `IdentityRiskEvent.Read.All`
app roles (PR #26 adds them to the SOC2 permission map).

## Fix direction

- Format Graph errors once: HTTP status, Graph error `code`, and `message` from the response
  body, then the request. A small shared helper suits every collector that calls
  `Invoke-MgGraphRequest`.
- Use it in the four SOC2 catch blocks and in the `CurrentValue` text.
- Name the missing permission when the status is 403 (`SecurityAlert.Read.All` for `alerts_v2`,
  `IdentityRiskEvent.Read.All` for `riskDetections`).

## Acceptance

- [ ] A 403 from `alerts_v2` produces an issue that names the status and the missing permission.
- [ ] Tests cover a multi-line Graph error record, and fail without the change.
