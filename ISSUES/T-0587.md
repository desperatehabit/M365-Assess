# T-0587 — Sensitivity labels and SITs API with second-reviewer encryption gate

## Report

EPIC-030 SPEC.md §2 US-3 and US-4, §3.3, and §3.4 define **Sensitivity Labels** (Name · Scope ·
Priority · Encryption · Marking · State, with publish/`Clone to template` and publishing-policy
management) and **Sensitive Info Types** (Name · Type · Pattern confidence · Based on). §4.3 says
label creation and publishing-policy assignment are separate steps. §6 fixes `GET`/`POST`/`PATCH`/
`DELETE /v1/tenants/{id}/purview/labels` and `.../sits`. §11.1 places labels/SITs in the second
wave (after DLP/retention/Safe Links), and §11.2 is resolved to require a **mandatory second
reviewer** for label-encryption changes.

Deliver a read worker over the T-0582 Purview session seam plus the labels and SITs read/change
routes. `label-encryption-review.ts` blocks any change that alters encryption settings until a
second, distinct reviewer approves, and records the approval on the resulting
`CompliancePolicyChange` (T-0581). Publishing-policy assignment is a separate operation from label
creation. All writes route through the EPIC-006 gated path (T-0108).

## Acceptance

- [ ] Labels and SITs list/detail return the §3.3/§3.4 columns, paginated and tenant-scoped.
- [ ] Creating a label and assigning a publishing policy are separate operations.
- [ ] An encryption-setting change is refused until a distinct second reviewer approves.
- [ ] All applied writes go through T-0108 and record an audit + change row.
- [ ] A test covers the encryption gate and fail-without behaviour.
- [ ] No file outside `scope` is modified.
