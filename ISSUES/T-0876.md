# T-0876 — Custom-script schedules and system timers enqueue job types with no runner

## Report

- Scheduling a custom script (SPEC §4.2, §6 US-6) is impossible: the schedule schema accepts
  `custom-script` (`portal/contracts/src/schedules.ts:12`) but create/update rejects it with 501
  because `runnableJobTypes` is derived from `workerRunners` (`portal/bff/src/adapters/automation.ts:531-538`;
  `portal/bff/src/app.ts:537-559,610`) and no runner is registered for `custom-script`.
- The `cleanup` system timer is typed `backup` and names `Invoke-PortalCleanup`
  (`portal/bff/src/scheduler/system-timers.ts:44-63`), but `backup` has no runner, so the scheduler
  tick's enqueue throws 501 on every tick (`portal/bff/src/scheduler/tick.ts:192`,
  `adapters/automation.ts:455-459`) and the timer never runs. The `webhooks` and `token-refresh`
  timers are likewise typed `report`/`assessment` and carry envelopes their runners do not understand.
- `DELETE /v1/scripts/:id` 501 is tracked separately in T-0873.

## Acceptance

- [ ] A `custom-script` schedule can be created, stored, and run by the scheduler.
- [ ] Each system timer's job type has a registered runner or is corrected to an existing type.
- [ ] The scheduler no longer throws on its tick for these timers.
- [ ] A test covers a custom-script schedule run and each corrected timer.
- [ ] No file outside `scope` is modified.
