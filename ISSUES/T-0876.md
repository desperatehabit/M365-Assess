# T-0876 — Custom-script schedules and system timers enqueue job types with no runner

## Report

- Scheduling a custom script (SPEC §4.2, §6 US-6) is impossible: the schedule schema accepts
  `custom-script` (`portal/contracts/src/schedules.ts:12`) but create/update rejects it with 501
  because `runnableJobTypes` is derived from `workerRunners` (`portal/bff/src/adapters/automation.ts:531-538`;
  `portal/bff/src/app.ts:537-559,610`) and no runner is registered for `custom-script`.
- The `cleanup` system timer is typed `backup` and names `Invoke-PortalCleanup`
  (`portal/bff/src/scheduler/system-timers.ts:44-63`), but `backup` has no runner, so the scheduler
  tick's enqueue throws 501 on every tick (`portal/bff/src/scheduler/tick.ts:192`,
  `adapters/automation.ts:455-459`) and the timer never runs. The `webhooks` and `token-refresh`
  timers are likewise typed `report`/`assessment` and carry envelopes their runners do not understand.
- `DELETE /v1/scripts/:id` 501 is tracked separately in T-0873.

## Acceptance

- [ ] A `custom-script` schedule can be created, stored, and run by the scheduler.
- [ ] Each system timer's job type has a registered runner or is corrected to an existing type.
- [ ] The scheduler no longer throws on its tick for these timers.
- [ ] A test covers a custom-script schedule run and each corrected timer.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `custom-script` is now a `JobType` (`portal/contracts/src/envelope.ts`) with a registered
  runner (`createCustomScriptRunner` in `adapters/automation.ts`). The runner loads the
  schedule the job came from (by its `schedules/<id>/` outputRef) and dispatches on the
  schedule's `command`. `Invoke-CustomScript` runs `parameters.scriptId` at its current
  version through the T-0126 sandbox, for real, once per target tenant, audits each run as
  `scripts.run`, and writes `custom-script-results.json` to the job's output folder. A
  command with no handler (for example `Invoke-VacationSchedule`, T-0894) fails the job
  instead of succeeding silently, so T-0894 can register its handler in the same map.
- Saving a custom-script schedule that names a missing or disabled script, or one with no
  current version, is rejected with 422 (`schedule.custom_script_invalid`).
- The `webhooks`, `cleanup`, and `token-refresh` timers had no implementation anywhere:
  their commands exist in no worker and no runner dispatches on command. They are now
  marked `unavailableReason` in `system-timers.ts`, listed as disabled by
  `/v1/schedules/system`, skipped by the tick (no 501 on every tick), and their commands
  are no longer accepted for user tasks. Implementations are tracked in T-0902 (webhook
  renewal), T-0903 (cleanup), and T-0904 (token refresh).
