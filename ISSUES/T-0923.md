# T-0923 — Report builder has no styling, few block types and no ready-made components

## Report

The Report builder is not built out and looks unfinished: no styling, a thin set of block types,
and no predefined components.

## Current state

- **Styling:** `reports/builder/page.tsx` uses a few inline `style={{...}}` props (background,
  text colour, padding). Nothing in `portal.css` targets the builder, so the canvas, block list
  and settings rail render as mostly unstyled HTML.
- **Block types:** `V1_BLOCK_TYPES` in `BlockCanvas.tsx` has six types: `chart`, `score-cards`,
  `progress-bars`, `section-divider`, `page-break` and `rich-text`. None of them is tied to
  assessment data such as findings, framework coverage, secure score or remediation status.
- **Predefined components:** there are no starter report templates or ready-made sections.
  `/v1/report-templates` exists, but nothing seeds it.

## Fix direction

- Give the builder a real layout: a block palette on the left, a page-like canvas in the middle,
  the settings rail on the right, and drag to reorder, all using the report theme tokens.
- Add data-bound blocks: findings table (filterable by status, severity or section), framework
  coverage, secure score trend, top risks, remediation progress, tenant summary, and run
  comparison or drift summary.
- Seed built-in templates: *Executive summary*, *Technical findings*, *Compliance (per
  framework)* and *Remediation plan*.
- Show a live preview against a selected run (`PdfPreviewDialog` already exists).

## Acceptance

- [x] The builder has a styled palette, canvas and settings layout in light and dark themes.
- [x] At least the data-bound blocks above can be added and render real run data.
- [x] At least two built-in report templates can be picked as a starting point.
- [x] No file outside `scope` is modified.

## Fix

### Builder layout and styling

- `portal/web/src/app/reports/builder/page.tsx` now renders a three-column layout: block
  palette left, page-like `.report-page` canvas centre, settings rail right. The header holds
  template name, starter-template picker, live-run picker and the save/download/preview actions.
- `portal.css` adds the full `.report-*` stylesheet using only report theme tokens
  (`--bg`, `--bg-elev`, `--surface`, `--accent`, `--success`, `--danger`, `--radius`, …), so
  all light, dark and high-contrast themes are covered without a second stylesheet.
- Palette buttons add a block directly; the existing block-type select + Add block stay for
  keyboard and test compatibility.
- Blocks can be reordered by drag-and-drop (`dragstart`/`drop`) and by keyboard:
  `Alt+ArrowUp`/`Alt+ArrowDown` on a focused block, plus the existing Move up/Move down
  controls. `moveBlockToIndex` is shared by drag and the control buttons.
- `BlockControls` and `ReportSettingsRail` switched from inline style objects to the new
  classes while preserving every test id and accessible label.

### Data-bound block types

Added to `portal/contracts/src/reports.ts` and mirrored in `BLOCK_TYPES` / the builder:

| Type | Binding | Filters / settings |
| --- | --- | --- |
| `findings-table` | `findings` | `statuses`, `severities`, `sections`, `limit` |
| `framework-coverage` | `compliance` | `frameworks`, `showGaps` |
| `secure-score-trend` | `secure-score` | `points`, `includeTarget` |
| `top-risks` | `findings` | `limit`, `minSeverity` |
| `remediation-progress` | `findings` | `groupBy` (status/severity/section), `showPercentages` |
| `tenant-summary` | `run-summary` | `fields` |
| `run-comparison` | `run-summary` | `baselineRunId`, `mode` (comparison/drift), `showUnchanged` |

- Contract parse validation covers each setting with typed helpers; empty/unknown values are
  rejected while every optional filter may be omitted.
- Backward compatibility: the new types are appended to `BLOCK_TYPES`, so stored v1 documents
  containing only the original six types still parse (covered by a test).
- `BlockCanvas` renders a run-data preview for every new type: filtered findings table,
  coverage bars, secure-score percentage, top risks, remediation counts, tenant facts and
  run-to-run deltas. Without a run it shows a block-specific placeholder.
- `portal/bff/src/domain/reports/html.ts` renders the same blocks in server HTML. It accepts
  run data from `composeBuilderHtml(document, runData)`, from `composeReportHtml`'s
  `runData`/`data`, from `document.data`, or from a captured `settings.data`/`settings.snapshot`
  snapshot. Output is escaped and each block falls back to a placeholder when data is absent.
- The builder adds its live run data to the preview/download document only; saved templates
  never embed tenant data.

### Built-in templates

- `portal/bff/src/routes/report-templates.ts` exposes four built-ins:
  *Executive summary*, *Technical findings*, *Compliance (per framework)* and
  *Remediation plan*. They are global records merged into list/get, marked `readOnly: true`,
  and cannot be updated or deleted (409 `report_template.read_only`).
- No seed path or migration already existed. They live in the route module rather than the
  SQLite store because `app.ts` wires the repository directly and this keeps the built-ins
  immutable without a migration; cloning or saving a built-in writes a normal editable record.
- The builder loads them through the existing `/v1/report-templates` API on demand and treats
  one as a starting point (clears `templateId`, so Save creates a copy).

### Live preview

- The header's "Preview against a run" button loads `/v1/runs`, selecting one fetches
  `/v1/runs/{runId}/results`, and the findings feed the canvas blocks immediately. The resolved
  run is also attached to the preview/download render payload, so the server HTML has the same
  values.
