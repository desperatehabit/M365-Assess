# T-0801 — Integration framework and config store

## Report

**PARKED / optional.** EPIC-041 is deferred behind EPIC-038 and stays parked until there is
confirmed demand for a named integration (see the SPEC §11 resolution: the first un-park target
is GitHub, T-0802). This ticket is authored so the seam exists, not because it is scheduled.

EPIC-041 SPEC.md §4, §5, §6, §9: one `IntegrationConfig` (`id`, `kind`, `enabled`, `secretRef`,
`mapping`) store behind the common `GET`/`PUT /v1/integrations/{kind}`, `POST …/test`, `POST
…/sync` surface, with a vendor-adapter interface so per-vendor auth complexity is isolated
(§9 risk). Add migration `0130_integrations.sql`, `integration-repository.ts` (extending T-0009),
and `integration-registry.ts` mapping a `kind` to an adapter and its test/sync handlers. Secrets
are stored **by reference only** (`secretRef`); config changes require `integrations.manage` and
are audited. A registered adapter is exercised through the registry without this ticket adding a
vendor.

## Acceptance

- [ ] Migration `0130_integrations.sql` is forward-only and creates `IntegrationConfig` with `secretRef` and `mapping`.
- [ ] The registry resolves a `kind` to an adapter and returns a structured error for an unknown kind.
- [ ] No secret value is stored or logged; only `secretRef` is persisted.
- [ ] Config changes require `integrations.manage` and are audited.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
