# T-0803 — SIEM export (webhook-first)

## Report

**PARKED / optional.** EPIC-041 is deferred behind EPIC-038.

EPIC-041 SPEC.md §3.2, §4, §5, §6: configure a SIEM destination and which events to export, test
delivery, and stream `AuditEvent`/`AlertEvent` to it. §11 open question 2 is **resolved
(adopted): webhook first, syslog/vendor APIs later.** Build a webhook-only exporter this ticket;
syslog and vendor APIs are later follow-ons.

Add migration `0131_siem_destinations.sql` (`SiemDestination`: `id`, `url`, `events[]`,
`enabled`) and `siem-exporter.ts` posting events with retry/backoff and per-destination delivery
status. The `GET`/`PUT /v1/siem` config requires admin and is audited; the destination URL may
carry a secret placed in the stored-by-reference secret store, never in plain config. Export
failures alert and do not drop the source event.

## Acceptance

- [ ] `GET`/`PUT /v1/siem` persist a webhook destination and its event selection; changes require admin and are audited.
- [ ] The exporter posts events with retry/backoff and records delivery status.
- [ ] A destination secret is stored by reference; no secret is written to logs or the DB.
- [ ] The SIEM page renders config, an event picker, and a test-delivery action.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
