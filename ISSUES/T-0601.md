# T-0601 — Secure score snapshot and action-mapping storage

## Report

EPIC-031 SPEC.md §5 defines `SecureScoreSnapshot` (`id`, `tenantId`, `at`, `current`, `max`,
`percentage`, `categories`) as the trend source and `ScoreActionMapping` (`actionId`, `checkId`,
`standardKey`) as the action→remediation mapping; §4.2 says retention applies per
[`03-database.md`](../../docs/portal-specs/00-guides/03-database.md) §7. §5 also routes mapping
changes through the `AuditEvent` shape.

Deliver migration `0052_secure_score.sql` (numbered, forward-only, advancing `SchemaVersion`), a
repository for snapshots + mappings with retention pruning, and the shared contract types in
`portal/contracts/src/secure-score.ts`. `tenantId` references the EPIC-002 tenant table (data
dependency, prose only). No route or UI code belongs here.

- [ ] The repository round-trips the §5 snapshot and mapping fields and queries snapshots by tenant/time.
- [ ] Snapshot retention pruning follows the configured window per `03-database.md` §7.
- [ ] A mapping change writes an audit event.
