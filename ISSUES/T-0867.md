# T-0867 — Mount EPIC-037 Settings, Branding & Preferences routes

## Report

The EPIC-037 factories (`createSettingsRoutes` at `portal/bff/src/routes/settings.ts:267`,
`createBrandingRoutes` at `branding.ts:218`, `createFeatureFlagRoutes` at `feature-flags.ts:126`,
`createPreferencesRoutes` at `preferences.ts:114`, `createLogbookRoutes` at `logbook.ts:240`,
`createDiagnosticsRoutes` at `diagnostics.ts:142`) exist and are tested, but
`portal/bff/src/app.ts` imports none of them and there are no adapters bridging the repositories in
`portal/db/src/` to the route stores, so the endpoints 404. `diagnostics.ts` also replaces the
EPIC-001 stub with the full `GET /v1/diagnostics` report, but it is not mounted.

Pages exist (`app/settings`, `app/settings/branding`, `app/settings/features`,
`app/settings/notifications`, `app/preferences`, `app/advanced/diagnostics`, `app/logbook`); only
`/diagnostics` is linked in the nav.

## Acceptance

- [ ] Every EPIC-037 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [ ] Settings, branding, feature flags, preferences, logbook, and diagnostics persist and serve live data.
- [ ] `GET /v1/diagnostics` returns the full report rather than 404.
- [ ] No file outside `scope` is modified.
