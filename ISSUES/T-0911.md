# T-0911 — GDAP page always shows "disabled" because it probes a route that does not exist

## Report

`portal/web/src/app/gdap/page.tsx` (line ~94) decides whether GDAP is enabled by calling
`GET /v1/gdap/relationships` and treating 404 as "disabled". `routes/gdap.ts` defines only
`POST /v1/gdap/sync` (`GDAP_SYNC_PATH`). With `M365_BFF_GDAP_PARTNER_TENANT_ID` set, sync is
mounted but the relationships route still is not, so the page always shows GDAP as disabled
and the Sync button is never reachable. The relationship store
(`createGdapRelationshipStore`) is already passed to `createGdapRoutes`.

## Fix direction

Add `GET /v1/gdap/relationships` (list from the relationship store), mounted with the same
`enabled` gate as sync, so 404 keeps meaning "GDAP not configured".

## Acceptance

- [ ] With a partner tenant configured, the GDAP page lists relationships and Sync works.
- [ ] Without one, the page still shows the "not configured" state.
- [ ] A route test covers the list in both states.
- [ ] No file outside `scope` is modified.
