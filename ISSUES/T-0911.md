# T-0911 — GDAP page always shows "disabled" because it probes a route that does not exist

## Report

`portal/web/src/app/gdap/page.tsx` (line ~94) decides whether GDAP is enabled by calling
`GET /v1/gdap/relationships` and treating 404 as "disabled". `routes/gdap.ts` defines only
`POST /v1/gdap/sync` (`GDAP_SYNC_PATH`). With `M365_BFF_GDAP_PARTNER_TENANT_ID` set, sync is
mounted but the relationships route still is not, so the page always shows GDAP as disabled
and the Sync button is never reachable. The relationship store
(`createGdapRelationshipStore`) is already passed to `createGdapRoutes`.

## Fix direction

Add `GET /v1/gdap/relationships` (list from the relationship store), mounted with the same
`enabled` gate as sync, so 404 keeps meaning "GDAP not configured".

## Acceptance

- [ ] With a partner tenant configured, the GDAP page lists relationships and Sync works.
- [ ] Without one, the page still shows the "not configured" state.
- [ ] A route test covers the list in both states.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `GET /v1/gdap/relationships` in `routes/gdap.ts` returns `{ items }` from the relationship
  store that `app.ts` already passes in, so `app.ts` needed no change. Each item carries the
  tenant's `customerName` when the tenant row is known, and items are sorted by tenant ID and
  filtered to the caller's tenant scope. It is behind the same `enabled` gate as sync: with no
  `M365_BFF_GDAP_PARTNER_TENANT_ID`, neither route is served, and the page's 404 probe still
  shows "not configured".
- Permission `Tenant.Administration.Read` (new `GDAP_READ_PERMISSION`). It is registered via
  `GDAP_OPENAPI`, which `rbac/permissions.ts` already reads. `portal.v1.yaml` is regenerated
  (outside `scope`; the drift test requires it).
- `gdap.test.ts` adds 6 tests: not served when disabled; list with names and sort; empty before
  the first sync; tenant-scope filter; 401 and the requested permission. The existing tests now
  look routes up by path instead of `routes[0]`. `web/src/app/gdap/page.test.tsx` (listed in
  `tests`) does not exist. The page needed no change, so none was added. Full bff suite: 4399
  passed.
- Live check (only with a partner tenant configured): the GDAP page lists relationships, and
  Sync refreshes them.
