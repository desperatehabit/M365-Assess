# T-0062 — Dashboard payload routes and RBAC-filtered widget registry

## Report

EPIC-004 SPEC.md §6 fixes the dashboard API: `GET /v1/dashboard/{tenantId}` (per-tenant),
`GET /v1/dashboard` (all-tenants) and `GET /v1/dashboard/widgets` (available widgets). §7
requires RBAC `dashboard.read` and that "a widget the caller cannot read is omitted, not shown
empty"; the payload is filtered by the caller's `UserScope` (EPIC-038).

Deliver:

- Route handlers that serve the payloads from T-0061's repository, using the BFF error
  envelope and correlation id from T-0008.
- A widget registry naming the stock v1 widgets and the permission each requires, with a route
  that returns only the widgets the caller may read.
- Structured errors for an out-of-scope tenant (not an empty payload).
- OpenAPI updated to match the implemented routes and payload schemas.

## Acceptance

- [ ] All three dashboard routes are implemented and match the OpenAPI document.
- [ ] A request for a tenant outside the caller's scope returns a structured `403`, not data.
- [ ] Widgets the caller cannot read are absent from `/v1/dashboard/widgets`.
- [ ] A test covers the routes and fails without them.
- [ ] No file outside `scope` is modified.
