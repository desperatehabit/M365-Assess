# T-0403 — Transport rule template storage and CRUD

## Report

EPIC-021 SPEC.md §2 (US-2), §3.3, §5, and §6 require transport-rule templates with `View`, `Edit`,
`Clone`, `Deploy`, `Export`, and `Delete`. §5 defines `TransportRuleTemplate` (`id`, `name`,
`ruleJson`, `variables`, `source`). Resolved §11.3 adopts **local templates first**, deferring
community template sharing to EPIC-039, so `source` records a local origin only.

Deliver migration `0034_transport_rule_templates.sql` and `transport-template-repository.ts`
(shared with the connector templates in T-0405), plus `transport-rule-templates.ts` for the §6
`GET`/`POST`/`PATCH`/`DELETE` routes. Templates persist; a rule cloned to a template is stored as
`ruleJson` with declared `variables` and never as a live tenant write. Extend `portal.v1.yaml`.
Deploy itself is T-0406.

## Acceptance

- [ ] Migration 0034 applies after the highest existing migration, is re-runnable, and advances `SchemaVersion`.
- [ ] Transport rule templates create, read, update, soft-delete, and clone.
- [ ] A template records `ruleJson`, declared `variables`, and a local `source`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
