# T-0484 — Create SharePoint sites (single and bulk CSV) with per-row results

## Report

EPIC-025 SPEC.md §2 US-2, §3.2, and §4.1 define site creation: a wizard for single or bulk (CSV)
creation with type, owners, template, and sharing settings; create routes through EPIC-006; bulk
add reports per-row results and never silently partial-succeeds. §6 exposes `POST
/v1/tenants/{id}/sharepoint/sites`. §11 item 3 is resolved (adopted): the **CSV schema** for bulk
creation is fixed here.

CSV schema (header row, one site per row): `name`, `alias` (the site URL slug), `type`
(`team`|`communication`), `owners` (semicolon-separated UPNs), `template` (optional
`SharePointTemplate` id or name), `sharing` (`disabled`|`externalUserSharingOnly`|
`externalUserAndGuestSharing`). Unknown columns are ignored; missing required columns reject the
file before any write.

Deliver `New-SharePointSite.ps1` (single) and `New-SharePointSiteBulk.ps1` (bulk) handlers plus
thin entrypoints; both apply through the EPIC-006 gated executor (T-0108) with audit and return
one result per row. The route validates `sharepoint.write` + `Remediation.Apply` and tenant
scope. Extend `portal.v1.yaml` and document the schema in the OpenAPI request description.

## Acceptance

- [ ] Single create accepts type/owners/template/sharing and routes through EPIC-006.
- [ ] Bulk import validates the CSV schema above and returns one result per row, with no silent partial success.
- [ ] A malformed or incomplete CSV is rejected before any write.
- [ ] A test covers single create and a mixed-result bulk import and fails without it.
- [ ] No file outside `scope` is modified.
