# T-0922 — There are no pre-defined assessment templates when starting a run

## Report

Starting an assessment offers no pre-defined templates. The operator has to pick sections and
options by hand every time.

## Current state

`NewRunDialog.tsx` is a three-step wizard (tenants, then sections and options, then confirm)
with a select-all toggle for sections. There is no template or preset concept for runs in the
web app or the BFF. The "templates" elsewhere in the portal are standards, CA, Intune and
other configuration templates, not run presets.

## Decisions (operator, 2026-11-19)

- Ship **built-in** templates, and let operators **save their own**.
- Built-in templates are **locked**: they cannot be edited, renamed or deleted. To change one,
  the operator makes a copy, which becomes an operator template they can edit freely. The
  originals always stay intact.

## Fix direction

- **Built-in templates**, each filling in sections and options:
  - **Full assessment**: all sections, the CLI default.
  - **Quick identity check**: Entra, CA and MFA.
  - **Email security**: EXO, DNS and Defender for Office.
  - **CIS M365 benchmark**: the sections and framework filter for CIS.
  - **Baseline + drift**: full run with `-AutoBaseline`.
- **Operator templates:** a new `run-templates` store and route (`GET/POST/PATCH/DELETE
  /v1/run-templates`, plus `POST /v1/run-templates/{id}/copy`). Built-ins are served with
  `builtIn: true`. `PATCH` or `DELETE` on a built-in returns 403 with a code such as
  `template.builtin_locked`.
- **Wizard:**
  - Step 1 offers a template picker with *Built-in* and *Saved* groups, plus *Custom*.
  - Changing sections or options after picking a built-in does not edit the built-in. The
    confirm step offers "Save as new template".
  - Built-ins show a lock badge and a "Make a copy" action. No edit or delete actions.
- A run records the template it started from (`options.templateId` and `templateName`), and
  whether it was changed before starting.

## Acceptance

- [x] The New run wizard offers the built-in templates above.
- [x] Picking a template fills in sections and options, and the operator can still change them
      for that run.
- [x] An operator can save the current selection as a named template, and edit, rename or
      delete their own templates.
- [x] Built-in templates cannot be edited, renamed or deleted through the UI or the API (403).
      "Make a copy" creates an editable copy.
- [x] A run records which template it used.
- [x] No file outside `scope` is modified.

## Fix

### Store, migration and routes

- Added forward-only migration `0133_run_templates.sql` (soft delete, JSON sections/options,
  audit trail) and `SqliteRunTemplateRepository` in `@m365-assess/db`, exported from
  `portal/db/src/index.ts`.
- Added `portal/bff/src/routes/run-templates.ts`:
  - `GET/POST /v1/run-templates`, `GET/PATCH/DELETE /v1/run-templates/{id}`,
    `POST /v1/run-templates/{id}/copy` (201).
  - Five built-ins served from the module, `builtIn: true`: Full assessment (all 13
    sections), Quick identity check (Identity, quick scan), Email security (Email +
    Security), CIS M365 benchmark (CLI sections, `framework: cis-m365-v6`), Baseline +
    drift (all sections, `autoBaseline: true`).
  - Built-ins live outside the repository, so a refresh or upgrade never overwrites an
    operator copy.
- Locking reuses the T-0924 shared module `routes/template-builtin.ts`: PATCH/DELETE on a
  built-in (route id or a stored `builtIn` row) returns **403 `template.builtin_locked`**;
  `copyTemplateName` gives `(copy)`, `(copy 2)`, … names.
- Mounted in `app.ts` against `SqliteRunTemplateRepository`; permissions registered from
  `RUN_TEMPLATES_OPENAPI` in `rbac/permissions.ts`, fragment added to
  `ROUTE_OPENAPI_FRAGMENTS`, and `portal/contracts/openapi/portal.v1.yaml` regenerated.

### Run provenance

- `adapters/runs.ts` now accepts `templateId`, `templateName` and `templateChanged` as known
  run options alongside the T-0927 switches. The template fields are validated (non-empty
  strings / boolean) but are deliberately kept out of the worker context: only the four
  assessment switches reach `Options` and `provenance.assessmentOptions`.
- `runs-create.ts` needed no signature change; its parent and child run records carry the
  full options object, so the template is recorded on every run row.

### Wizard

- Step 1 gained the template picker: Custom, Built-in and Saved groups; built-ins show a
  lock badge and **Make a copy**; saved templates show **Rename** and **Delete**.
- Picking a template copies its sections and the four switches into the form (the template
  object is never mutated). Changing them marks the run as changed for that run.
- Step 2 still allows free section changes; step 4 shows the template and whether it was
  changed, offers **Save as new template**, and **Update template** for a saved template.
- `/runs/new` loads `/v1/run-templates`, POSTs new templates, PATCHes updates, copies
  built-ins, and deletes/renames saved templates. Submitted run options carry
  `templateId`/`templateName`/`templateChanged`.
- All styling keeps the report theme tokens (the zero-colour-literal test still passes).

### Notes / limits

- `framework` (`cis-m365-v6`) and `autoBaseline` are template properties, shown in the picker
  and persisted on the template copy; the run records the template identity. They are not
  sent as run switches: the worker's option block maps only QuickScan, SkipPurview, Redact
  and Evidence, and T-0927 keeps unknown options rejected rather than silently dropped.
  Wiring `-HeadlineFramework`/`-AutoBaseline` is a follow-up in the worker/run option
  contract.
- Built-ins are code, not rows. Adding or changing one is a route-module change; operator
  copies in `run_templates` are never refreshed.
