# T-0586 — Compliance template CRUD and deploy engine

## Report

EPIC-030 SPEC.md §2 US-6, §3.6, and §4.2 define templates per area (**DLP/Retention/Label/SIT/Safe
Links Templates**) with row actions `View`, `Edit`, `Clone`, `Deploy`, `Export`, `Delete`, and
deploy supporting **variables** with **partial-failure reporting**. §6 fixes `GET`/`POST`/`PATCH`/
`DELETE /v1/compliance-templates` and `POST /v1/compliance-templates/{id}/deploy`. §11.3 is resolved
to **local templates first**, with the community catalog deferred to EPIC-039.

Deliver template CRUD over `ComplianceTemplate` (T-0581), a `template-deploy.ts` engine that resolves
variables (reusing the EPIC-002 `%var%`/variable substitution, T-0027, per tenant or group), builds a
plan, applies through the EPIC-006 gated path (T-0108), and reports per-target partial failures
without aborting the whole deploy. `source` accepts `local` only in v1; community is rejected.

## Acceptance

- [ ] CRUD lists, creates, edits, clones, exports, and deletes templates for all five areas.
- [ ] `POST .../deploy` resolves variables, applies through T-0108, and reports per-target success/failure.
- [ ] A partial failure does not roll back successful targets and is surfaced in the response.
- [ ] `source` rejects `community` in v1 (deferred to EPIC-039).
- [ ] A test covers CRUD + deploy and fails without the code.
- [ ] No file outside `scope` is modified.
