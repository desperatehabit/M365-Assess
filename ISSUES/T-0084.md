# T-0084 — Reports API: executive render, custom render, history, download, bundle

## Report

EPIC-005 SPEC.md §6 defines the report endpoints: `POST /v1/reports/executive`,
`POST /v1/reports/render`, `GET /v1/reports`, `GET /v1/reports/{id}/download`, and
`POST /v1/reports/{id}/bundle`. §4.1 assembles the executive payload from the latest run +
compliance state + secure score; §3.4 bundles the module's HTML/XLSX/JSON/evidence artifacts into
one download. §7 requires `reports.read` / `reports.generate` and tenant scoping; §10 requires
generation to be audited.

Deliver:

- Route handlers that assemble the executive/custom payloads from persisted rows, enqueue a
  render job through the T-0010 queue, and stream the resulting artifact on download with correct
  content types (`03-database.md` §1 principle 2).
- The bundle endpoint gathers the run artifacts referenced by the report's tenant/run.
- OpenAPI updated to match.

Note: run/finding data is produced by EPIC-003 (runs/queue), which is not yet authored; this
ticket reads it through the repository seam and stubs it in tests.

## Acceptance

- [ ] Executive and custom render endpoints enqueue a job and return a `GeneratedReport` handle.
- [ ] History is paginated and tenant-scoped; download streams the artifact with a correct type.
- [ ] The bundle endpoint returns the run's HTML/XLSX/JSON/evidence artifacts.
- [ ] A test covers the routes and fails without them.
- [ ] No file outside `scope` is modified.
