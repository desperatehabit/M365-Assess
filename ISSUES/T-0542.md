# T-0542 — Normalized alert model across Defender, MDO, and Graph

## Report

EPIC-028 SPEC.md §3.3 requires an alert table whose `Service source` unifies Defender, MDO, and
Graph; §9 names source divergence (Defender vs Graph alert shapes) as a risk and requires a
**normalized alert model**. §11 item 2 is resolved (adopted): the normalized model is defined
here, in this ticket, as shared contracts.

Deliver `portal/contracts/src/alerts.ts` defining a `NormalizedAlert` type (id, source, title,
severity, status, entity, created, incidentId, plus source-specific passthrough) and
`normalizeAlert`/`validateAlert` helpers that map each source (Defender, MDO, Graph security
alert) onto the model, plus a Vitest unit test that normalizes a sample from each source and
rejects an unmappable shape. Types only; no HTTP or worker behavior.

## Acceptance

- [ ] `NormalizedAlert` covers the common fields used by the alert list and detail views.
- [ ] `normalizeAlert` maps a Defender, an MDO, and a Graph alert onto the model.
- [ ] Unknown/unmappable source shapes are rejected, not silently coerced.
- [ ] A test normalizes one sample per source and fails without the mapping.
- [ ] No file outside `scope` is modified.
