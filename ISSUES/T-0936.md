# T-0936 — All 11 Power BI checks are Review after a 404, and the message blames the wrong cause

## Report

In the walk's run, all 11 Power BI checks are **Review**. The collector's call to
`admin/tenantSettings` (`Get-PowerBISecurityConfig.ps1:58`) returned **404 Not Found**, and the
message tells the operator to check the Power BI admin role.

## Likely cause (to confirm)

A 404, as opposed to a 401 or 403, points to a wrong endpoint rather than a missing role. Tenant
settings are believed to be served from the Fabric admin API
(`https://api.fabric.microsoft.com/v1/admin/tenantsettings`), not the Power BI REST path the
collector calls.

## Fix direction

- Confirm the endpoint with a raw call, then correct it.
- Make the error message match the HTTP status: 401 or 403 means a permission or role problem,
  and 404 means an endpoint or API problem.
- Record the failure as a collector issue or sentinel (T-0930), so the run is `partial` (T-0937).

## Acceptance

- [ ] On a tenant where the app has the required access, the Power BI checks record real
      values.
- [x] A 404 and a 403 give different, accurate messages.
- [x] No file outside `scope` is modified.

## Fix

Confirmed the endpoint and its contract against the Microsoft Fabric REST API
specification (`admin/swagger.json` in `microsoft/fabric-rest-api-specs`):

- Host/base path: `https://api.fabric.microsoft.com` + `/v1/admin`, operation
  `GET /tenantsettings` (`Tenants_ListTenantSettings`).
- Caller must be a Fabric administrator or a service principal; delegated scope
  `Tenant.Read.All` or `Tenant.ReadWrite.All`.
- Response shape `{ value: [ { settingName, title, enabled, ... } ], continuationUri }`
  (the legacy Power BI `admin/tenantSettings` shape was
  `{ tenantSettings: [ { isEnabled } ] }`). The collector now follows
  `continuationUri` and reads `enabled`, with `isEnabled` kept as a fallback.

`Get-PowerBISecurityConfig.ps1` now calls the Fabric endpoint directly through
`Invoke-PowerBIRestMethod` (the same absolute-URL pattern the repo's Power BI
remediation helper already uses). HTTP status is read from the exception response
and falls back to matching the message, then:

- `401`/`403` — "Access denied (HTTP …)": names the Fabric Administrator role,
  `Tenant.Read.All`, and the service-principal admin-API setting.
- `404` — "Fabric admin API endpoint not found (HTTP 404)": names the endpoint and
  cloud/version availability, and explicitly says it is not a role problem.

The T-0930 sentinel now carries `POWERBI-COLLECTOR-000`.

Tests run: `tests/PowerBI/Get-PowerBISecurityConfig.Tests.ps1` — 26 passed.
Coverage added/updated: Fabric `value`/`enabled` fixture drives real Pass/Fail
values; continuation pages are followed; 401 and 403 assert role/permission text
and reject "endpoint not found"; 404 asserts endpoint text and rejects role
language; the sentinel id is asserted. A live tenant call was not possible in
this environment, so the first acceptance box stays open.
