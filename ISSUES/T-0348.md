# T-0348 — Devices list page with filters and danger-styled actions

## Report

EPIC-018 SPEC.md §3.1 fixes the **Devices** page: the §3.1 table columns, filters (platform,
compliance, ownership, last check-in age, encrypted), and row actions `View`, `Sync`, `Retire`,
`Wipe`, `Fresh start`, `BitLocker key`, `Collect diagnostics`. Destructive actions must be visually
distinct (danger token) and require confirmation. §11.3 is resolved: **no bulk destructive actions
in v1**.

Deliver the Devices page, `DeviceTable` (columns, permission-filtered row actions, danger-styled
destructive actions), and `DeviceFilters`. There is deliberately **no select-all/bulk-action
toolbar** for destructive verbs. Destructive row actions route to the confirmation dialogs
(T-0350); `View` deep-links the detail page (T-0349).

## Acceptance

- [ ] The page renders the §3.1 columns and applies the documented filters server-side.
- [ ] Destructive row actions use the danger token and are permission-filtered.
- [ ] No bulk destructive action affordance exists in the UI.
- [ ] Component tests cover table rendering, filters, and action gating and fail without them.
- [ ] No file outside `scope` is modified.
