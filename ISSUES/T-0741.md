# T-0741 — RBAC entities, migration, and base-role presets

## Report

EPIC-038 SPEC.md §5 fixes the access-control entities: `PortalUser` (`id`, `upn`,
`displayName`, `status`, `preferences`), `Role` (`id`, `name`, `include[]`, `exclude[]`,
`builtin`), `UserScope` (`userId`, `targetType(tenant|group|all)`, `targetId`), `ApiClient`
(`id`, `name`, `secretHash`, `roles[]`, `ipRanges[]`, `rateLimit`, `enabled`, `lastUsedAt`),
`AccessIPRange` (`id`, `cidr`, `scope`), `PermissionRegistry` (`endpoint`, `permission`,
`functionality`), and the shared `AuditEvent`. SPEC.md §4.1 fixes the four base roles exactly:
`readonly`, `editor`, `admin`, `superadmin` with the include/exclude table; base roles are
`builtin=true` and immutable.

Add the next forward-only migration under `portal/db/migrations/` (pick the next free number for
this worktree) and an `rbac-repository.ts` implementing the entity shapes, extending the
repository interface/index from T-0009. Add `base-roles.ts` as the canonical preset data and
prove via test that it matches the §4.1 table, including that `editor` excludes
`Remediation.Apply`.

## Acceptance

- [ ] Migration is forward-only and creates the §5 entities with the stated columns.
- [ ] The four base roles match SPEC §4.1 exactly; `editor` excludes `Remediation.Apply`.
- [ ] Base roles are `builtin=true`; the repository exposes no mutator for them.
- [ ] API client secrets are stored only as hashes (no plaintext column).
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
