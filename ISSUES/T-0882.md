# T-0882 — MFA report actions are placeholders and dialogs are orphaned

## Report

`portal/web/src/app/mfa-report/page.tsx:69-77,110-120` implements `handleAction`, `handleBulkReset`,
and `handleBulkPush` as no-ops, and `DISABLED_REASONS` states the dialogs "will be mounted in T-0229".
The per-user action dialogs exist but are orphaned:
`portal/web/src/components/mfa/ResetMfaDialog.tsx` and `TapDialog.tsx` are imported by no page. The
backend reset/TAP/push/default-method adapters are wired (`portal/bff/src/app.ts:945-953`,
`portal/bff/src/adapters/mfa.ts:65-107`), so the gap is UI-side (SPEC §3.1–§3.2).

## Acceptance

- [ ] Reset (row and bulk), TAP, and push actions call the MFA endpoints.
- [ ] `ResetMfaDialog` and `TapDialog` are rendered from the MFA report page.
- [ ] The placeholder no-op handlers and the T-0229 note are removed.
- [ ] A component test covers a reset action round trip.
- [ ] No file outside `scope` is modified.
