# T-0345 — Wipe and fresh-start with typed confirmation and optional two-person rule

## Report

EPIC-018 SPEC.md §3.3 and §4.1 define **Wipe** and **Fresh start** as destructive: wipe requires
typed confirmation (device name) plus a reason and is irreversible, fresh-start requires a
destructive confirmation. §11.1 is resolved to an **optional per-tenant two-person rule** for
wipe. §9 names irreversible data loss as the top risk.

Deliver migration `0046_device_action_policies.sql` + a `device-action-policies.ts` repository for
the per-tenant policy (`twoPersonRule` flag), `Invoke-DeviceWipe.ps1` + entrypoint, and the
destructive-action route behind the T-0108 gated-write seam. When the two-person rule is enabled,
apply is held in a `pending-approval` state until a second distinct actor with `devices.actions`
approves it. Both actions capture reason and append an audit record.

## Acceptance

- [ ] Wipe requires typed device-name confirmation and a reason; fresh-start requires a destructive confirmation.
- [ ] When the per-tenant two-person rule is on, wipe stays pending until a second distinct actor approves.
- [ ] The policy defaults to off and is stored/read per tenant.
- [ ] Tests cover the route, policy, and worker and fail without them.
- [ ] No file outside `scope` is modified.
