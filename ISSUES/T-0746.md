# T-0746 — UserScope tenant/group scoping and intersection enforcement

## Report

EPIC-038 SPEC.md §4.2: `Test-PortalAccess -TenantList` / `-GroupList` resolves the caller's
allowed tenant set from `UserScope` (direct tenants plus expanded tenant groups). Every
tenant-scoped query **intersects** the requested scope with the allowed scope; a request outside
scope is denied, never silently narrowed. `superadmin` may hold `all`. SPEC.md §9 names
"scope bypass — trusting a client-supplied tenant list" as a risk whose mitigation is to always
intersect with `UserScope`.

Build `user-scope.ts`: resolve `UserScope` rows (`targetType(tenant|group|all)`) to a concrete
tenant set (expanding groups), intersect with the requested selection, and return an explicit
`denied` result when the request leaves the allowed set. Wire it into the `/v1/users` scope
editing (T-0744) and make it the shared helper every tenant-scoped endpoint calls. Add the
`UserScope` edit path.

## Acceptance

- [ ] A user scoped to tenant A is denied read/act on tenant B (denied, not narrowed).
- [ ] A `group` scope expands to its member tenants; `all` is allowed only for `superadmin`.
- [ ] Intersection is applied to the requested selection before any query runs.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
