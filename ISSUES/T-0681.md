# T-0681 — Backup and BackupConfig schema and repository

## Report

EPIC-035 SPEC.md §5 defines the `Backup` entity (`id`, `type`, `tenantId?`, `createdAt`,
`createdBy`, `schemaVersion`, `artifactRef`, `checksum`) and `BackupConfig` (`id`, `scheduleId`,
`retentionDays`, `replicationTarget`); §6 exposes them through `/v1/backups` and
`/v1/backup-settings`. ADR-0015 requires numbered, forward-only migrations and makes the
repository the only DB-aware layer.

Deliver migration `0100_backups.sql` (next free global number; do not reuse a lower one) adding
both tables behind the `0001_init` schema, plus repository methods on `portal/db/src/repository.ts`
and `sqlite-repository.ts` to list/filter, get, create, delete backups and get/upsert the
`BackupConfig`. Backups are tenant-scoped for `type = tenant` and instance-scoped otherwise; an
`artifactRef` references the archive on the artifact tier — **no secret value is ever a column**.
Every create/delete writes the existing append-only `AuditEvent`. No route, archive, or UI code
belongs in this ticket.

## Acceptance

- [ ] Migration `0100` applies after the latest migration, is re-runnable, and advances `SchemaVersion`.
- [ ] Repository exposes Backup list/get/create/delete and BackupConfig get/upsert; no raw SQL appears outside `portal/db/`.
- [ ] Tenant-type backups are tenant-scoped and soft-tenancy rules match `03-database.md` §3.
- [ ] A test asserts no column stores a secret value and that create/delete are audited.
- [ ] No file outside `scope` is modified.
