# T-0721 — Typed application settings schema and AppSetting repository

## Report

EPIC-037 SPEC.md §5 defines `AppSetting` (`key`, `value`, `scope`, `updatedAt`, `updatedBy`);
§9 names **settings sprawl** as a risk whose mitigation is "a typed settings schema; no free-form
blobs". §11.1 resolves the settings schema to **typed keys with a migration path, not free-form**.

Deliver `portal/bff/src/settings/schema.ts`: a typed key registry (key → type, default, allowed
scopes, validation) plus a schema version and a migration path for key changes. Deliver migration
`0110_settings.sql` (next free global number) and repository methods to read all settings, read by
key, and upsert a typed value with `updatedBy`/`updatedAt`, writing an `AuditEvent`. Unknown keys
and type-mismatched values are rejected. The HTTP layer is T-0722.

## Acceptance

- [ ] Every setting write is validated against a typed key; an unknown key or wrong type is rejected.
- [ ] Migration `0110` applies after the latest migration, is re-runnable, and advances `SchemaVersion`.
- [ ] The schema carries a version and a documented migration path for key changes.
- [ ] Every upsert writes an audit event.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
