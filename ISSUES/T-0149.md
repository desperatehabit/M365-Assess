# T-0149 — Scheduled standards enforcement with dedupe and change-detection

## Report

EPIC-008 SPEC.md §4.3: the **Standards system timer** (registered in EPIC-007, every 12 h)
enqueues a standards job per tenant; per-tenant, per-standard work uses a **dedupe cache**
(CIPP `RerunCache` analogue) to prevent double-application, and a **change-detection guard**
(CIPP `IntunePolicyTypeTracking` analogue) skips standards whose target config is unchanged since
the last run. §9 rates "schedule overlap" a risk mitigated by single-flight per tenant.

Resolved §11.3 adopts Intune/CA as the first cacheable change-detection types (CIPP parity).
Resolved §11.5 keeps the SPEC's recommendation of the per-12 h dedupe window. Deliver the timer
enqueue, the change-detection guard, and the dedupe store migration (`0008`).

## Acceptance

- [ ] The standards timer enqueues one job per tenant per 12 h window with `trigger: schedule`.
- [ ] Re-running an unchanged tenant is a no-op; a changed standard is re-evaluated.
- [ ] The dedupe cache prevents a double-application within the window and is single-flight per tenant.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
