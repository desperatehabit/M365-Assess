# T-0909 — Backup restore wizard calls an unmounted preview endpoint

## Report

`RestoreWizard.tsx` (`fetchRestorePreview`, line ~55) calls
`POST /v1/backups/{id}/restore/preview` as soon as a backup is selected. The BFF has no such
route: a running BFF answers `request.not_found` ("No route for POST
/v1/backups/b1/restore/preview"). `POST /v1/backups/{id}/restore` itself is mounted.

The wizard therefore shows "Preview failed: 404" at the step SPEC §3 calls "preview what will
change", and SPEC §9 acceptance ("Restore previews changes and applies with rollback on
failure") cannot pass. The preview route is also missing from SPEC §6, so the UI and the spec
disagree.

## Fix direction

Add a dry-run preview to `backups-restore.ts` (same authorization as restore, no writes) that
returns the per-table change counts the wizard renders, mount it, and add it to SPEC §6.

## Acceptance

- [ ] `POST /v1/backups/{id}/restore/preview` returns the change summary without writing.
- [ ] The restore wizard shows the preview for a real backup, then restores on confirm.
- [ ] A route test covers the preview and fails without the mount.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `POST /v1/backups/{id}/restore/preview` is served by `createBackupsRestoreRoutes`, which
  `app.ts` already mounts, so `app.ts` needed no change. It shares restore's admin gate, backup
  lookup, tenant-scope check and archive read, then calls the read-only T-0686
  `previewRestore`. It needs no confirmation and no Idempotency-Key, and an empty body previews
  the full scope (the wizard sends `{}`). The response is `{ backupId, schemaVersion, tables }`,
  and each table carries `added` / `changed` / `removed`, which is the shape the wizard renders.
- Errors match restore: 401, 403 (scope or tenant), 404 (backup or archive), 409 (schema), and
  400 `backup.restore.table_missing` for a table the archive does not carry.
- Added to SPEC §6 and to the OpenAPI fragment (`previewBackupRestore`). Outside `scope`, as
  every new route requires: the permission registry (`rbac/permissions.ts`), the fragment
  permission override (`routes/openapi.ts`, same `CIPP.Admin.BackupRestore` token as restore),
  and the regenerated `portal.v1.yaml`. The registry-completeness guard fails without them.
- `backups-restore.test.ts` adds 8 tests. The route-list assertion fails without the route. The
  main test asserts the preview makes no writes, no transaction, no pre-restore backup, no new
  artifact and no audit. Full bff suite: 4393 passed.
- Live check (Phase 2 runbook, T-0865 row): open Backup, then Restore on a real backup; the
  preview step lists the per-table changes; confirm restores.
