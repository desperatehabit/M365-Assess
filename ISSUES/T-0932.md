# T-0932 — Forms checks read property names the API doesn't return (one false Fail, one possible false Pass)

## Report

In the walk's run:
- **FORMS-CONFIG-004** is **Fail** with an empty CurrentValue.
- **FORMS-CONFIG-006** is **Pass** with an empty CurrentValue, which is a possible false
  negative.
- FORMS-CONFIG-004 also contradicts ENTRA-ORGSETTING-002, which reports the same setting as
  "Cannot be checked via API → Review".

## Likely cause (to confirm)

`Get-FormsSecurityConfig.ps1` reads `isPhishingScanEnabled` (line 107) and
`isBingImageVideoSearchEnabled` (line 133), and both come back empty. The beta `formsSettings`
names are believed to be `isInOrgFormsPhishingScanEnabled` and `isBingImageSearchEnabled`.

## Fix direction

- Capture a raw response, then correct the property names.
- When a property is absent, as opposed to false, emit Review ("not returned by API") instead of
  a Pass or Fail.
- Align ENTRA-ORGSETTING-002 and FORMS-CONFIG-004 so one setting yields one consistent status.

## Acceptance

- [ ] FORMS-CONFIG-004 and FORMS-CONFIG-006 record the real value from the API.
- [x] A missing property yields Review, never Pass or Fail.
- [ ] Tests use a fixture taken from the raw response, with PII removed.
- [x] No file outside `scope` is modified.

## Fix

- `Get-FormsSecurityConfig.ps1`
  - Added a local `Get-SettingProperty` helper that reports whether a property is
    present, so a present-but-false value is distinguishable from an absent property
    (works for both `IDictionary` and `PSObject` responses).
  - FORMS-CONFIG-004 now reads `isInOrgFormsPhishingScanEnabled` first and falls back
    to `isPhishingScanEnabled`. When neither is returned it records `Review` with
    CurrentValue `Not returned by API` instead of the previous false `Fail`.
  - FORMS-CONFIG-006 now reads `isBingImageSearchEnabled` first and falls back to
    `isBingImageVideoSearchEnabled`. When neither is returned it records `Review`
    with CurrentValue `Not returned by API` instead of the previous false `Pass`.
  - The documented name wins when both shapes are present.
- `tests/Collaboration/Get-FormsSecurityConfig.Tests.ps1`
  - Added synthetic `formsSettings` fixtures using the documented property names,
    a both-shapes fixture proving the documented name wins, and a missing-property
    fixture proving Review.
- Tests run: `Invoke-Pester -Path './tests/Collaboration/Get-FormsSecurityConfig.Tests.ps1'`
  -> 24 passed, 0 failed. PSScriptAnalyzer (project settings, Severity Warning) clean.

Not verified: no live tenant was available, so the documented property names were not
confirmed against a raw `GET /beta/admin/forms/settings` response. The fixture is shaped
like that response but is synthetic, not a captured one; the collector supports both the
documented and legacy names so either shape works. FORMS-CONFIG-004/ENTRA-ORGSETTING-002
alignment still needs a live run to confirm the same status is produced.
