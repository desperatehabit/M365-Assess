# T-0955 — App credential checks read only service principals and miss app registration secrets and certificates

## Report

- ENTRA-ENTAPP-001, -012, -013, -014 and -018 in `Get-EntAppSecurityConfig.ps1` (around lines
  310, 701, 730, 763, 909) iterate `$regularApps`, which holds service principals.
- Client secrets and certificates are normally added to the **app registration**
  (`/applications`, `passwordCredentials` / `keyCredentials`), not to the service principal.
  The app registrations query (around line 285) does not select those properties.
- Result: an app registration with an expired secret, or one that relies on a secret instead
  of a certificate, does not fail ENTRA-ENTAPP-012 or -013.
- Observed on the live tenant: both app registrations hold a certificate. ENTRA-ENTAPP-001
  reported "1 enabled app(s) have secrets or certificates", which counted only a first-party
  service principal with service-principal credentials.

## Fix direction

- Select `passwordCredentials,keyCredentials` on the app registrations query and evaluate
  credentials on both objects, labelling which object holds each credential.
- Apply the change to ENTRA-ENTAPP-001, -012, -013, -014 and -018.
- Consider excluding first-party Microsoft service principals from the "credentialed apps with
  no owners" check (ENTRA-ENTAPP-018), where an owner cannot be assigned.

## Acceptance

- [x] An app registration with an expired secret fails ENTRA-ENTAPP-013.
- [x] An app registration with only a client secret fails ENTRA-ENTAPP-012.
- [x] ENTRA-ENTAPP-001 counts credentials on app registrations and service principals.
- [x] Tests cover app-registration credentials and fail without the change.
