# T-0856 — Mount and deliver EPIC-026 Teams & Voice routes and UI

## Report

The EPIC-026 factories (`createTeamsListRoute`, `createTeamsCreateRoute`,
`createTeamsLifecycleRoutes`, `createTeamsActivityRoutes`, `createLisLocationsRoutes`,
`createTeamsVoiceRoutes`) exist under `portal/bff/src/routes/` and are tested, but
`portal/bff/src/app.ts` imports none of them and there is no adapter under `portal/bff/src/adapters/`,
so the endpoints 404. Workers (`get-teams.ps1`, `new-team.ps1`, `invoke-team-action.ps1`,
`get-teams-activity.ps1`, `invoke-lis-location.ps1`, `invoke-teams-voice.ps1`) exist.

UI gaps (SPEC §3.1, §4.1, §10):

- `components/teams/{AddTeamWizard,TeamDeleteDialog}.tsx` are referenced only by
  `TeamLifecycle.test.tsx` and appear on no page.
- `app/teams/page.tsx:139,147,150,153,156,159,162` links to `/teams/new`, `/teams/{id}`,
  `/teams/{id}/members`, and `/teams/{id}/edit`, none of which exist.

## Acceptance

- [x] Every EPIC-026 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Team create, lifecycle, activity, LIS, and voice actions run their real workers.
- [x] The linked team new/detail/members/edit routes exist and render live data.
- [x] No file outside `scope` is modified.

## Fix

`createTeamsProviders` binds the worker-backed seams to their existing entrypoints.
Every call carries the tenant credential block, so the BFF never reaches Graph
itself:

- `get-teams.ps1` receives the flat list job (visibility, archived, from, to, top,
  cursor) and returns the filtered cursor page.
- `get-teams-activity.ps1` receives the period and date window and returns the
  per-team/per-user report.
- `invoke-team-action.ps1` runs edit/archive/clone/delete with the action at the
  envelope's top level and the team fields under `payload`; delete carries the
  route's confirmation name.
- `invoke-lis-location.ps1` lists locations (and resolves one by id) and runs the
  create/edit/delete writes.
- `invoke-teams-voice.ps1` lists the number inventory with the license state
  (normalizing the worker's PascalCase license fields) and runs assign/release/policy.
- `new-team.ps1` backs the create route's queue seam: the route's resolved plan
  envelope is mapped onto the worker's `payload.team` and runs immediately, so a
  create actually reaches Graph rather than sitting in a remediation envelope no
  dispatcher consumes. The LIS write routes' queue seam maps the same way onto
  `invoke-lis-location.ps1`.

`createApp` mounts all six route groups behind `resolveCaller`, the shared
authorizer, and the audit sink, with `/teams/activity` and `/teams/lis` before
`/teams/:teamId`. Lifecycle, LIS, and voice writes persist their TeamOperation
rows through the shared repository; the create route's TeamOperation and audit
event are recorded the same way. Every endpoint is registered in the EPIC-038
permission registry, published through its OpenAPI fragment, and the checked-in
contract is regenerated.

The linked Teams pages now exist under `portal/web/src/app/teams/`:
`new` hosts the AddTeamWizard, `[id]` renders the live team row and the lifecycle
actions, `[id]/members` renders the live owner/member counts, and `[id]/edit`
saves name/visibility through the gated PATCH. They read the live team list
(`GET /v1/tenants/{id}/teams`), which is the §6 surface; the detail pages select
the requested team from that page rather than inventing a non-SPEC endpoint.
