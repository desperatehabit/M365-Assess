# T-0668 — Domains page with add/verify flow

## Report

EPIC-034 SPEC.md §3.1 defines the **Domains** page (*Tenant Administration → Domains*): a table of
Domain, Type (initial/verified/managed), Verification, DNS health badge, Services (MX target), and
Last checked, with row actions `View`, `Check DNS`, `Verify`, `Set as default`, `Remove`, and a
primary `Add domain` button. §4.1 fixes the add flow: add → get verification records → verify.

Build the domains route and the `DomainsTable` / `AddDomainWizard` components plus a typed
`domainsApi.ts` client for the T-0662 list and T-0663 action endpoints. `Add domain` opens the
wizard showing the returned verification records and then calls `verify`; `Set as default`,
`Verify`, and `Remove` route through T-0663 (EPIC-006 writes). `Check DNS` and `View` hand off to
the T-0669 analyser. Use report theme tokens only; no colour literals.

## Acceptance

- [ ] The table renders every §3.1 column and all row actions.
- [ ] `Add domain` shows the verification records and completes verification through the API.
- [ ] `Set as default` and `Remove` warn that they are writes routed through the remediation
      engine and reflect the result.
- [ ] A test covers the component states and fails without it; only theme tokens are used.
- [ ] No file outside `scope` is modified.
