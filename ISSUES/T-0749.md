# T-0749 — Per-client rate limiting (100 req / 10 s default)

## Report

EPIC-038 SPEC.md §4.4: enforce a per-client sliding window, adopting CIPP's **100 requests /
10 s** default and making it per-client configurable via `ApiClient.rateLimit` (SPEC §5).
Exceeded requests return `429` with a `Retry-After` header. SPEC.md §11 item 4 resolves the
default as 100 req / 10 s.

Build `rate-limit.ts` as a sliding-window limiter keyed by API client id, using the client's
`rateLimit` when set and the 100/10 s default otherwise. Wire it into the API client
authentication middleware (T-0748) so it runs after identity resolution and before the route
handler. Expose the configured limit in the API-clients route (T-0747). Return `429` +
`Retry-After` with a structured error body.

## Acceptance

- [ ] Past the threshold, the next request returns `429` with a `Retry-After` header.
- [ ] The default is 100 req / 10 s; a per-client override is honored.
- [ ] Limits are enforced per client id, independently of other clients.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
