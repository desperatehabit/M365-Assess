# T-0009 — SQLite repository interface and migration bootstrap

## Report

ADR-0015 chooses SQLite behind a repository interface that all feature code depends on; the
repository is "the only place the engine is named". EPIC-001 SPEC.md §5 lists the entities this
epic introduces (`Run`, `RunSection`, `Finding`, `Job`, `TenantCredential`, `SchemaVersion`,
`AuditEvent`, plus a minimal `Tenant` stub that EPIC-002 extends).

Deliver:

- A `portal/db/` workspace exporting repository interfaces and a SQLite implementation. No
  feature code imports a SQLite driver directly.
- Numbered, forward-only migrations (`0001_init.sql`) and a startup gate on the `SchemaVersion`
  row (ADR-0015; SPEC §10 "Migrations gate startup on `SchemaVersion`").
- WAL mode; tenant scoping, soft delete, and append-only audit enforced **in the repository
  layer**, not left to callers (ADR-0015).
- Migration idempotence/rollback tests.

## Acceptance

- [ ] Migrations apply once, are re-runnable, and set `SchemaVersion`.
- [ ] Repository exposes interfaces for the §5 entities; no raw SQL string appears outside
      `portal/db/`.
- [ ] A test proves tenant scoping and soft delete are enforced by the repository.
- [ ] Startup is gated on the schema version.
- [ ] No file outside `scope` is modified.
