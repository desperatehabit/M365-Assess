# T-0687 — Restore apply with rollback, pre-restore backup, and audit

## Report

EPIC-035 SPEC.md §4.2 steps 3-4, §6 `POST /v1/backups/{id}/restore`, §7 (restore requires
`CIPP.Admin.*`), and §8 (restore is destructive and audited with before/after). §9 mitigates
restore data loss with preview (T-0686), explicit confirmation, and a **pre-restore automatic
backup**. §11.4 resolves selective restore to per-table first.

Deliver `apply.ts`: apply the confirmed diff inside a transaction where the store allows, per table
(resolving §11.4), rolling back on failure; take an automatic pre-restore backup before mutating;
write an `AuditEvent` capturing before/after per table; require a confirming `Idempotency-Key`.
Add the restore route and update `portal.v1.yaml`. Per-record granularity is explicitly deferred,
not built here.

## Acceptance

- [ ] A confirmed restore applies the selected tables in a transaction and rolls back fully on a mid-apply failure.
- [ ] An automatic pre-restore backup exists before any mutation.
- [ ] The restore writes an audit event with before/after.
- [ ] A replayed `Idempotency-Key` does not apply the restore twice.
- [ ] No file outside `scope` is modified.
