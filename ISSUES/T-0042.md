# T-0042 — Runs list API with filters and pagination

## Report

EPIC-003 SPEC.md §6 defines `GET /v1/runs` with filters by status/trigger/tenant/date (and §3.1
adds section); §3.1's table needs run ID, tenant(s), trigger, sections, status, progress,
findings, started, and duration. EPIC-001's T-0012 delivered the minimal run endpoints; this
ticket owns the full list surface. Results use cursor pagination (`05-programming.md` §3) and
every query intersects the caller's RBAC tenant scope (EPIC-003 §7; EPIC-038).

Deliver the list route against the T-0041 repository, returning parent and child runs
addressable as a unit, with filters, cursor pagination, and an updated OpenAPI document. A run
may only surface tenants inside the caller's scope.

## Acceptance

- [ ] The endpoint filters by status/trigger/tenant/date/section and paginates with a cursor.
- [ ] A bulk parent run and its children are both listed and linked by `parentRunId`.
- [ ] Runs for tenants outside the caller's scope are never returned.
- [ ] The OpenAPI document matches the implementation.
- [ ] No file outside `scope` is modified.
