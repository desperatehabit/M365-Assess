# T-0162 — DriftDeviation entity and triage-state-preserving upsert

## Report

EPIC-009 SPEC.md §5 defines `DriftDeviation` with `kind(mismatch|extra)`, `current`, `expected`,
`state ∈ open|accepted|customerSpecific|denied|deletePending|resolved`, `reason`, `expiresOn`,
`autoRemediateOnExpiry`, `overrideValue`, and `lastSeenAt`. §4.1 step 4 requires each run to
**upsert** deviations while preserving prior triage state so a re-run does not resurrect settled
items; §9 names that resurrection a risk. Resolved §11.4 fixes the **triage key =
`tenantId + standardKey + resourceId`**.

Deliver migration `0010` and repository methods for idempotent upsert keyed by the triage key.
An upsert updates `current`/`lastSeenAt` but never clears `accepted`/`customerSpecific`/`denied`
without an explicit operator action.

## Acceptance

- [ ] Deviations upsert by `tenantId + standardKey + resourceId`; re-running does not duplicate rows.
- [ ] An `accepted`, `customerSpecific`, or `denied` deviation keeps its state and reason across upserts.
- [ ] The state column is constrained to the six-value taxonomy; an unknown state is rejected.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
