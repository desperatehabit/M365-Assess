# T-0621 — Audit search, coverage, webhook, and exclusion-window entities

## Report

EPIC-032 SPEC.md §5 fixes four entities that must persist before any audit or webhook route
exists: `AuditSearch` (`id`, `name`, `filters`, `saved`, `scheduleId`, `lastRunAt`, `createdBy`),
`AuditCoverage` (`tenantId`, `auditEnabled`, `lastSearchAt`, `gaps[]`), `WebhookSubscription`
(`id`, `tenantId`, `resource`, `expiresOn`, `state`, `notificationUrl`), and
`AuditExclusionWindow` (`id`, `tenantId`, `startsAt`, `endsAt`, `reason`). Every search, export,
and subscription change also writes an append-only `AuditEvent` (SPEC §4.1, §8).

Add a numbered, forward-only migration under `portal/db/migrations/` and an
`audit-repository.ts` implementing the SPEC §5 shapes behind the ADR-0015 repository interface;
extend the EPIC-001 repository index. Enforce tenant scoping and soft delete in the repository
layer, expose create/read/list/update for searches and windows, upsert for coverage, and expiry
queries for subscriptions. No Graph calls and no route code belong here.

## Acceptance

- [ ] The migration is forward-only, re-runnable, and creates the four entities with the SPEC §5
      columns plus append-only `AuditEvent` writes.
- [ ] The repository round-trips a saved search, a coverage row, a subscription, and a window;
      subscription expiry queries return rows inside a window.
- [ ] Tenant scoping is enforced by the repository; a cross-tenant read returns nothing.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
