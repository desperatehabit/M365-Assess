# T-0502 — Teams list worker and API with filters

## Report

EPIC-026 SPEC.md §2 US-1, §3.1, and §6 define the team list: Name · Owners · Members ·
Visibility (public/private) · Archived · Created · Sensitivity, with filters by visibility,
archived, and activity. §6 exposes `GET /v1/tenants/{id}/teams`; teams are read live from Graph
per §7. §9 requires pagination for activity/volume.

Deliver a `Get-Teams.ps1` handler (entrypoint `get-teams.ps1`) that reads teams through the
Graph Teams scopes (§7, app-only per tenant) and returns a `ResultEnvelope`, plus the list route
that validates `teams.read` and tenant scope and supports cursor pagination. Filtering is passed
to the worker so large tenants are not fully materialized in the BFF. Extend `portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/teams` returns the §3.1 columns, filtered and paginated.
- [ ] Results are tenant-scoped; a caller without `teams.read` is refused.
- [ ] The BFF performs no Graph call directly (it enqueues the worker).
- [ ] A test covers listing and filtering and fails without the code.
- [ ] No file outside `scope` is modified.
