# T-0884 — Conditional Access named locations UI is missing

## Report

`portal/web/src/components/conditionalAccess/NamedLocationEditor.tsx` exists but is imported by no
page, there is no `portal/web/src/app/**/named-locations` route, and `portal/web/src/lib/caApi.ts`
has no named-location calls surfaced in the UI. SPEC §3.4 / US-4 require managing named locations.
The backend is wired: `ca-named-locations.ts` is mounted (`portal/bff/src/app.ts:1002`) with worker
`set-ca-named-location.ps1`.

## Acceptance

- [ ] A named-locations page exists and renders `NamedLocationEditor`.
- [ ] It lists, creates, and edits named locations through the mounted endpoints.
- [ ] A component test covers the CRUD round trip.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `caApi.ts` now exposes `listCaNamedLocations`, `createCaNamedLocation`, `editCaNamedLocation`,
  and `deleteCaNamedLocation` against the mounted `/v1/tenants/:id/ca/named-locations` routes.
- `NamedLocationsPanel` lists locations (type, ranges/countries, referencing policies) and opens
  `NamedLocationEditor` for create/edit; in-use deletes still require the editor's typed-name
  confirmation.
- The page at `/tenant/conditional-access/named-locations` wraps the panel in `RequireTenant`, so
  it uses the selected or `?tenantId=` tenant.
- Component tests cover list, create, edit, unused delete, and the in-use delete hand-off.
