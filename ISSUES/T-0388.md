# T-0388 — Soft-deleted mailbox view and restore

## Report

EPIC-020 SPEC.md §3 nav lists **Deleted Mailboxes** under *Email & Exchange → Administration*, and
resolved §11.4 adopts the **soft-deleted mailbox view plus restore**. Mailbox objects stay live in
EXO (§5), so the view is a read-only projection over soft-deleted mailboxes and restore is a
gated write.

Deliver `deleted-mailboxes.ts` for `GET /v1/tenants/{id}/deleted-mailboxes` and
`POST /v1/tenants/{id}/deleted-mailboxes/{mailboxId}/restore`, plus the `Restore-Mailbox.ps1`
worker job and `restore-mailbox.ps1` entrypoint. Restore routes through the EPIC-006 gate (T-0107),
requires confirmation, captures before/after, records a `MailboxOperation` (T-0382), and writes an
`AuditEvent`; a mailbox not in the soft-deleted set is a structured 4xx. Extend `portal.v1.yaml`.
Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Soft-deleted mailboxes list with the identity and deletion metadata needed to choose a restore.
- [ ] Restore of a soft-deleted mailbox succeeds, is confirmed, and writes before/after plus an `AuditEvent`.
- [ ] Restoring a mailbox that is not soft-deleted returns a structured 4xx.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
