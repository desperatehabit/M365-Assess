# T-0107 — Typed gated executor with -WhatIf and dry-run

## Report

EPIC-006 SPEC.md §8 and [`06-remediation.md`](../../docs/portal-specs/00-guides/06-remediation.md)
§2.2, §3.2, §8: remediation must never use `Invoke-Expression`; execution prefers typed cmdlets,
and every apply function must implement `-WhatIf`/dry-run, require confirmation, capture
`before`/`after`, and honor the gates. SPEC.md §11 item 1 resolves the design: **typed
per-command functions for the first validated set; a generic allowlisted executor only for
simple one-liners.**

Build `Invoke-RemediationAction` as the executor contract (parameters for the resolved check,
target, gates context, and `SupportsShouldProcess`/`-WhatIf`) and `Get-RemediationCommand`, the
allowlisted command-binding layer that maps a check id to a typed function or a vetted
parameter-bound command — never string evaluation. The first typed set covers the simplest
validated commands; unknown commands return a `not-implemented` result rather than executing.
Reuse tenant credentials from EPIC-001 (`Resolve-TenantCredential`); the tenant credential model
itself is EPIC-002 (not yet authored).

## Acceptance

- [ ] `-WhatIf` / dry-run writes nothing and reports the intended change; a test asserts no mutation.
- [ ] No `Invoke-Expression` appears anywhere in `Remediate/` (AST test).
- [ ] An unknown/unvalidated command is refused (`not-implemented`), not executed.
- [ ] `before`/`after` are captured around a typed action.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
