# T-0265 — GroupTemplate persistence and template CRUD API

## Report

EPIC-014 SPEC.md §5 defines the `GroupTemplate` entity — `id`, `name`, `groupType`, `naming`,
`owners[]`, `members[]`, `settings`, `licensing[]` — and §3.2 requires templates to define group
type, naming, owners, initial members, GAL/delivery settings, and licensing. §6 fixes
`GET`/`POST`/`PATCH`/`DELETE /v1/group-templates`. Only templates and deployment records persist;
group objects stay live in Graph (§5).

Deliver a numbered forward-only migration creating the `GroupTemplate` table (EPIC-001 §5 /
T-0009 repository interface), a `group-templates` repository, and the BFF CRUD routes behind the
RBAC `groups.templates` permission (§7). Templates are the input to the T-0266 deploy worker;
this ticket persists and validates them (non-empty type, well-formed naming template and owners)
but performs no tenant writes.

## Acceptance

- [ ] A migration creates the `GroupTemplate` table and the repository round-trips the §5 fields.
- [ ] CRUD routes list, create, edit, and delete templates with validation and structured errors.
- [ ] A test covers the repository/routes and fails without them.
- [ ] No tenant write path is introduced.
- [ ] No file outside `scope` is modified.
