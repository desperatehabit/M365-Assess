# T-0682 — Versioned JSON backup archive with manifest and checksum

## Report

EPIC-035 SPEC.md §4.1 steps 2-3 require serializing the collected configuration to a **versioned
archive** with a manifest (schema version, contents, checksum) stored on the artifact tier; §9
warns that a backup must never contain secrets (credential *references* only). §11.2 is resolved
to a **JSON archive (manifest + per-table dumps) over a raw DB dump**.

Deliver `portal/bff/src/backup/archive.ts`: a writer that packs `manifest.json` (epic/archive
version, producing instance version, timestamp, table list, per-table row counts, checksum) plus
one JSON dump per table into a single zip, and a reader that validates the checksum and refuses a
`schemaVersion` mismatch (SPEC §9 risk mitigation). The archive layer is pure I/O — it does not
touch the repository or artifact store. Secret-bearing columns are rejected at pack time.

## Acceptance

- [ ] A round-trip write→read preserves the manifest and every table dump.
- [ ] A mutated archive fails checksum validation with a structured error.
- [ ] A manifest schema version newer/older than the instance is refused, not partially applied.
- [ ] A test seeds a secret-looking column and asserts packing rejects it.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
