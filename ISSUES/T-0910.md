# T-0910 — Tenant detail Variables and History tabs call routes that do not exist

## Report

`portal/web/src/app/tenants/[id]/page.tsx` (lines ~206-222) loads:

- `GET /v1/tenants/{id}/variables`, but tenant variables are served at
  `GET /v1/tenant-variables?tenantId={id}` (`routes/tenant-variables.ts`).
- `GET /v1/tenants/{id}/audit`, which no route serves. Only the `/audit/coverage`,
  `/audit/search`, `/audit/searches` and similar sub-paths exist.

Both calls are wrapped in `try {} catch {}` and ignore non-OK responses, so the tabs are always
empty and nothing reports an error.

## Fix direction

Point Variables at `/v1/tenant-variables?tenantId=`. For History, use the portal logbook
(`GET /v1/logbook`, which stores `tenantId` per entry) filtered to the tenant, or remove the
tab. Surface load errors instead of swallowing them.

## Acceptance

- [ ] The Variables tab lists the tenant's variables from the mounted endpoint.
- [ ] The History tab shows portal activity for the tenant, or is removed.
- [ ] A failed load shows an error state, not an empty list.
- [ ] A component test covers both tabs and fails against the old paths.
- [ ] No file outside `scope` is modified.
