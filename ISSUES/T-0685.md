# T-0685 — Backups API: list, create, download, delete

## Report

EPIC-035 SPEC.md §6 defines `GET`/`POST /v1/backups`, `GET /v1/backups/{id}/download`, and
`DELETE /v1/backups/{id}`; §3.1 lists the table columns and row actions these back. §7 requires
`backup.read`/`backup.write` and tenant-scoped visibility; §8 requires every backup operation to
be audited.

Deliver `portal/bff/src/routes/backups.ts`: list (cursor-paginated, tenant-filtered by RBAC),
create (dispatch instance or tenant collection), download (stream the archive artifact from the
artifact tier — never buffer it), and delete (remove artifact + row, audited). Update
`portal.v1.yaml` to match exactly. RBAC enforcement itself is owned by EPIC-038; this ticket
enforces the permission seam by contract and stubs it in tests.

## Acceptance

- [ ] All four endpoints are implemented and match the OpenAPI document.
- [ ] Listing is tenant-scoped and paginated; a caller cannot see another tenant's backup.
- [ ] Download streams the archive without loading it wholly into memory.
- [ ] Create and delete write audit events.
- [ ] No file outside `scope` is modified.
