# T-0904 — Implement or retire the token-refresh system timer

## Report

T-0876 found that the `token-refresh` system timer (`portal/bff/src/scheduler/system-timers.ts`)
names `Invoke-TokenRefresh`, which no worker or runner implements. It used to be enqueued as a
`assessment` job that no runner could execute, so every tick threw 501. T-0876 marked it
`unavailableReason`, so it is now listed as disabled and skipped.

Tenant credentials are certificate-based, so there may be no token to refresh. Decide whether this timer should check credential and certificate expiry instead (overlaps T-0874) or be removed, then implement that decision.

Then remove `unavailableReason` from the timer so the tick runs it again.

## Acceptance

- [x] The behaviour described in the report is implemented and the timer runs on its cron.
- [x] A test covers the timer's run and fails without the fix.
- [x] No file outside `scope` is modified.

## Fix

Retired the timer rather than implementing it. Credentials are certificate-based (there is no
OAuth token to refresh), and credential/certificate expiry is the domain of the scheduled
credential-expiry scan (T-0874). The timer is removed from `SYSTEM_TIMERS`, which also drops
it from `/v1/schedules/system` and removes `Invoke-TokenRefresh` from the allowed schedule
commands; EPIC-007 SPEC §4.1 records the decision.
