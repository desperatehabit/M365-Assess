# T-0703 — Pack run service and API (list packs, run, get report)

## Report

EPIC-036 SPEC.md §2 US-1/US-2, §4.1, and §6 define: select a pack and tenant, expand the pack to
its checks, run them through the assessment engine (EPIC-003), score per the pack definition, and
store a `TestRun`; `GET /v1/test-packs`, `POST /v1/test-packs/{id}/run`, and
`GET /v1/test-runs/{id}` expose it. §8 confirms standard packs never write to tenants.

Deliver `run.ts`: expand the T-0701 catalogue entry to its check ids, request the engine run
through the existing create-run API (T-0043), collect results, score with T-0701's shared
normalization, and persist the TestRun (T-0702). Deliver `routes/test-packs.ts` for the three
endpoints (tenant-scoped, `tests.read`/`tests.run` seam) and update `portal.v1.yaml`.

## Acceptance

- [ ] Listing returns the available packs with description and check count.
- [ ] Running a pack produces a scored `TestRun` for the tenant by reusing the engine (no duplicated check logic).
- [ ] The report endpoint returns per-control results and the score.
- [ ] A pack run performs no tenant write.
- [ ] No file outside `scope` is modified.
