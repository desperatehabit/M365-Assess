# T-0041 — Extend the Run model with parent/child runs and options

## Report

EPIC-003 SPEC.md §5 extends the EPIC-001 `Run` entity with `options`, `summaryCounts`, and
`parentRunId`, fixing the status taxonomy `queued | running | succeeded | failed | partial |
cancelled`. Resolved §11.1 adopts **parent `Run` with per-tenant child `Run` rows
(`parentRunId`)** so bulk runs are addressable as a unit and individually. §4.6 and resolved
§11.5 require retention to follow `03-database.md` §7 (configurable retention for runs,
artifacts, and audit events).

Deliver migration `0003_runs.sql` adding `parentRunId`, `options`, and the status/summary
columns, plus repository methods to create a parent with children, query children by
`parentRunId`, and enforce the retention window. No route or UI code belongs here.

## Acceptance

- [ ] Migration 0003 applies after 0002, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository creates a parent run with child runs and resolves children by `parentRunId`.
- [ ] Run status is constrained to the six-value taxonomy; a test rejects an unknown status.
- [ ] A test proves retention pruning follows the configured window and keeps audit rows.
- [ ] No file outside `scope` is modified.
