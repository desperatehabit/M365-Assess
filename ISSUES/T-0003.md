# T-0003 — Orchestrator builds and threads a RunContext

## Report

The main orchestrator reads and writes process-global run state named in
`01-architecture.md` §4 (`$global:M365AssessRegistry`, `$global:CheckProgressState`,
`$global:AdoptionSignals`) and passes the ~20 implicit caller-scope variables that
`Connect-RequiredService.ps1` consumes. EPIC-001 SPEC.md §4.1 requires this state to move into
`$ctx` with the CLI unchanged from a user's perspective (SPEC §10: "No new `$global:`/`$script:`
run state outside `RunContext`").

Deliver:

- `Invoke-M365Assessment` constructs one RunContext per invocation from its existing
  parameters and passes it to `Connect-RequiredService -Context` and to collectors.
- Orchestrator-owned globals are read/written through `$ctx`; no new `$script:`/`$global:`
  run state is added.
- CLI output, section selection, output-folder layout, and exit behavior are byte-identical to
  today for existing callers.

## Acceptance

- [ ] `Invoke-M365Assessment` builds exactly one RunContext per run and threads it downward.
- [ ] No orchestrator `$global:`/`$script:` run state remains outside `$ctx`.
- [ ] Existing `tests/Invoke-M365Assessment.Tests.ps1` passes unchanged.
- [ ] A test asserts the CLI path produces the same section set / output folder as before.
- [ ] No file outside `scope` is modified.
