# T-0406 — Template deploy with variables and partial-failure reporting

## Report

EPIC-021 SPEC.md §2 (US-2, US-4), §3.3, §4.2, §9, and §10 require deploying a transport-rule or
connector template to a tenant/group with **variable substitution** (domains, IPs, action
overrides), a plan showing the resolved rule/connector JSON, and **partial failures reported per
target**. §9 risk "template drift across tenants" is mitigated by versioned templates plus a
deploy diff.

Deliver `domain/transport/template-deploy.ts`, which resolves a template plus its declared
variables, validates that every required variable is supplied, and produces the resolved payload
and a per-target diff. Add the `POST .../deploy` handlers on `transport-rule-templates.ts` and
`connector-templates.ts` and the `Deploy-TransportTemplate.ps1` worker job plus
`deploy-transport-template.ps1` entrypoint. Each apply routes through the EPIC-006 gate (T-0107),
captures before/after, and writes an `AuditEvent`; one target's failure does not abort the others,
and the per-target result is returned. A missing required variable is a validation error, not a
partial apply.

## Acceptance

- [ ] Deploy resolves variables into the rule/connector JSON and shows the plan before apply.
- [ ] A missing required variable is rejected before any target is touched.
- [ ] A failure on one target is reported per target without aborting the rest.
- [ ] Every apply routes through the EPIC-006 gate and writes an `AuditEvent`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
