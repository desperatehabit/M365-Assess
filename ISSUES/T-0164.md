# T-0164 — Drift read API, breakdown, and refresh

## Report

EPIC-009 SPEC.md §6 fixes the drift read surface: `GET /v1/drift/{tenantId}` returns deviations
plus the state breakdown, `POST /v1/drift/{tenantId}/refresh` recomputes now, and
`GET /v1/drift/alignment` serves the shared alignment views (US-2). §3.1's breakdown card counts
by state (`open`, `accepted`, `customer specific`, `denied`, `delete pending`), and §3.3 shares the
alignment report with EPIC-008 and adds the "extra policies not in template" dimension.

Deliver the read/refresh/alignment handlers and update the OpenAPI document. Reads require
`drift.read`, tenant-scoped via `UserScope` through the EPIC-001 T-0013 RBAC seam (prose). The
alignment view reuses the EPIC-008 T-0148 alignment contract.

## Acceptance

- [ ] `GET /v1/drift/{tenantId}` returns deviations and a breakdown by state.
- [ ] `POST /v1/drift/{tenantId}/refresh` recomputes and upserts without clearing triage state.
- [ ] `GET /v1/drift/alignment` includes the extra-policy dimension; endpoints match OpenAPI.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
