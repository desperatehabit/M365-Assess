# T-0401 — Transport rules read API

## Report

EPIC-021 SPEC.md §2 (US-1), §3.1, §5, and §6 require `GET /v1/tenants/{id}/transport-rules` to
list transport rules with name, priority, state, conditions, actions, exceptions, and last
modified. §5 states rules are **read live from EXO**, so nothing is persisted.

Deliver the `Get-TransportRules` worker job plus `get-transport-rules.ps1` entrypoint reading the
job envelope (T-0007) through the EPIC-001 worker/queue path (T-0010) with child-process
credential materialization (T-0011), reusing the EPIC-020 EXO base (T-0381). The BFF route
validates RBAC `transport.read` and tenant scope and serves cursor-paginated rows; extend
`portal.v1.yaml`. Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] `GET /v1/tenants/{id}/transport-rules` returns the §3.1 columns with cursor pagination.
- [ ] The worker performs no tenant write and the BFF route holds no M365 SDK call.
- [ ] Rules read live from EXO; no transport-rule state is persisted.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
