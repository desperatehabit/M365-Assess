# T-0464 — Message viewer: delivery timeline, headers, and gated body

## Report

EPIC-024 SPEC.md §2 US-3, §3.3, and §4.1 define the message viewer: given a trace/search result,
show the full delivery timeline (events, connectors, filters hit) and headers, read-only. §6
exposes `GET /v1/tenants/{id}/mail/messages/{messageId}`. §11 item 2 is resolved (adopted):
metadata + headers first, with the message body behind a **higher permission**. §9 names the
privacy-exposure risk and requires high privilege plus auditing for every read.

Deliver a `Get-MessageDetail.ps1` handler (entrypoint `get-message-detail.ps1`) returning
delivery events, connectors, filters hit, and headers, plus the body only when the caller holds
the elevated `mailtools.content` permission; otherwise the response omits the body and reports
it as gated. The route validates `mailtools.read`, tenant scope, and writes an audit record for
every read. Add the read-only `MessageViewer` component. Extend `portal.v1.yaml`.

## Acceptance

- [ ] The viewer renders delivery events, connectors, filters hit, and headers.
- [ ] The body is returned only with `mailtools.content`; otherwise it is reported as gated.
- [ ] Every message read writes an audit record and is tenant-scoped.
- [ ] A test covers both the gated and ungated responses and fails without it.
- [ ] No file outside `scope` is modified.
