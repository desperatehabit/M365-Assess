# T-0566 — Notification channel configuration API and test-send

## Report

EPIC-029 SPEC.md §2 US-5 and §3.4 define the **Notifications** page: configure channels (email
recipients, webhook URLs, PSA connection, Slack) with per-channel enablement and test-send. §6
fixes `GET`/`PUT /v1/notifications` and `POST /v1/notifications/test`.

Deliver the channel-configuration routes over `NotificationConfig` (T-0561) behind RBAC
`alerts.write` for writes and `alerts.read` for reads, wiring the test-send to the T-0565 adapters
so a test send exercises the real adapter without recording an `AlertEvent`. PSA/Slack are exposed
in the schema but return a structured "not yet supported" error (PSA deferred to EPIC-041). Extend
`portal.v1.yaml`. Update of a channel target is audited and secrets remain referenced, not stored.

## Acceptance

- [ ] `GET /v1/notifications` lists channels with enabled state; `PUT` updates a channel's config.
- [ ] `POST /v1/notifications/test` performs a real send via the T-0565 adapter and does not record an event.
- [ ] PSA and Slack return a structured not-supported error rather than failing silently.
- [ ] Channel config changes write an audit event; no secret value is returned.
- [ ] A test covers config and test-send and fails without the code.
- [ ] No file outside `scope` is modified.
