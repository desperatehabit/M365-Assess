# T-0229 — Per-user MFA action dialogs

## Report

EPIC-012 SPEC.md §3.2 (US-2, US-3, US-4, US-5): `ActionDialog`s for **Reset MFA** (warns that
methods are removed and re-registration is required), **TAP** (lifetime, one-time-use toggle,
start time; shows the pass once with a copy control and a "this will not be shown again"
warning), **Send push** (targets a registered device), and **Default method** (select from
registered methods). Extend the `mfaApi.ts` client from T-0228 with the T-0222/T-0223/T-0224
calls.

Reset and bulk confirmation follow the EPIC-006 confirmation pattern (count, required reason, and
batch confirmation where more than one user is affected). The TAP result is rendered once in the
dialog and never persisted client-side beyond the session.

## Acceptance

- [ ] Each dialog posts to its endpoint and renders inline success/failure per action.
- [ ] Reset requires confirmation with a reason; a batch reset shows a second count confirmation.
- [ ] The TAP value is shown once with a copy control and a warning that it will not be shown again.
- [ ] Default-method choices are limited to the user's registered methods.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
