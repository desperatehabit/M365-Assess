# T-0529 — Mailbox and calendar permission report

## Report

EPIC-027 SPEC.md §2 US-5, §3.5, and §6 define the mailbox-permissions surface: **reuse
EPIC-020's mailbox/calendar permission reports in the sharing/permissions context**. §6 exposes
`GET /v1/tenants/{id}/mailbox-permissions`. This epic owns only the read-only report view; the
underlying mailbox-permission collection depends on the mailbox epic (EPIC-020), which is not yet
authored — this ticket declares the shared read contract and a thin adapter so the report renders
when EPIC-020 lands (describe the cross-epic dependency in prose; do not add a `depends_on` on an
unauthored epic).

Deliver a `Get-MailboxPermissions.ps1` handler (entrypoint `get-mailbox-permissions.ps1`) that
reads mailbox and calendar permissions and returns a `ResultEnvelope`, plus the read route
validating `sharing.read` and tenant scope with pagination, and the page rendering
`MailboxPermissionsTable` in the sharing context. This ticket performs no writes. Extend
`portal.v1.yaml`.

## Acceptance

- [ ] `GET /v1/tenants/{id}/mailbox-permissions` returns mailbox and calendar permissions, paginated.
- [ ] The report renders in the sharing/permissions context and is read-only.
- [ ] A caller without `sharing.read` is refused; results are tenant-scoped.
- [ ] A test covers listing and the EPIC-020 adapter seam and fails without it.
- [ ] No file outside `scope` is modified.
