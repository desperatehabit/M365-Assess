# T-0584 — Retention policy read and change API

## Report

EPIC-030 SPEC.md §2 US-2 and §3.2 define **Retention Policies** (Name · State · Locations ·
Retention period · Disposition) with row actions `View`, `Edit`, `Enable/Disable`, `Clone to
template`, `Delete`. §6 fixes `GET`/`POST`/`PATCH`/`DELETE /v1/tenants/{id}/purview/retention`.
§11.1 is resolved to ship retention in the **first wave** alongside DLP and Safe Links. §8 requires
writes through EPIC-006 with a compliance warning on disable.

Deliver a read worker (reusing the T-0582 Purview session seam) and the BFF read + change routes
behind `purview.read`/`purview.write`, applying changes through the EPIC-006 gated path (T-0108).
Disable/delete is flagged compliance-impacting and records `CompliancePolicyChange` (T-0581). No
direct Purview write bypasses EPIC-006.

## Acceptance

- [ ] `GET /v1/tenants/{id}/purview/retention` returns the §3.2 columns, paginated and tenant-scoped.
- [ ] Create/edit/enable/disable/delete apply only through the EPIC-006 gated path.
- [ ] Disabling a retention policy warns before apply and records an audit + change row.
- [ ] The worker reuses the shared Purview session seam and is read-only.
- [ ] A test covers read and change gating and fails without the code.
- [ ] No file outside `scope` is modified.
