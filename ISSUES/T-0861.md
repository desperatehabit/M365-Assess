# T-0861 — Mount and deliver EPIC-031 Secure Score routes

## Report

The EPIC-031 factories (`createSecureScoreRoutes`, `createSecureScoreFleetRoutes`,
`createSecureScorePeersRoutes`, `createSecureScoreTrendRoutes`) exist under `portal/bff/src/routes/`
and are tested, but `portal/bff/src/app.ts` imports none of them and there is no adapter under
`portal/bff/src/adapters/`, so the endpoints 404. `get-secure-score.ps1` and migration
`0039_secure_score.sql` exist.

Functional gaps:

- The improvement-action → check/standard mapping is never applied:
  `portal/bff/src/routes/secure-score.ts:137-141` returns `check: null, standardKey: null`
  unconditionally, while `portal/bff/src/domain/secure-score/mapping.ts:132` (`deriveActionCheckMap`)
  and `:294` (`persistResolvedMapping`) have no non-test callers (SPEC §3.1, §3.4, §10).
- Daily snapshot scheduling is not registered anywhere: `Invoke-SecureScoreSnapshot.ps1` exists but
  no scheduler or route invokes it (only `secure-score-trend.ts:185` references `recordSnapshot`).

## Acceptance

- [x] Every EPIC-031 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Improvement actions resolve to a registry check/standard through the mapping module.
- [x] A daily snapshot job is registered and records trend points.
- [x] No file outside `scope` is modified.

## Fix

`createSecureScoreProviders` binds the read path to the existing `get-secure-score.ps1`
worker; the same provider backs the current, peers, and trend routes. `createApp` mounts
all four route groups behind `resolveCaller`, the shared authorizer, and the snapshot
repository over migration 0039; the fleet route builds its snapshot table from the
tenant store filtered to the caller's scope.

The current-score route now accepts an optional `SecureScoreActionMapping`. The wiring
passes `resolveFixTarget` (the shipped registry derivation plus `mapping-overrides.json`),
so `check`/`standardKey` are populated where a mapping exists and stay null honestly when
none does. Every mapped target is persisted through `persistResolvedMapping`, which writes
the `ScoreActionMapping` row and its audit event, giving both previously uncalled mapping
functions a production caller.

A `secure-score-snapshot` system timer (daily, 01:00 UTC) rides the `maintenance` job type
and dispatches `Invoke-SecureScoreSnapshot`. The command reads each included tenant's score
through the same provider, records one snapshot, and prunes the 90-day retention window;
the PowerShell handler's List/Record/Prune seams are scriptblocks a child process cannot
receive from the BFF, so the command performs those portal-local writes around the same
read path. All endpoints are registered in the EPIC-038 permission registry, published
through their OpenAPI fragments, and the checked-in contract is regenerated.
