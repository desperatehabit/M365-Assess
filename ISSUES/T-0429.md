# T-0429 — Spamfilter, quarantine, and allow/block UI

## Report

EPIC-022 SPEC.md §3 fixes the UI under *Email & Exchange → Spamfilter* and
*Administration → Quarantine, Allow/Block Lists*: the **Spam Filter**, **Anti-Phishing**,
**Malware Filter**, and **Connection Filter** pages (§3.1), **Filter Templates** (§3.2),
**Quarantine** with its tabs and bulk actions (§3.3), **Tenant Allow/Block Lists** (§3.4), and
**Quarantine Policies** (§3.5). Theme per `02-ui-design.md`.

Deliver the Next.js pages above using the read APIs (T-0421) and write routes (T-0422–T-0428):
the filter policy editor with plan preview and disable warnings, the template deploy form, the
quarantine table with preview/release/delete/submit and the capped bulk confirmation (T-0425), the
allow/block editor with expiry, and the quarantine-policy editor. Per the deferred §11.4
disposition, the **User Reported** tab is not shipped in v1. No browser call reaches a tenant
directly.

## Acceptance

- [ ] Filter pages render the §3.1 columns and row actions from the BFF.
- [ ] Quarantine renders the §3.3 columns, filters, actions, and capped bulk confirmation; the User Reported tab is absent.
- [ ] Allow/block and quarantine-policy pages render and act through the BFF.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
