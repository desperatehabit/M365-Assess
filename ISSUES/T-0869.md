# T-0869 — Mount EPIC-039 Template Library & Catalog routes

## Report

The EPIC-039 route factories are defined outside `portal/bff/src/routes/`, under
`portal/bff/src/templates/`: `createLibraryRoutes` (`templates/library-routes.ts:68`),
`createTemplateRepoRoutes` (`templates/repo-routes.ts:100`),
`createPackageRoutes` (`templates/package-routes.ts:83`),
`createCloneRoutes` (`templates/clone-routes.ts:63`), and the GitHub save route
(`templates/save-to-github.ts:279`). None is imported by `portal/bff/src/app.ts`, and there is no
adapter wiring `portal/db/src/template-repository.ts`, so every SPEC §6 endpoint 404s.

Migration `0050_template_library.sql` covers the entities; `app/templates/page.tsx` and
`app/catalog/page.tsx` exist. The Template Package Manager page (SPEC §3.5) is missing — no page
matches `app/**/*package*`.

## Acceptance

- [x] Every EPIC-039 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Template library, repo, clone, package, and save-to-GitHub routes persist through SQLite.
- [x] The Template Package Manager page exists and renders live data.
- [x] No file outside `scope` is modified.

## Fix

The five EPIC-039 route factories were mounted in `createApp`. A new
`adapters/templates.ts` binds library, repo, clone, and package work to the
existing `SqliteTemplateRepository` and bridges save-to-GitHub onto the
EPIC-041 GitHub adapter; the service fails closed with a 409 until the
integration row is enabled. The repo OpenAPI fragment is published through the
shared document and every endpoint was added to the permission registry.
`app/templates/package/page.tsx` adds the Template Package Manager with live
import/export/list wiring. `app-epic039-mounts.test.ts` probes every endpoint
through the real app and proves package/repo persistence and clone planning.
