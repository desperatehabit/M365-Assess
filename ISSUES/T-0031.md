# T-0031 — Add-tenant wizard UI

## Report

EPIC-002 SPEC.md §3.3 defines the add-tenant `Wizard` (per `cipp-ui-patterns.md` §4) with six
steps: setup method
(create app + consent / existing app / manual credentials / import from GDAP); tenant
(validated via `Resolve-TenantIdentity`); credentials (method-specific, environment
commercial/gcc/gcchigh/dod); groups & variables; test connection (per-service pass/fail); and
confirmation (gated, audited). The onboarding step must surface the same confirmation as the
`ConfirmImpact: High` setup cmdlet and never call it `-Force` unconfirmed (SPEC §8).

Deliver the wizard route and component, wiring the onboarding step to the T-0025 route, the
test-connection step to the T-0024 endpoint, and credential entry to the T-0023 API. Use report
theme tokens only; no colour literals.

## Acceptance

- [ ] All six steps render and validate; the tenant step resolves the tenant identity.
- [ ] The confirmation step gates onboarding and surfaces the high-impact confirmation.
- [ ] Test-connection shows per-service pass/fail inline; a test covers the step transitions.
- [ ] No file outside `scope` is modified.
