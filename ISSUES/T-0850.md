# T-0850 — Mount and deliver EPIC-020 Mailboxes routes with real storage

## Report

`portal/bff/src/routes/{mailboxes,mailbox-write,mailbox-settings,mailbox-permissions,mailbox-reports,
mailbox-rules,mailboxes,retention,vacation-schedules,deleted-mailboxes}.ts` define the SPEC §6
endpoints, but none of their factories (`createMailboxRoutes`, `createMailboxWriteRoutes`,
`createMailboxSettingsRoutes`, `createMailboxPermissionRoutes`, `createMailboxReportsRoute`,
`createMailboxRuleRoutes`, `createRetentionRoutes`, `createVacationScheduleRoutes`,
`createDeletedMailboxRoutes`) is imported by `portal/bff/src/app.ts`; a repo-wide search finds each
only in its own file or tests. `portal/bff/src/adapters/` has no mailbox provider, so every endpoint
404s. The backing workers exist (`get-mailboxes.ps1`, `get-mailbox-permissions.ps1`, `set-mailbox*.ps1`,
`set-mailbox-rule.ps1`, `set-retention-tag.ps1`, `invoke-vacation-schedule.ps1`, `restore-mailbox.ps1`).

UI gaps beyond mounting (SPEC §3.7, §10): no page or component calls
`GET /v1/tenants/{id}/mailbox-reports` (route exists at `mailbox-reports.ts`); the Deleted Mailboxes
view (§11.4) has no page though `deleted-mailboxes.ts` exists.

## Fix direction

Add a mailbox adapter on `runFeatureWorker`, mount the route groups in `app.ts`, then add the
mailbox/mail-flow reports and Deleted Mailboxes surfaces to the existing `app/email/` tree.

## Acceptance

- [ ] Every EPIC-020 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [ ] Mailbox reads/writes, permissions, rules, retention, and vacation schedules run their real workers.
- [ ] The mailbox/mail-flow reports page and the Deleted Mailboxes view exist and render live data.
- [ ] A test covers each mounted route and fails without the mount.
- [ ] No file outside `scope` is modified.
