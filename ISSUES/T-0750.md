# T-0750 — Access audit of every allow/deny and /v1/access/check

## Report

EPIC-038 SPEC.md §4.5 and §3.4: every allow/deny writes an `AuditEvent` with `actorType`, role(s),
permission, tenant, result, IP, and correlation ID; append-only; surfaced in the Logbook view
(EPIC-037). SPEC.md §6 adds `POST /v1/access/check`, a UI preflight that evaluates a permission
for the caller.

Build `access-audit.ts` as the single writer every authorization decision calls — both the
`Test-PortalAccess` path (T-0743) and the tenant-scope denial path (T-0746) — recording the
decision shape above. Build the `access.ts` route exposing `POST /v1/access/check` for the UI
(T-0752) so buttons can preflight rather than guess. Extend `portal.v1.yaml`. Audit rows must be
append-only; export to SIEM remains EPIC-041.

## Acceptance

- [ ] Every allow and every deny writes an `AuditEvent` with the §4.5 fields.
- [ ] `POST /v1/access/check` returns the same decision the endpoint would enforce.
- [ ] Audit rows are append-only.
- [ ] A denied request is audited from both the RBAC and the scope path.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
