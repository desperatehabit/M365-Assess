# T-0623 — Saved search CRUD, re-run, and scheduling

## Report

EPIC-032 SPEC.md §3.2 defines the **Saved Log Searches** table (Name, Filter summary, Last run,
Schedule, State) with row actions `Run`, `Edit`, `Schedule`, `Delete`, and §6 exposes
`GET`/`POST`/`PATCH`/`DELETE /v1/tenants/{id}/audit/searches`. §4.1 step 2: "A saved search
stores the filter and can be scheduled (EPIC-007)". The `AuditSearch.scheduleId` field (SPEC §5)
links to a `Schedule` row.

Deliver the CRUD routes plus a `Run` action that re-dispatches the T-0622 search job and updates
`lastRunAt`, storing the filter as JSON and validating it against the §3.1 filter shape. The
`Schedule` action creates or updates an EPIC-007 schedule through T-0124 (prose cross-ref) and
stores its id; mutations write an `AuditEvent`. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Create, read, update, and soft-delete of a saved search work, with the filter persisted
      and re-usable by `Run`.
- [ ] `Run` dispatches the T-0622 job and updates `lastRunAt`; `Schedule` records a valid
      `scheduleId` and rejects an unknown one.
- [ ] Mutations write an `AuditEvent`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
