# T-0425 — Bulk quarantine release and delete with a cap

## Report

EPIC-022 SPEC.md §3.3, §4.2, §8, and §9 require bulk release/delete with confirmation, and §9
risk "quarantine volume" is mitigated by filters, pagination, and bulk actions. Resolved §11.2
adopts **a capped bulk action with explicit confirmation**.

Deliver `domain/quarantine/bulk.ts` with the per-action cap, the selection validation (a batch
over the cap is rejected, not silently truncated), and the confirmation count model. Add
`quarantine-bulk.ts` for the bulk routes and the `Invoke-QuarantineBulk.ps1` worker job plus
`invoke-quarantine-bulk.ps1` entrypoint. Each item is released/deleted through the EPIC-006 gate
(T-0107) with a `QuarantineAction` (T-0424) and an `AuditEvent`; a failure on one message is
reported per message without aborting the rest. Extend `portal.v1.yaml`.

## Acceptance

- [ ] A bulk request over the configured cap is rejected before any release or delete.
- [ ] Bulk release/delete shows the confirmation count and proceeds only on confirm.
- [ ] Each item is audited with actor, message, and recipient; one failure does not abort the batch.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
