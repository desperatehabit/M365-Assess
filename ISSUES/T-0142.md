# T-0142 — StandardTemplate, TemplateAssignment, and three-tier resolution

## Report

EPIC-008 SPEC.md §5 defines `StandardTemplate` (`id`, `name`, `kind(standards|drift)`,
`actions{report,alert,remediate}`, `autoRemediate`, `settings[]`, `scheduleId`) and
`TemplateAssignment` (`templateId`, `targetType(allTenants|group|tenant)`, `targetId`,
`precedence`). §4.1 (`Get-Standards`) requires a **three-tier merge**: AllTenants → Tenant Group
→ Tenant-specific, **later wins per-setting**, matching CIPP's `Get-CIPPStandards`.

Deliver the migration (`0007`), the repository persistence for both entities, and
`standards-resolve.ts` resolving the effective standards for a tenant. Resolution must be
deterministic: within a tier, the higher `precedence` wins; a missing per-setting value falls
through to the lower tier. No routes or UI here.

## Acceptance

- [ ] `StandardTemplate` and `TemplateAssignment` persist with the §5 fields and the `standards|drift` kind.
- [ ] Three-tier resolution returns the effective per-tenant standards with tenant-specific winning over group over all-tenants, per setting.
- [ ] Two assignments in the same tier resolve deterministically by `precedence`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
