# T-0441 — ContactTemplate persistence and repository methods

## Report

EPIC-023 SPEC.md §5 and §9 fix the data model: contacts and resources are read live from EXO,
but `ContactTemplate` persists with fields `id`, `name`, `properties`, `variables`, and every
write emits an `AuditEvent`. ADR-0015 and `03-database.md` §5 require numbered, forward-only
migrations behind the repository interface, and `03-database.md` §4 keeps secrets out of data
tables (templates carry no credential material).

Deliver migration `0031_contact_templates.sql` extending the `0001_init` schema (the next free
number below is claimed elsewhere, so this file must not reuse a lower number), plus
list/get/upsert/soft-delete methods on `portal/db/src/repository.ts` and
`sqlite-repository.ts`. `properties` and `variables` are stored as JSON text; no raw SQL may
appear outside `portal/db/`. This ticket adds no routes and no worker code.

## Acceptance

- [ ] Migration 0031 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes `ContactTemplate` list/get/upsert/soft-delete; templates are tenant-scoped.
- [ ] A test proves `properties`/`variables` round-trip and that no column stores a secret value.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
