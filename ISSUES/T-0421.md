# T-0421 — Spam, anti-phish, malware, and connection filter read API

## Report

EPIC-022 SPEC.md §2 (US-1), §3.1, §5, and §6 require `GET /v1/tenants/{id}/filters/{type}` for the
spam, anti-phish, malware, and connection filter policies, with name, priority, state, key
settings summary, and last modified. §5 states filter policies are **read live from EXO**, so
nothing is persisted. The module already assesses these areas
(`DefenderAntiSpamChecks`, `DefenderAntiPhishingChecks`, `Get-ExoSecurityConfig`); reuse their
read logic where it fits.

Deliver the `Get-Filters` worker job plus `get-filters.ps1` entrypoint reading the job envelope
(T-0007) through the EPIC-001 worker/queue path (T-0010) with child-process credential
materialization (T-0011), reusing the EPIC-020 EXO base (T-0381). The BFF route validates RBAC
`spam.read` and tenant scope; extend `portal.v1.yaml`. Tenant and credential records are EPIC-002
(prose dependency).

## Acceptance

- [ ] `GET /v1/tenants/{id}/filters/{type}` returns the §3.1 columns for all four filter types.
- [ ] The worker performs no tenant write and the BFF route holds no M365 SDK call.
- [ ] Filter policies read live from EXO; no filter state is persisted.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
