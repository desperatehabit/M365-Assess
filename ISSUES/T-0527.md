# T-0527 — Bulk sharing-link removal with plan preview

## Report

EPIC-027 SPEC.md §2 US-4, §3.4, §4.2, and §8 define bulk removal: select links → **plan
preview** (what will be removed) → confirm (naming the count) → apply. It is high blast radius
and requires `sharing.write` + `Remediation.Apply` semantics. §6 exposes `POST
/v1/tenants/{id}/sharing/links/remove`; each removal is audited (§4.2) with before/after routed
through **EPIC-006** (§8). §11 item 3 is resolved (adopted): v1 removes **links (anonymous and
organization) first**, with direct-permission removal deferred.

Deliver a `Remove-SharingLinks.ps1` handler (entrypoint `remove-sharing-links.ps1`) with a plan
mode that returns exactly which links will be removed and an apply mode that executes through
the EPIC-006 gated executor (T-0108), recording a `LinkRemovalJob` (T-0526) with per-link
results. The route validates `sharing.write` + `Remediation.Apply`, requires an explicit
confirmation naming the count, and audits each removal. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Plan mode returns the exact set of links to be removed and performs no writes.
- [ ] Apply mode requires a confirmation naming the count and refuses without it.
- [ ] Every removal is audited; a `LinkRemovalJob` records per-link results with no silent partial success.
- [ ] A test covers the plan preview, the confirmation gate, and per-link results and fails without it.
- [ ] No file outside `scope` is modified.
