# T-0879 — Baseline stage advance is not reachable from the UI

## Report

`portal/bff/src/routes/baselines-advance.ts:20` defines the stage-advance route and it is mounted,
but no caller exists: `portal/web/src/lib/baselinesApi.ts` has no advance function and no page under
`portal/web/src/app/baselines/` posts to it. EPIC-010 US-3 / SPEC §3.4 acceptance ("a tenant advances
a stage") is therefore unwired end-to-end. (The baselines list "Run now" action is also a no-op
notice at `app/baselines/page.tsx:365-369`, but no baseline-run endpoint is defined in SPEC §6, so
that is out of scope here.)

## Acceptance

- [ ] `baselinesApi.ts` exposes an advance call and a baselines page action invokes it.
- [ ] Advancing a tenant moves its rollout stage and is reflected in the UI.
- [ ] A client/route test covers the flow and fails without the wiring.
- [ ] No file outside `scope` is modified.

## Resolution notes

- `advanceBaselineStage(baselineId, stageOrder, tenantId)` in `portal/web/src/lib/baselinesApi.ts`
  POSTs `/v1/baselines/{id}/stages/{order}/advance` and returns the updated rollout.
- The baselines page renders a "Ready to advance" table from the fleet overview's `eligible`
  rollouts; the per-tenant button calls the endpoint, shows the new stage, and reloads the fleet.
- `baselinesApi.test.ts` covers the request shape and a 409, and the page test covers the click →
  POST → reload flow.
