# T-0664 — DNS analysis worker (MX/SPF/DKIM/DMARC/MTA-STS/TLS-RPT) with selector discovery

## Report

EPIC-034 SPEC.md §3.2 defines the per-domain DNS panel: MX records + target provider; SPF record,
lookup count, and `-all`/`~all` policy; DKIM selector1/selector2 presence and enabled state; DMARC
record, policy (`none`/`quarantine`/`reject`), rua/ruf, and alignment; MTA-STS / TLS-RPT presence
and policy. §4.2 says to resolve with the module's `Resolve-DnsRecord` and evaluate against
expected patterns.

Module ADR-0003 is directly load-bearing here: DNS checks run **last**, fed by the connect-time
prefetch and the prefetched accepted domains (`-AcceptedDomains`), and `.onmicrosoft.com` domains
are filtered at source because they cannot have public records by design. This ticket reflects
that contract: the worker consumes the prefetched accepted-domain list and never re-derives it
mid-run. Resolved §11.1 adopts DKIM selector discovery as **try the known selectors
(`selector1`/`selector2` plus common provider defaults) and allow a per-tenant selector
override**.

Build `Test-DomainDns.ps1` (evaluate records + produce `health`) and `DnsSelectors.ps1` (selector
resolution with override), plus a `check-domain-dns.ps1` entrypoint and the
`portal/contracts/src/dns.ts` result shape. Reuse the module's `Resolve-DnsRecord` /
`Get-DnsSecurityConfig` semantics; do not edit `src/**`.

## Acceptance

- [ ] The worker evaluates all six record families and returns a health result per domain.
- [ ] DKIM resolution tries the known selectors and honours a per-tenant override; a provider
      default selector is detected without a stored override.
- [ ] `.onmicrosoft.com` domains are excluded and the accepted-domain list is consumed from the
      prefetch per ADR-0003 (not re-fetched).
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
