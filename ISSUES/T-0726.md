# T-0726 — User preferences schema, repository, and API

## Report

EPIC-037 SPEC.md §2 US-4, §3.4, and §4.3 define **Preferences** (usage location, table page size,
table view mode, default test suite, persist filters, bookmarks, compact nav, theme/density/text
scale, portal links), stored per user in `UserPreference` (`userId`, `prefs`) and mirrored to
`localStorage` for first-paint theming; §6 defines `GET`/`PUT /v1/preferences`; §7 makes
preferences per-user (no `CIPP.AppSettings.*` gate).

Deliver migration `0113_preferences.sql` (keyed by user), a typed `preferences/schema.ts` (the same
typed-key discipline as T-0721), repository get/upsert scoped to the calling user, and
`routes/preferences.ts` for `GET`/`PUT`. The `localStorage` mirror is a web-side concern consumed
by the UI ticket (T-0728); this ticket exposes the canonical per-user record.

## Acceptance

- [ ] `GET`/`PUT /v1/preferences` persist and return only the caller's preferences.
- [ ] Preferences are validated against the typed schema; unknown keys are rejected.
- [ ] Migration `0113` applies, is re-runnable, and advances `SchemaVersion`.
- [ ] A test covers per-user isolation and fails without it.
- [ ] No file outside `scope` is modified.
