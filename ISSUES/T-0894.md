# T-0894 — Vacation schedules never enable or revert on their own; revert does not restore prior state

## Report

`createVacationScheduleRoutes` is mounted without a `scheduler`, and the EPIC-007 scheduler only runs its existing job types, so a future-dated schedule is stored but never enables or reverts. The worker revert clears forwarding and out-of-office outright instead of restoring what the mailbox had before, because pre-vacation state is never stored. Needs a design decision (scheduler job type vs worker-side timer), then: enable/revert on schedule, capture and restore prior state, tests.

## Acceptance

- [ ] The behaviour described in the report is fixed.
- [ ] A test covers it and fails without the fix.
- [ ] No file outside `scope` is modified.

## Resolution notes

- **Design decision:** keep the EPIC-007 scheduler path the route already encoded. The
  enable and revert rows are ordinary `scheduled_tasks` with `type: custom-script` and
  command `Invoke-VacationSchedule`, so they use the job type and runner added in T-0876.
- `app.ts` now passes a `VacationJobScheduler` backed by `SqliteScheduleRepository`
  (`createVacationJobScheduler`) to `createVacationScheduleRoutes`, so POST registers the
  enable/revert rows and End now disables them.
- The custom-script runner's handler map now carries `Invoke-VacationSchedule`
  (`createVacationScheduleCommand`). It runs the mailbox worker through the existing
  `VacationApplyProvider`, records the worker's audit event, moves the schedule to
  `active`/`ended`/`failed`, and disables both phase rows when the window ends.
- **Prior-state restore:** a successful enable now returns the worker's `plan.before`
  snapshot as `beforeState`. The route stores it on the revert row's `parameters.priorState`
  (both for an immediate start and for a scheduled enable via the command handler). The
  revert path — scheduled or End now — passes it to the worker, and
  `Invoke-VacationSchedule` restores the prior OoO state/message and forwarding instead of
  clearing them. A mailbox with no stored snapshot keeps the old clear behavior.
- Tests: `vacation-schedules.test.ts` covers snapshot carry-over, End-now restore, and the
  command handler's state/audit/disable behavior. `Invoke-VacationSchedule.Tests.ps1` covers
  the worker's restore path and reads `priorState` from the job envelope.
- Verification: vacation route tests 20/20, vacation worker tests 19/19 under Pester 5.7.1;
  the full BFF suite remains at its documented 21 pre-existing failures (no failures in the
  vacation, mailbox, or scheduler files).
