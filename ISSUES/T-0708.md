# T-0708 — Custom-test failure alert hand-off

## Report

EPIC-036 SPEC.md §2 US-5, §3.4, and §4.3: a failing custom test fires an alert carrying the
test's output, with delivery via EPIC-029. §6 leaves alerting to the existing notifications seam,
and §3.2 gives the `Enable/Disable alerts` toggle (T-0706).

Deliver `alerts.ts`: on a failed custom-test run (T-0707), when `alertsEnabled` is set, emit an
alert event through the EPIC-029 alerting seam including the test identity and rendered output;
do not implement delivery, channels, or dedupe (EPIC-029 owns those). The alerting epic is not yet
authored, so this ticket depends on its interface by contract and stubs it in tests.

## Acceptance

- [ ] A failed run with alerts enabled emits one alert event carrying the test output.
- [ ] A failed run with alerts disabled emits none; a passing run emits none.
- [ ] Delivery/channel logic is not implemented here.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
