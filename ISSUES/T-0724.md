# T-0724 — Branding API (GET/PUT), asset upload, and live preview

## Report

EPIC-037 SPEC.md §6 defines `GET`/`PUT /v1/branding`; §4.2 requires edit → **live preview** → save;
§3.2 requires a live preview that "renders the effect on a sample report/PDF"; §7 gates branding on
`CIPP.AppSettings.*` (EPIC-038); §9 warns branding uploads must be validated (T-0723). ADR-0016
consumes the config at render time (EPIC-005 T-0086).

Deliver `routes/branding.ts`: `GET` returns the config with resolved asset URLs, `PUT` validates
via the T-0723 schema, persists, and audits; an upload endpoint accepts a validated asset
(T-0723). Deliver `branding/preview.ts` producing the token-override CSS and cover/watermark/footer
fragments the live preview renders from a draft config (not saved) for a sample report, mirroring
the render-time injection contract T-0086 consumes. Update `portal.v1.yaml`.

## Acceptance

- [ ] `GET`/`PUT /v1/branding` are implemented and match the OpenAPI document; changes are audited.
- [ ] The preview endpoint returns CSS/fragments for an unsaved draft config without persisting it.
- [ ] An invalid upload is rejected through the T-0723 validation.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
