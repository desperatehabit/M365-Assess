# T-0858 — Mount and deliver EPIC-028 Incidents & Alerts routes and bulk triage

## Report

The EPIC-028 factories (`createIncidentsRoutes`, `createIncidentsDetailRoute`,
`createIncidentsActionsRoute`, `createAlertsRoutes`, `createAlertActionsRoute`,
`createCheckAlertsRoutes`) exist under `portal/bff/src/routes/` and are tested, but
`portal/bff/src/app.ts` imports none of them and there is no adapter under `portal/bff/src/adapters/`,
so the endpoints 404. Workers (`get-incidents.ps1`, `get-incident-detail.ps1`,
`invoke-incident-action.ps1`, `get-alerts.ps1`, `invoke-alert-action.ps1`) and migration
`0055_incident_triage.sql` exist.

UI gap (SPEC §3.1, §10): the incidents list builds URLs of the form
`/incidents/{id}?action=...&bulk=...` (`app/incidents/page.tsx:134-139`), but the detail page ignores
the `bulk` parameter and `components/incidents/BulkTriageDialog.tsx` is referenced only by
`IncidentDetail.test.tsx`. Bulk triage with confirmation is therefore non-functional.
`app/alerts/page.tsx:195` already renders `CheckAlertsPanel`.

## Acceptance

- [x] Every EPIC-028 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] Incident detail, triage (accept/override/deny/bulk), and alert actions run real workers.
- [x] Bulk triage is wired end to end and shows a confirmation before applying.
- [x] No file outside `scope` is modified.

## Fix

`portal/bff/src/adapters/incidents.ts` binds the six factories to the workers:
`get-incidents.ps1` and `get-alerts.ps1` through `createTenantWorker` (flat job fields),
`invoke-incident-action.ps1` and `invoke-alert-action.ps1` through the T-0007 envelope
worker, and `get-incident-detail.ps1` with the tenant's `IncidentNote` and
`AlertStateChange` rows merged in. The alert action adapter translates the worker's
`alerts.unsupported_action` error into the route's `unsupported` result, so a
non-promotable create-incident is a 400 rather than a 502. `/v1/check-alerts` reads each
included tenant's latest finished run and serves its non-passing findings, guarded by
`Security.Incident.Read`.

All seven endpoints are mounted in `createApp`, registered in the permission registry,
and published through the EPIC-028 OpenAPI fragments; `portal.v1.yaml` is regenerated.
`app-epic028-mounts.test.ts` probes every group through the real app.

Bulk triage is now end to end: the list page carries each selected incident's tenant with
its id, the detail page renders `BulkTriageDialog` and posts one confirmed request per
tenant with `incidentIds` plus `confirm: true`. The orphaned-dialog gap is closed. The
alerts list no longer navigates to a nonexistent `/alerts/{id}` page: View shows a detail
panel and the write actions open `AlertTriageDialog`, which drives the real action route.
