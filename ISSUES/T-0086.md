# T-0086 — Branding injection at render time

## Report

EPIC-005 SPEC.md §4.4: branding (colours, logo, cover, watermark, footer, page numbers) is
applied **at render time** from the instance `BrandingConfig`, with per-report-type defaults.
ADR-0016 says branding "is a render-time injection, not a separate template set" and is injected
into the HTML before Chromium prints it. §5 delegates `BrandingConfig` to EPIC-037.

Deliver:

- `Get-BrandingStyles.ps1`: reads a `BrandingConfig` (via a read interface; the storage and CRUD
  belong to EPIC-037, not this ticket) and produces the token-override CSS plus cover/watermark
  and footer/page-number fragments.
- A hook in `Invoke-ReportRender.ps1` (T-0082) that injects the branding into the HTML prior to
  rendering; per-report-type defaults select the config.
- Pester tests asserting the injected CSS variables and cover/footer fragments for a stub config,
  and that a missing config falls back to the stock theme.

## Acceptance

- [ ] A stub branding config injects colours, logo, watermark, footer, and page numbers.
- [ ] A missing config falls back to the report default theme without error.
- [ ] No tenant-supplied HTML/JS reaches the renderer (escaped only).
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
