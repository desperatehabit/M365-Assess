# T-0381 — Mailbox list, detail, and reports read API

## Report

EPIC-020 SPEC.md §2 (US-1, US-8), §3.1, §3.7, §5, and §6 require
`GET /v1/tenants/{id}/mailboxes` (list/search/filter), `GET /v1/tenants/{id}/mailboxes/{mailboxId}`
(detail), and `GET /v1/tenants/{id}/mailbox-reports`. §5 is explicit that mailbox objects are
**read live from EXO and not mirrored**, so the worker performs a read-only `Get-Mailbox` /
`Get-MailboxStatistics` projection and the BFF persists nothing.

Deliver the `Get-Mailboxes` worker job plus `get-mailboxes.ps1` entrypoint reading the job
envelope (T-0007) through the EPIC-001 worker/queue path (T-0010) with child-process credential
materialization (T-0011), returning the §3.1 columns (display name, primary SMTP, type, quota
used, archive, hold, forwarding, last activity) with cursor pagination and the §3.1 filters. The
`mailbox-reports.ts` routes back the mailbox statistics/activity, permissions, calendar
permissions, forwarding, and mail-flow reports by reusing the module collectors
(`Get-MailboxSummary`, `Get-MailboxPermissionReport`, `Get-MailFlowReport`). Extend
`portal.v1.yaml` with the operations. RBAC `mailboxes.read`, tenant-scoped; tenant and credential
records come from EPIC-002 (a data dependency, not a code dependency here).

## Acceptance

- [ ] `GET /v1/tenants/{id}/mailboxes` returns filtered, cursor-paginated rows with the §3.1 columns.
- [ ] `GET /v1/tenants/{id}/mailboxes/{mailboxId}` returns the off-canvas detail settings, permissions, and rules.
- [ ] `GET /v1/tenants/{id}/mailbox-reports` serves the §3.7 report set from the module collectors.
- [ ] The worker performs no tenant write and the BFF route holds no M365 SDK call.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
