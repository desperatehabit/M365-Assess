# T-0008 — Thin BFF skeleton (HTTP, config, structured errors, OpenAPI serving)

## Report

ADR-0014: the BFF "owns web concerns only … routing, authentication/sessions, request
validation, OpenAPI, rate limiting, and the SSE/WebSocket channel" and **contains no tenant or
domain logic**. EPIC-001 SPEC.md §6 requires contract-first OpenAPI 3.1, structured errors
`{ code, message, details, correlationId }`, and cursor pagination (`05-programming.md` §3).

Deliver:

- A TypeScript BFF workspace (`portal/bff/`) with `tsconfig.json` (strict) and a startable
  HTTP server exposing `/v1` routing, a request `correlationId`, and JSON error middleware.
- `config.ts` (port, storage path, worker pool size default `2` per SPEC §11.4, paths) sourced
  from environment with sane defaults — **no `.env`, no committed secrets**.
- `pagination.ts` implementing `?cursor=&limit=` with default 100 / hard max 1000.
- The server serves the OpenAPI document from `@portal/contracts`; no domain imports.

## Acceptance

- [ ] The server starts and returns the structured error shape for an unknown route.
- [ ] Every response carries a `correlationId`; errors expose stable `code` values.
- [ ] Cursor pagination helper enforces the default and hard max.
- [ ] No M365 SDK import and no check/remediation logic anywhere in `portal/bff/src/`.
- [ ] `portal/bff/src/server.test.ts` covers the above and fails without the code.
- [ ] No file outside `scope` is modified.
