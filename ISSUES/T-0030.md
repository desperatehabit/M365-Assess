# T-0030 — Tenants list and tenant detail UI

## Report

EPIC-002 SPEC.md §3.1 defines the **Tenants** page: a `DataTable` with display name, primary
domain, tenant ID (mono), source, credential `status-badge` (valid/expiring/expired/missing),
last run, status (active/excluded/error), and error count; filters by status/source/credential
state/group; search; row actions `View`/`Edit`/`Test credential`/`Set credential`/`Exclude` or
`Include`/`Remove`; bulk actions Exclude, Add to group, Run assessment (hands off to EPIC-003);
and a card view for small screens. §3.2 defines the detail tabs Overview/Credential/Groups/
Variables/History. All components use report theme tokens (`02-ui-design.md` §3) and add no
colour literals (`05-programming.md` §4).

Deliver the list route and the detail route wired to the T-0022/T-0023 APIs, with a
`CredentialBadge` driven by the T-0023 expiry states and a Vitest/Testing-Library test for the
table's states and credential badge.

## Acceptance

- [ ] The list renders every §3.1 column, supports the named filters/search, and exposes the row
      actions; the detail page renders the five tabs.
- [ ] The credential badge reflects valid/expiring/expired/missing from the API.
- [ ] Loading, loaded, and error states are tested; only theme tokens are used.
- [ ] No file outside `scope` is modified.
