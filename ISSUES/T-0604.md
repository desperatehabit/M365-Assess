# T-0604 — Daily secure-score snapshot job and trend API

## Report

EPIC-031 SPEC.md §4.2 defines snapshot & trend: a scheduled job (EPIC-007, T-0123) records a
`SecureScoreSnapshot` per tenant and the trend chart reads them; retention applies. §6 fixes
`GET /v1/tenants/{id}/secure-score/trend` and `POST /v1/tenants/{id}/secure-score/snapshot`. §11.2
is resolved to a **daily cadence** (not per run).

Deliver `Invoke-SecureScoreSnapshot.ps1`, a job handler registered as an EPIC-007 system timer that
captures the current score via the T-0602 read path once per tenant per day, plus the trend read
route (ordered snapshots) and a manual snapshot trigger route. Snapshots persist through T-0601 and
obey its retention. No tenant writes.

## Acceptance

- [ ] The snapshot job records one snapshot per tenant per day and is idempotent within a day.
- [ ] `GET .../secure-score/trend` returns the tenant's snapshots in time order.
- [ ] `POST .../secure-score/snapshot` records a snapshot on demand.
- [ ] Snapshots honour the T-0601 retention window.
- [ ] A test covers snapshot recording and trend read and fails without the code.
- [ ] No file outside `scope` is modified.
