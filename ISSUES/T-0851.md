# T-0851 — Mount and deliver EPIC-021 Transport & Connectors routes and workers

## Report

The EPIC-021 factories (`createTransportRulesRoute`, `createTransportRulesWriteRoutes`,
`createTransportRuleTemplateRoutes`, `createConnectorRoutes`, `createConnectorTemplateRoutes`) are
defined under `portal/bff/src/routes/` and covered by tests, but `portal/bff/src/app.ts` imports none
of them and `portal/bff/src/adapters/` has no transport/connector adapter, so the endpoints 404.

Two worker entrypoints the routes name are absent from `portal/workers/`:

- `get-connectors.ps1` — named by `portal/bff/src/routes/connectors.ts:4` ("Get-Connectors child job");
  there is no wrapper or `M365Portal.Workers/Get-Connectors.ps1` implementation. Only
  `set-connector.ps1` (create/edit/enable/disable/delete) exists.
- `set-transport-rule.ps1` — named by `portal/bff/src/routes/transport-rules.ts:156`; the wrapper is
  absent although `M365Portal.Workers/Set-TransportRule.ps1` implements the logic.

Web pages exist under `app/email/transport/` for rules, rule templates, connectors, and connector
templates.

## Fix direction

Author the two missing wrapper entrypoints following the existing `portal/workers/*.ps1` +
`M365Portal.Workers/*` pattern, add a transport/connector adapter on `runFeatureWorker`, and mount the
four route groups in `app.ts`.

## Acceptance

- [x] Every EPIC-021 SPEC §6 endpoint returns a non-404 response from a running BFF.
- [x] `get-connectors.ps1` and `set-transport-rule.ps1` exist and are exercised by a test.
- [x] Connector and transport-rule reads/writes run through their real workers.
- [x] No file outside `scope` is modified.

## Fix

Two missing worker entrypoints now follow the existing `portal/workers/*.ps1` +
`M365Portal.Workers/*` pattern:

- `get-connectors.ps1` wraps a new `Get-Connectors.ps1` that reads inbound and
  outbound connectors with Get- cmdlets only, shapes the §3.2 columns, and pages
  with the same opaque cursor scheme as the transport-rule read.
- `set-transport-rule.ps1` wraps the existing `Set-TransportRule.ps1` for
  create/edit/delete, mapping the job envelope to `Invoke-SetTransportRule` and
  carrying `-DryRun`/`-Confirmed` through.

`createTransportProviders` binds the route seams to those workers plus
`get-transport-rules.ps1` and `set-connector.ps1`, and implements the template
deploy executor over `deploy-transport-template.ps1` (one target per call,
returning the worker's audit event with before/after).

`createApp` mounts the transport-rule read/write, connector, transport-rule
template, and connector-template routes. Template records persist through
`SqliteTransportRuleTemplateRepository` / `SqliteConnectorTemplateRepository`
(migrations 0027/0028, now exported from `@m365-assess/db`), and deploy runs
through the EPIC-006 apply seam. Reads need `Exchange.Transport.Read`; writes
accept `Exchange.Transport.ReadWrite` or `Remediation.Apply`; template deploy is
gated on the write permission. All paths are registered in the EPIC-038
permission registry, published through the route modules' OpenAPI fragments, and
`portal/contracts/openapi/portal.v1.yaml` is regenerated.

The existing pages under `portal/web/src/app/email/transport/` now resolve their
API calls because the routes are mounted; no web change was needed.
