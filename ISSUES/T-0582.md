# T-0582 — Purview session seam and DLP list/detail API

## Report

EPIC-030 SPEC.md §2 US-1 and §3.1 define **DLP Policies** (Name · State · Locations · Rules · Last
modified) with row actions `View`, `Edit`, `Enable/Disable`, `Clone`, `Clone to template`, `Delete`.
§6 fixes `GET /v1/tenants/{id}/purview/dlp`. §7 requires Purview app-only via `Connect-IPPSSession`
and notes the Purview↔EXO mutual exclusion is handled by the per-tenant process (EPIC-001 T-0006);
the module already assesses DLP (`Get-DlpPolicyReport`).

Following ADR-0014, add a read-only `Get-PurviewDlp.ps1` job handler + `get-purview-dlp.ps1`
entrypoint that connects app-only to Purview, reads DLP policies, and returns a `ResultEnvelope`;
the BFF route validates `purview.read` + tenant scope and returns a cursor-paginated list. This
ticket establishes the Purview session seam reused by retention/labels/SITs. No tenant writes.

## Acceptance

- [ ] `GET /v1/tenants/{id}/purview/dlp` returns the §3.1 columns, paginated and tenant-scoped.
- [ ] The worker connects app-only to Purview and never shares a session across tenants.
- [ ] A caller without `purview.read` receives a structured error.
- [ ] Reuses the module's DLP read path without modifying `src/M365-Assess/`.
- [ ] A test covers listing and fails without the code.
- [ ] No file outside `scope` is modified.
