# T-0924 — Built-in standards, baselines and other templates can be edited in place

## Report

Rule from the operator (2026-11-19, while scoping T-0922): pre-defined templates must be
locked, and changing one means making a copy first, *"that way the original baselines,
standards, etc. remain intact."* This applies to every template family, not only run templates.

## Current state (from code, not yet checked live)

No template route in `portal/bff/src/routes/` has a built-in or locked concept. A search for
`builtIn`, `isSystem` and `locked` across the `*-templates.ts`, `baselines*.ts` and template
adapters finds nothing. `standards-templates.ts` supports cloning (`"<name> (copy)"`, around
line 440), but `PATCH` and `DELETE` treat every template the same. Any template that ships as
pre-defined content can therefore be changed or deleted, and the original is lost.

To confirm live: open a shipped standards template or baseline, edit it and save. The save
should be refused, and today it is expected to succeed.

## Fix direction

- Add a shared `builtIn: boolean` (or `source: "builtin" | "operator"`) field to every template
  family that ships pre-defined content, set when it is seeded.
- **API:** `PATCH` and `DELETE` on a built-in return 403 with one shared error code (for example
  `template.builtin_locked`). Every family gets `POST …/{id}/copy`, which creates an operator copy
  with `builtIn: false`.
- **UI:** built-ins show a lock badge. Edit and delete are replaced by "Make a copy". Opening a
  built-in in an editor is read-only, with a "Make a copy to edit" banner.
- Seeding or upgrades may refresh built-ins, but must never overwrite operator copies.
- T-0922 (run templates) and T-0923 (report templates) should use the same pattern.

## Acceptance

- [x] Every template family that ships built-in content marks it `builtIn`.
- [x] Built-ins cannot be edited, renamed or deleted through the UI or the API.
- [x] "Make a copy" works on every family and produces an editable operator template.
- [x] A seed or upgrade refreshes built-ins without touching operator copies.
- [x] No file outside `scope` is modified, unless the scope review adds to it.

## Fix

### Scope review

Searched every `portal/bff/src/routes/*-templates.ts` and `baselines*.ts` for
`BUILT_IN`/`builtIn`/`preset`/seeded records, plus the repositories, migrations and demo data.

Families that actually ship pre-defined content:

- **Standards templates** — now ships three built-ins (*Identity baseline*,
  *Conditional Access baseline*, *Sharing baseline*) derived from the shipped baseline catalog.
- **Baselines** — the local baseline catalog's three prebuilt baselines are served as locked
  built-in baselines.
- **Report templates** — already implemented by T-0923; left untouched as instructed.

CA, Intune, defender, group, user, SharePoint, transport-rule, JIT, PIM-settings, compliance,
connector, contact, filter and application templates are operator-created only: no migration,
repository or route seeds a record for them, so no `builtIn` field was added (avoids a dead
field). Run templates are T-0922 and will reuse the shared module.

### Shared contract

- Added `portal/bff/src/routes/template-builtin.ts` with one marker (`builtIn`), one 403 code
  (`template.builtin_locked`), `builtinLockedError`, `isBuiltInTemplate`, and
  `copyTemplateName` (`(copy)`, `(copy 2)`, …).
- Built-ins live in the route modules, like T-0923's report templates: every read refreshes
  them, and an upgrade can never overwrite an operator copy in the repository.

### Standards templates

- `GET /v1/standards/templates` merges the three built-ins ahead of stored templates; `GET
  /v1/standards/templates/{id}` reads a built-in without hitting the store.
- `PATCH`/`DELETE` on a built-in (route built-in or a future seeded `builtIn` record) return
  **403** `template.builtin_locked`; `Convert` is therefore also blocked.
- Added `POST /v1/standards/templates/{id}/copy` (the existing `/clone` route still works) and
  it produces a stored `builtIn: false` template with a collision-free `(copy)` name.

### Baselines

- `GET /v1/baselines` merges the three built-in baselines; `GET /v1/baselines/{id}` returns a
  built-in with an empty assignment list.
- `PATCH`, `DELETE` and `POST …/assign` on a built-in return **403** `template.builtin_locked`.
- Added `POST /v1/baselines/{id}/copy`; the copy has `builtIn: false`, the source stages, and
  no assignments (so the operator assigns it explicitly).
- `GET /v1/baselines/catalog` entries now carry `builtIn: true`.

### UI

- `TemplatesTable` shows a lock badge for built-ins; Edit, Clone & edit, Convert, schedule and
  Delete are replaced by **Make a copy**. `StandardsPage` wires the copy route.
- `Standards` editor shows a read-only banner ("Make a copy to edit") with a copy action and
  disables the name, assignment, standards and save controls.
- Baselines table shows a lock badge and **Make a copy** for built-ins (no Edit/Run/Delete).
- Baseline builder shows the read-only banner with a copy action; inputs, assignments, stages,
  alerting and save are disabled.
- Baseline catalog dialog marks entries as built-in.
- `standardsApi`/`baselinesApi` gained `copyStandardTemplate`/`copyBaseline`; OpenAPI YAML
  regenerated for the two new copy paths.
