# T-0891 — Wire the dashboard demo dataset behind an explicit toggle

## Report

`portal/web/src/data/dashboard-demo.ts` defines `DEMO_DASHBOARD_PAYLOAD` (`:145`),
`DEMO_FLEET_PAYLOAD` (`:233`), and the `DemoDashboard` renderer (`:300`). EPIC-004 SPEC §3.5/§11.1
specify a demo mode. Today the module is orphaned — `getDemoDashboardPayload`/`DemoDashboard` are
referenced only by `portal/web/src/components/dashboard/DemoData.test.tsx`; no dashboard page imports
them, so the feature is unreachable and the fabricated payload can never become confused with live
data only because nothing uses it.

Per the project decision, keep demo mode but make it impossible to mistake for real data: expose it
only through an explicit, clearly labelled entry point (e.g. an opt-in query parameter or a
"View demo" action on the dashboard empty state) that renders a persistent "Demo data" banner.

## Acceptance

- [ ] The demo dashboard is reachable only through an explicit opt-in control/URL.
- [ ] A persistent, visible "Demo data" indicator is shown whenever demo payloads render.
- [ ] Live dashboard routes never select the demo payload implicitly.
- [ ] A test asserts the live path ignores demo mode and the opt-in path shows the banner.
- [ ] No file outside `scope` is modified.
