# T-0485 — Site delete, restore, and recycle-bin operations

## Report

EPIC-025 SPEC.md §2 US-3, §3.1, §4.1, and §8 define the destructive lifecycle: delete, restore
from the deleted view, and recycle-bin empty/restore. Deletion requires confirmation, destroy
operations route through EPIC-006, and delete/empty carry before/after and audit. §6 exposes
`DELETE /v1/tenants/{id}/sharepoint/sites/{siteId}`, `POST .../restore`, and `GET`/`POST`
`/v1/tenants/{id}/sharepoint/recyclebin`. §11 item 1 is resolved (adopted): list + add + delete
+ restore are in v1.

Deliver an `Invoke-SharePointSiteAction.ps1` handler (entrypoint `invoke-sharepoint-site-action.ps1`)
covering delete, restore, recycle-bin list, and recycle-bin restore/empty, applying through the
EPIC-006 gated executor (T-0108) and updating `SiteOperation` (T-0481) with state and result.
The routes validate `sharepoint.write` + `Remediation.Apply`, require explicit confirmation on
delete and empty, and audit each operation. Extend `portal.v1.yaml`.

## Acceptance

- [ ] Delete requires confirmation and records a `SiteOperation` plus an audit event.
- [ ] Restore from the deleted view works for a soft-deleted site.
- [ ] Recycle-bin list and restore/empty are supported and audited.
- [ ] A test covers delete confirmation and restore and fails without it.
- [ ] No file outside `scope` is modified.
