# T-0892 — Add a system-wide demo dataset and explicit demo mode

## Report

The portal ships exactly one demo dataset: `portal/web/src/data/dashboard-demo.ts`
(`DEMO_DASHBOARD_PAYLOAD`, `DEMO_FLEET_PAYLOAD`) covering the dashboard's 8 widgets and a 3-tenant
fleet view. T-0891 gates it behind an explicit toggle. No demo data exists for any other area
(tenants, runs, mailboxes, Intune, Purview, audit logs, licensing, domains, backup, settings, tools,
etc.), so a prospective user cannot explore ~140 pages without a live tenant.

There is no central fetch layer to hook: pages call a `fetcher` prop defaulting to the global
`fetch`, and the Next.js rewrite forwards `/v1/*` to the BFF. A demo mode therefore needs a
site-wide, client-side demo data source that answers the paths the pages request, plus an explicit
opt-in control.

## Fix direction

Build a demo data layer and an explicit demo mode:

- A typed demo dataset covering the GET endpoints the nav-reachable pages call, with representative
  populated payloads (list, detail, dashboard, report, and chart shapes). Reuse and extend the
  dashboard payloads rather than duplicating them.
- A client-side demo transport installed by the app shell that intercepts `fetch` (or wraps the
  `fetcher`) only when demo mode is enabled, matching request path → canned response, and passing
  through when disabled. Pages must not need per-page changes to be populated.
- An explicit opt-in (e.g. a demo flag in the shell/URL) and a persistent, visible "Demo data"
  banner whenever demo mode is active. Demo mode must never engage implicitly.
- Write actions in demo mode must not mutate anything: return a structured, clearly-labelled
  non-persisting response, or disable the action with an explanatory message.

Hard constraint: no real tenant names, domains, or UPNs. Use reserved documentation domains
(`*.example.com`, `*.invalid`) per the repo PII rule — feedback comments and demo values included.

## Acceptance

- [ ] A demo mode toggle enables canned data for every GET endpoint the nav-reachable pages call.
- [ ] Every nav-reachable page renders populated data in demo mode; none show empty/error states.
- [ ] A persistent "Demo data" banner is visible while demo mode is active.
- [ ] Demo mode never activates implicitly, and live mode never serves demo payloads.
- [ ] Write actions in demo mode do not persist and are clearly marked as demo.
- [ ] No demo value contains a real tenant name, domain, or UPN (status unchanged).
- [ ] Tests cover enabling/disabling demo mode and a representative endpoint per major area.
- [ ] No file outside `scope` is modified.
