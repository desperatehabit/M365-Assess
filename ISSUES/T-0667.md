# T-0667 — Scheduled domain analysis and DNS change detection

## Report

EPIC-034 SPEC.md §3.4 defines scheduled analysis: "A schedule (EPIC-007) runs the analyser and
stores results; history shows DNS changes over time (e.g. MX record change alerts tie to
EPIC-029)". §4.3 says the analyser runs on schedule, results are stored, and diffs detect
changes. This is the entrypoint an EPIC-007 system timer (T-0123, prose cross-ref) invokes for
each tenant.

Build the `Invoke-DomainAnalysisSchedule.ps1` worker job that iterates verified domains, runs the
T-0664 analyser, and persists a T-0661 `DomainCheck`, and a `dns-change-detect.ts` domain function
that diffs the new records against the previous check and classifies MX/SPF/DKIM/DMARC changes.
Detected changes raise an alert through EPIC-029 (prose) — this ticket produces the change event,
not the notification. The optional schedule-creation route lets an operator enable/disable the
job. `.onmicrosoft.com` exclusion follows ADR-0003.

## Acceptance

- [ ] A scheduled run persists one `DomainCheck` per verified domain and skips expired/removed
      domains.
- [ ] Change detection identifies an MX/SPF/DMARC change against the prior check and emits a
      change event; an unchanged domain emits none.
- [ ] `.onmicrosoft.com` domains are excluded per ADR-0003.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
