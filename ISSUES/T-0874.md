# T-0874 — No scheduled credential-expiry check

## Report

`portal/bff/src/credentials/expiry.ts` provides `deriveCredentialState`, consumed only at read time
by `portal/bff/src/routes/credentials.ts:11`. SPEC §4.5 requires a scheduled check (EPIC-007) that
promotes credentials to `expiring`/`expired` and raises an alert. There is no such timer in
`portal/bff/src/scheduler/system-timers.ts:26-66` (the timers list covers retention, webhooks,
token-refresh, etc. but no credential-expiry scan), and no alert is emitted when a credential crosses
its expiry window.

## Acceptance

- [ ] A system timer scans tenant credentials on a schedule and updates their expiry state.
- [ ] A credential entering its warning window raises an alert through EPIC-029.
- [ ] A test covers the transition and fails without the timer.
- [ ] No file outside `scope` is modified.
