# T-0874 — No scheduled credential-expiry check

## Report

`portal/bff/src/credentials/expiry.ts` provides `deriveCredentialState`, consumed only at read time
by `portal/bff/src/routes/credentials.ts:11`. SPEC §4.5 requires a scheduled check (EPIC-007) that
promotes credentials to `expiring`/`expired` and raises an alert. There is no such timer in
`portal/bff/src/scheduler/system-timers.ts:26-66` (the timers list covers retention, webhooks,
token-refresh, etc. but no credential-expiry scan), and no alert is emitted when a credential crosses
its expiry window.

## Acceptance

- [x] A system timer scans tenant credentials on a schedule and updates their expiry state.
- [x] A credential entering its warning window raises an alert through EPIC-029.
- [x] A test covers the transition and fails without the timer.
- [x] No file outside `scope` is modified.

## Fix

Added `credential-expiry` timer (`Invoke-CredentialExpiryScan`, cron `0 0 4 * * *`) in `portal/bff/src/scheduler/system-timers.ts`, `scanCredentialExpiry` (`CREDENTIAL_EXPIRY_ALERT_RULE_ID = "credential-expiry-approaching"`) in `portal/bff/src/credentials/expiry.ts`, `CREDENTIAL_EXPIRY_COMMAND` / `createCredentialExpiryCommand` in `portal/bff/src/scheduler/maintenance.ts`, and wired `[CREDENTIAL_EXPIRY_COMMAND]` in `portal/bff/src/app.ts`. Pending live-tenant verification in Phase 2 (`fixed-unverified`).
