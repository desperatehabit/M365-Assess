# T-0350 — Device action dialogs and key-reveal auto-hide component

## Report

EPIC-018 SPEC.md §3.3 defines the `ActionDialog`s: Sync (light confirm), Retire (confirmation with
summary), Wipe (typed device-name confirmation + reason, irreversible), Fresh start (destructive
confirm). §3.4 requires key/credential display to be time-limited. §11.2 is resolved to a
**default auto-hide after 30 seconds**, per-tenant configurable within a bounded range
(15–120 s), read from the T-0345 policy store.

Deliver `DeviceActionDialogs` (the four dialogs wired to the T-0344/T-0345 routes, applying typed
confirmation and reason rules) and a `KeyReveal` component used by both BitLocker (T-0346) and
LAPS (T-0347): it shows a **Reveal** action, copies via an explicit button, and auto-hides after
the configured window with a visible countdown, without persisting the value client-side.

## Acceptance

- [ ] Sync, retire, wipe, and fresh-start dialogs enforce the §3.3 confirmation rules; wipe requires the typed device name and a reason.
- [ ] Reveal displays a key/credential only after explicit action, then auto-hides at the configured window.
- [ ] The revealed value is never written to persistent client storage or logs.
- [ ] Component tests cover the dialog rules and the auto-hide timer and fail without them.
- [ ] No file outside `scope` is modified.
