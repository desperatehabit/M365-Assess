# T-0686 — Restore preview: schema validation and change diff

## Report

EPIC-035 SPEC.md §4.2 steps 1-2 and §3.2: a restore first validates the backup's schema version
against the current instance and then **previews what will change** before confirmation. §9 makes
an incompatible schema a named risk (refuse on mismatch) and §11.4 resolves selective-restore
granularity to **per-table first, per-record later**.

Deliver `portal/bff/src/backup/restore.ts` (preview half): read the archive via T-0682, validate
its `schemaVersion` against the instance, and compute an added/changed/removed diff **per table**
for a requested table scope. Refuse a schema mismatch with a structured error. Preview is
read-only — it performs no writes and leaves no partial state.

## Acceptance

- [ ] A schema-version mismatch is refused with a structured error and no diff.
- [ ] The diff classifies records as added/changed/removed per table for the requested scope.
- [ ] Preview performs no write to the repository or artifact store.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
