# T-0028 — ITenantSource seam and DirectTenantSource

## Report

ADR-0017 makes tenant discovery sit behind an **`ITenantSource`** abstraction, with
`DirectTenantSource` shipping first and GDAP as a later implementation of the same interface.
The core only knows `Tenant` records with a `source` field; GDAP-specific data lives in a
satellite so direct-mode installs carry none of it (`03-database.md` §3.1). EPIC-002 SPEC.md §9
names the risk of "GDAP assumptions leak into core" and its mitigation.

Deliver the deliberately thin `ITenantSource` interface (list/resolve tenants) and
`DirectTenantSource` implementing it against the tenant repository (T-0022), with the tenant
`source` set to `direct`. Add a test asserting a direct-mode install creates **no** GDAP rows
(ADR-0017 failure-mode mitigation). No GDAP code in this ticket.

## Acceptance

- [ ] `ITenantSource` exposes only list/resolve; `DirectTenantSource` implements both.
- [ ] Direct onboarding sets `source: direct` and creates no `GdapRelationship` rows.
- [ ] A test asserts direct-mode installs carry no GDAP data.
- [ ] No file outside `scope` is modified.
