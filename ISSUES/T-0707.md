# T-0707 — Sandboxed custom-test dry-run/run and markdown output rendering

## Report

EPIC-036 SPEC.md §4.2: authoring includes a **dry run** that shows output against a tenant, and
enabling schedules/exposes the test executed **sandboxed** per EPIC-007; §6 exposes
`POST /v1/custom-tests/{id}/run`. §8 states a custom test obeys EPIC-006 and the EPIC-007 sandbox
when it writes; standard packs never write. §3.2 names a `MarkdownTemplate` for output.

Deliver `portal/workers/M365Portal.Workers/Invoke-CustomTest.ps1` that executes a custom test's
`ScriptContent` inside the existing sandbox (T-0126) and renders its output through the
`MarkdownTemplate`; deliver `run.ts` that dispatches a dry-run or live run through the job
envelope and records the result. Arbitrary code stays behind the T-0126 sandbox and the admin gate
(EPIC-038). Pester covers the worker.

## Acceptance

- [ ] A dry run executes in the sandbox and returns rendered markdown output without persisting pass/fail state.
- [ ] A live run executes in the same sandbox and records a result; a write made by the test obeys the EPIC-006 gate.
- [ ] A test that attempts an unsandboxed write is refused.
- [ ] Tests cover the worker and the run service and fail without them.
- [ ] No file outside `scope` is modified.
