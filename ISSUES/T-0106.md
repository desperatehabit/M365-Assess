# T-0106 — Manual instruction rendering from 02-controls/manual

## Report

EPIC-006 SPEC.md §4.2 and §5: a manual-only finding renders step-by-step instructions in-tool
from `docs/portal-specs/02-controls/manual/NNN-<checkId>.md`; the `ManualInstruction` entity is
`checkId`, `portalPath`, `steps[]`, `notes`. SPEC.md §11 item 2 resolves the source of truth:
the hand-written docs **override** the registry, which is the fallback.

Add a `Get-ManualInstruction.ps1` worker job plus a `get-remediation-instruction.ps1`
entrypoint that: strips the sub-number, locates the matching `manual/NNN-<checkId>.md`, parses
its portal path and numbered `## Steps`, and falls back to registry
`remediation.portal.path`/`steps[]` when the doc is absent. The BFF adds
`GET /v1/remediation/instructions/{checkId}` (extending the route file from T-0105) and returns
the parsed instruction; an `undetermined` check returns the empty-state marker. No writes.

## Acceptance

- [ ] `GET /v1/remediation/instructions/{checkId}` returns portal path + numbered steps for a doc that exists.
- [ ] When no doc exists, registry portal steps are the fallback; absent both returns the empty state.
- [ ] Sub-numbered check ids resolve to the same instruction as their base id.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
