# T-0705 — Custom-test parameter schema and validation

## Report

EPIC-036 SPEC.md §3.2 names `TestParameters` JSON as an editor field and §11.4 asks for the
custom-test **parameter schema and validation**, resolved here as a typed, validated schema (no
free-form blobs).

Deliver `parameters.ts`: a typed parameter definition (`name`, `type`, `required`, `default`,
`choices`, `secret`) and a validator used on author-save and again on run, rejecting unknown
parameters, type mismatches, and out-of-range choices with a structured error. `secret` parameters
carry a **reference only** and are never persisted as values. The schema is versionless within a
test version (a version is immutable); a schema-version field guards future changes.

## Acceptance

- [ ] A valid parameter set round-trips; unknown/mistyped/out-of-choice values are rejected with stable codes.
- [ ] `secret` parameters never store a value, only a reference.
- [ ] The schema exposes a version field for forward compatibility.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
