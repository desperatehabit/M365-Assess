# T-0742 — Endpoint permission registry and completeness test

## Report

EPIC-038 SPEC.md §4.1 and §7: every API endpoint declares one permission in a machine-readable
registry generated from endpoint metadata (CIPP's `Config/function-permissions.json` analogue),
and "a test fails the build if an endpoint lacks one." SPEC.md §11 item 2 resolves the taxonomy
as `{Area}.{Resource}.{Action}` (e.g. `Tenant.Standards.ReadWrite`, `Remediation.Apply`,
`CIPP.Admin`). `Public` permissions bypass the check; `anonymous`/`authenticated` are reserved
defaults.

Build `permissions.ts` exposing the `PermissionRegistry` and a helper that maps an endpoint
(route + method) to its declared permission, sourced from the route modules added by T-0013 and
the contract document. Add a Vitest completeness test that enumerates every mounted endpoint and
fails if any lacks a permission declaration. Extend `portal.v1.yaml` with the machine-readable
permission metadata the registry is derived from.

## Acceptance

- [ ] Every mounted endpoint resolves exactly one permission; the completeness test fails when one is removed.
- [ ] Permission strings follow `{Area}.{Resource}.{Action}`; `Public` bypasses evaluation.
- [ ] The registry is derived from endpoint metadata, not a hand-built parallel list.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
