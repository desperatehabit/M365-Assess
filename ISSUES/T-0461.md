# T-0461 — RestoreJob persistence and repository methods

## Report

EPIC-024 SPEC.md §5 fixes the only persisted email-tools entity besides audit: `RestoreJob` with
fields `id`, `tenantId`, `mailboxId`, `scope`, `target`, `state`, `result`, `createdBy`, and
states that message data is **not** persisted by the portal — only job and audit records.
ADR-0015 and `03-database.md` §5 require a numbered, forward-only migration behind the
repository interface.

Deliver migration `0032_mail_restore_jobs.sql` extending the `0001_init` schema (do not reuse a
claimed lower number), plus create/get/update/list methods on `portal/db/src/repository.ts` and
`sqlite-repository.ts`. Jobs are tenant-scoped and soft-delete is not needed; a test must prove
no message body/content field exists in the schema. No route or worker code belongs here.

## Acceptance

- [ ] Migration 0032 applies after the base migrations, is re-runnable, and advances `SchemaVersion`.
- [ ] The repository exposes create/get/update/list for `RestoreJob`, tenant-scoped.
- [ ] A test asserts the schema persists no message body or message content.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
