# T-0382 — Shared-mailbox create/convert with operation records

## Report

EPIC-020 SPEC.md §2 (US-2), §3.2, §4.1, §5, and §6 require `POST /v1/tenants/{id}/mailboxes`
(create) and `POST /v1/tenants/{id}/mailboxes/{mailboxId}/convert` (convert to shared), each
*form → plan preview → apply* through the EPIC-006 gated executor. Resolved §11.1 adopts the
**first cut: convert plus permissions, with full parity later**; this ticket delivers create and
convert, and T-0384 delivers the permissions half.

SPEC.md §5 lists `MailboxOperation` (`id`, `tenantId`, `mailboxId`, `operation`, `before`,
`after`, `state`, `by`, `at`) as the persisted audit trail, so add migration
`0031_mailbox_operations.sql` and a `mailbox-repository.ts` that later mailbox-write tickets
reuse. The `Set-Mailbox.ps1` worker job plus `set-mailbox.ps1` entrypoint run the create/convert
through the EPIC-006 gated executor (T-0107), capturing before/after, requiring confirmation, and
writing an `AuditEvent`. Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Migration 0031 applies after the highest existing migration, is re-runnable, and advances `SchemaVersion`.
- [ ] Create and convert each run through the EPIC-006 gate, capture before/after, and persist a `MailboxOperation` row plus an `AuditEvent`.
- [ ] A convert of an already-shared mailbox is a structured no-op, not a duplicate write.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
