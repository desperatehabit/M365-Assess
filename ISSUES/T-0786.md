# T-0786 — Application approval (consent requests) API and page

## Report

EPIC-040 SPEC.md §3.3, §4.2, §5, §6, §8 (US-4): page **Application Approval** listing pending
consent requests (app · requested permissions · requestor · status) with row actions
`Approve`, `Deny`, `View app`. `GET`/`POST /v1/tenants/{id}/consent-requests`. Approval and
denial are tenant writes and must be confirmed and audited, and the app-approval path routes
through the **EPIC-006** write boundary (T-0101).

Build `app-approval-service.ts` and `ConsentRequestTable.tsx`. Each decision records a
`ConsentDecision` (`id`, `tenantId`, `appId`, `decision`, `by`, `at`, `reason`) plus an
`AuditEvent`. Approve/Deny require `CIPP.Admin.*` (T-0743) and carry before/after state;
`reason` is required on Deny.

## Acceptance

- [ ] The page lists pending consent requests with the §3.3 columns and row actions.
- [ ] Approve/Deny write to the tenant through the EPIC-006 boundary, require `CIPP.Admin.*`, and are audited with before/after.
- [ ] A `ConsentDecision` row is persisted per decision; Deny requires a reason.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
