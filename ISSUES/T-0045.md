# T-0045 — Worker emits section progress and a check counter

## Report

EPIC-003 SPEC.md §4.2 says the child process emits structured progress per section, reusing the
module's check-level signal, as `RunSection` events. §9 names the risk that the module's
progress emits to console only and its mitigation: adapt the signal to structured events.
Resolved §11.3 adopts **sections + a check counter by default, with check-level detail
opt-in**.

Deliver a worker-side `Write-RunProgress.ps1` (exported from the `M365Portal.Workers` module)
that maps the module's per-section/per-check progress to the T-0014 event contract — one
section event per section plus an aggregate check counter — and writes it to the job's progress
channel. This ticket edits only the worker module, never `src/**`; it consumes the module's
existing progress output.

## Acceptance

- [ ] The worker emits a `RunSection` event per section and a check counter that advances.
- [ ] Check-level events are emitted only when the opt-in flag is set.
- [ ] A Pester test drives the mapping with stub module output and asserts the event shape.
- [ ] No file outside `scope` is modified.
