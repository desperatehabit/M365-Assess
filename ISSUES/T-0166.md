# T-0166 — Deny deviation and queued deletion with confirm and delay

## Report

EPIC-009 SPEC.md §3.2 and §4.2: **Deny deviation — queue deletion** moves a deviation to `denied`
→ `delete pending`; on the next remediation run it is **DELETED from the tenant and cannot be
undone**. §8 requires the destructive warning verbatim, explicit confirmation, a full audit
record, and routing through **EPIC-006** (no drift-specific executor). §9 rates this the top risk.

Resolved §11.3 adopts an explicit confirm **plus an optional delay/grace window** before deletion,
flagged as a safety review item. Deliver `POST /v1/drift/deviations/{id}/deny` and the
`drift-delete-queue.ts` state machine, which schedules deletion (respecting any configured delay)
and hands the actual delete to the EPIC-006 contract (prose). Requires `drift.remediate` and
`Remediation.Apply` (EPIC-038, prose).

## Acceptance

- [ ] Deny moves the deviation to `denied` → `deletePending` and never deletes synchronously.
- [ ] A configured delay defers deletion; without one, deletion is queued for the next run.
- [ ] Deleting routes through the EPIC-006 contract and writes an audit record with actor and reason.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
