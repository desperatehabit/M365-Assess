# T-0950 — A single-item Graph result unrolls to a hashtable, so counts and indexing are wrong

## Report

Collectors assign a list from an `if` statement:

```powershell
$gaList = if ($resp -and $resp['value']) { @($resp['value']) } else { @() }
```

PowerShell unrolls the output of a statement used as an assignment's value. When `value` holds
exactly one item, `$gaList` is that item, not a one-element array. `Invoke-MgGraphRequest`
returns hashtables, so:

- `$gaList.Count` is the hashtable's **key count**, not 1.
- `$gaList[0]` looks up a key named `0` and returns `$null`.

Observed on the live run (one Global Admin, one organization object):

| Check | Shown | Actual |
|---|---|---|
| ENTRA-CLOUDADMIN-001 | "All 4 GA accounts are cloud-only" | 1 GA (the member hashtable has 4 keys) |
| ENTRA-HYBRID-001 | Review, "Organization data not available" | Organization readable; cloud-only (`$orgValue[0]` is `$null`) |

An AST scan finds 22 such assignments whose variable is later used with `.Count`, `.Length` or
`[n]`, in 9 files:

- `Common/Build-ReportData.ps1:264` (`$mfaRows`), `Common/SecurityConfigHelper.ps1:131`
  (`$requiredPlans`)
- `Entra/EntraAdminRoleChecks.ps1:42, 397, 541`; `EntraConditionalAccessChecks.ps1:19`;
  `EntraPasswordAuthChecks.ps1:583`; `EntraUserGroupChecks.ps1:235, 613`
- `Entra/Get-EntAppSecurityConfig.ps1:174, 265, 287, 838, 877, 918`
- `SOC2/Get-SOC2AuditEvidence.ps1:98, 134, 171, 209`; `SOC2/Get-SOC2SecurityControls.ps1:242,
  368, 407`

Small tenants (one admin, one CA policy, one app owner) hit this routinely.

## Fix direction

- Wrap the whole statement so the result is always an array:
  `$gaList = @(if ($resp -and $resp['value']) { $resp['value'] })`.
- Fix all 22 sites, then add a Pester guard (AST scan like the one above) that fails on the
  pattern so it cannot return.
- Add single-item fixture tests for ENTRA-CLOUDADMIN-001 and ENTRA-HYBRID-001.

## Acceptance

- [ ] With one Global Admin, ENTRA-CLOUDADMIN-001 reports 1 account.
- [ ] With one organization object, ENTRA-HYBRID-001 evaluates `onPremisesSyncEnabled` instead of reporting data unavailable.
- [ ] A repository-wide test fails on `= if (...) { @(...) }` followed by `.Count`/`[n]`.
- [ ] Single-item tests fail without the change.
