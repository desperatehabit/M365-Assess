# T-0583 — DLP policy change API via the remediation engine

## Report

EPIC-030 SPEC.md §4.1 defines policy CRUD: create/edit via the editor → **plan preview** → apply,
gated and audited via EPIC-006; disabling a DLP policy is flagged compliance-impacting. §8 states
all compliance writes route through EPIC-006, disabling DLP requires confirmation, and before/after
is captured. §6 fixes `POST`/`PATCH`/`DELETE /v1/tenants/{id}/purview/dlp`.

Deliver the DLP write routes behind RBAC `purview.write` with `Remediation.Apply` semantics
(EPIC-038 in prose), driving the EPIC-006 gated apply (T-0108) with `Idempotency-Key`. Add a
`dlp-guard.ts` that marks disable/delete as compliance-impacting, requires explicit confirmation,
and records the `CompliancePolicyChange` row (T-0581). Plan preview is produced by the EPIC-006
plan path; this ticket adds no direct Purview write of its own.

## Acceptance

- [ ] Create/edit/enable/disable/delete are expressible as a plan and applied only through T-0108.
- [ ] Disabling or deleting a DLP policy requires confirmation and is flagged compliance-impacting.
- [ ] Each applied change records a before/after `CompliancePolicyChange` and an audit event.
- [ ] A caller without `purview.write` receives a structured error.
- [ ] A test covers the guard + routes and fails without the code.
- [ ] No file outside `scope` is modified.
