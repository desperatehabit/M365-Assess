# T-0915 — Onboarding reports a missing PowerShell module only after the operator starts it

## Report

Onboarding needs `Microsoft.Graph.Authentication`, `Microsoft.Graph.Applications`,
`Microsoft.Graph.Identity.Governance` and `ExchangeOnlineManagement` on the machine that runs the
BFF. The first in-portal onboarding on a machine without `Identity.Governance` failed with
`Missing required modules: Microsoft.Graph.Identity.Governance. Install them and re-run.
(code: onboard.failed)`. Nothing in the portal says this beforehand, and the message does not say
which version to install. Mixing Graph SDK versions across modules causes assembly load errors,
so the version matters.

### Also: onboarding does not grant a read permission the assessment needs (added 2026-11-19)

The run validity audit of the walk's first portal run (run `1e05ddc5`, see T-0926 to T-0939)
logged `WARN Missing Graph scopes: Agreement.Read.All`. Because of this, **ENTRA-TOU-001**
(Terms of Use) reports "Insufficient permissions → Review" instead of a real result.
`Agreement.Read.All` is not in `src/M365-Assess/Setup/PermissionDefinitions.ps1`, so
`Grant-M365AssessConsent` never grants it, and every onboarded tenant hits this.

## Fix direction

Check the modules before the wizard's final step (a read-only worker, or part of an existing
diagnostics endpoint), and show any missing module with the install command pinned to the
installed `Microsoft.Graph.Authentication` version.

Add `Agreement.Read.All` (Graph application permission, read-only) to the read set in
`PermissionDefinitions.ps1`. Tenants that are already onboarded need consent granted again.
Note that in the release notes, or show a "re-consent needed" prompt where an onboarded tenant
is missing a permission in the current set.

## Acceptance

- [x] A missing onboarding module is reported in the wizard before onboarding starts.
- [x] The message gives an install command whose version matches the installed Graph SDK.
- [ ] A newly onboarded tenant has `Agreement.Read.All`, and ENTRA-TOU-001 records a real
      result instead of "Insufficient permissions".
- [x] No file outside `scope` is modified.

## Fix

### Modules preflight (before onboarding starts)

- `Invoke-TenantOnboarding.ps1`: new `Test-OnboardingPrerequisite` reports
  `Microsoft.Graph.Authentication`, `Microsoft.Graph.Applications`,
  `Microsoft.Graph.Identity.Governance` and `ExchangeOnlineManagement` from
  `Get-Module -ListAvailable`, with installed versions. Missing Graph modules get
  `Install-Module <module> -RequiredVersion <installed Authentication version> -Scope CurrentUser -Force`
  so the whole Graph SDK stays on one version (mixed versions cause assembly load errors);
  `ExchangeOnlineManagement` installs unpinned. If Authentication itself is missing, the message
  says to install it first, then re-run so the others can be pinned. The function is read-only and
  takes an `-InstalledModules` table as a test seam.
- `portal/workers/onboarding-preflight.ps1`: thin entrypoint for the BFF worker convention.
- `GET /v1/onboarding/preflight` (`routes/onboarding-preflight.ts`, gated on
  `Tenant.Administration.Read`): returns `{ ready, graphVersion, modules, missingModules,
  installCommands, message }`. Mounted in `app.ts`, registered in `rbac/permissions.ts` and
  `routes/openapi.ts`; `portal.v1.yaml` was regenerated with the route.
- `AddTenantWizard.tsx`: when leaving the test-connection step, the wizard calls the preflight
  (a `onCheckPrerequisites` prop overrides the BFF call in tests). The confirmation step shows the
  missing modules with the exact install commands and blocks **Complete Onboarding** while the
  modules are known to be missing. If the preflight endpoint cannot be reached, the wizard shows
  an advisory warning and still lets onboarding run (the worker then reports
  `onboard.failed`). The permission count copy moves from 28 to 29.

### Agreement.Read.All

- `PermissionDefinitions.ps1`: `Agreement.Read.All` added to the read set (Identity), so
  `Grant-M365AssessConsent` grants it on the next run. No write permission was added (T-0917).
- Already-onboarded tenants still need `Grant-M365AssessConsent` run again to pick up the new
  permission. The release-note/re-consent prompt suggested in the report is not included here:
  `CHANGELOG.md` was out of this task's scope and the wizard only adds tenants, so this needs a
  follow-up (or a release note) before existing tenants see ENTRA-TOU-001 pass.

- `tests/Setup/Grant-M365AssessConsent.Tests.ps1`: 2 new data-table tests (`Agreement.Read.All`

- `portal/bff/src/routes/onboarding-preflight.test.ts`: 5 tests (path/permission, missing-module
  report, ready report, 401, 403). 5 passed.
- `portal/bff`: `openapi.test.ts` + `rbac/permissions.test.ts` 28 passed (registry complete, YAML
  in sync); `tsc --noEmit` has one unrelated existing error in `routes/runs-list.ts` from a
  concurrent edit, not from this change.
- `portal/web`: `AddTenantWizard.test.tsx` 5 passed; `tsc --noEmit` clean.
