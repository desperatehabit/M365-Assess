# T-0462 — Message trace worker and API within the EXO trace window

## Report

EPIC-024 SPEC.md §2 US-1, §3.1, and §4.1 define message trace: filter by sender, recipient,
subject, date range, and status; results table Timestamp · Sender · Recipient · Subject ·
Status · Event; and the EXO trace window limits must be surfaced with a clear message. §6
exposes `POST /v1/tenants/{id}/mail/message-trace`. §9 names the EXO trace window limit risk
with the mitigation to guide users to historical search; §8 makes read-only queries audited
because they expose message metadata.

Deliver a `Get-MessageTrace.ps1` handler (entrypoint `get-message-trace.ps1`) wrapping
`Get-MessageTraceV2` (or the supported EXO trace cmdlet) that validates the date range against
the trace window and returns a clear structured error when exceeded, plus the query route that
validates `mailtools.read`/`mailtools.search`, tenant scope, pagination, and writes an audit
record. The EXO base is EPIC-020 (prose). Extend `portal.v1.yaml`.

## Acceptance

- [ ] The route returns trace rows for a supported sender/recipient/subject/date filter.
- [ ] A date range beyond the EXO trace window returns a structured error naming the limit.
- [ ] Every query writes an audit record; results are tenant-scoped.
- [ ] A test covers filtering and the window-limit error and fails without it.
- [ ] No file outside `scope` is modified.
