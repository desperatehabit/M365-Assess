# T-0442 — Contacts list worker and read API

## Report

EPIC-023 SPEC.md §2 US-1 and §3.1 define the contacts list: Display name · External address ·
Type (mail contact/mail user) · Hidden from GAL · Last modified, with `GET
/v1/tenants/{id}/contacts` in §6. §5 states contacts are read live from EXO. §11 item 2 is
resolved to mail contact + mail user only for v1 (mail-enabled security groups are considered
but out of scope).

Following ADR-0014, add a `Get-Contacts.ps1` job handler plus a thin `get-contacts.ps1`
entrypoint that reads `Get-MailContact`/`Get-MailUser` and returns a `ResultEnvelope`; the BFF
route validates `contacts.read` and tenant scope and returns a cursor-paginated list. The EXO
base (app-only certificate connection) is provided by EPIC-020 and is a data dependency, not a
code dependency. Extend `portal.v1.yaml` to match the implementation.

## Acceptance

- [ ] `GET /v1/tenants/{id}/contacts` returns the §3.1 columns, paginated, filtered by tenant scope.
- [ ] The worker classifies each row as mail contact or mail user; no other types are returned.
- [ ] A caller without `contacts.read` receives a structured error.
- [ ] A test covers listing and fails without the code.
- [ ] No file outside `scope` is modified.
