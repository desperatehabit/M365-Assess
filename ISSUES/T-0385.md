# T-0385 — Mailbox rules and forwarding

## Report

EPIC-020 SPEC.md §2 (US-5), §3.4, §4.1, §6, and §9 require per-mailbox inbox rules and
forwarding configuration to be listed and managed (add/edit/remove). §3.4 and §9 flag forwarding
changes as **security-sensitive (a BEC vector)**; the mitigation is to flag forwarding changes,
audit them, and tie into EPIC-011's BEC checks.

Deliver `mailbox-rules.ts` for the §6 `GET`/`POST`/`PATCH`/`DELETE` rule routes and
`Set-MailboxRule.ps1` plus `set-mailbox-rule.ps1` for the worker. Add
`domain/mailboxes/forwarding-guard.ts`, which classifies a forwarding/rules change as
security-sensitive and forces the warning path. Every write routes through the EPIC-006 gate
(T-0107), records before/after, writes a `MailboxOperation` (T-0382) and an `AuditEvent`. Extend
`portal.v1.yaml`. Tenant and credential records are EPIC-002 (prose dependency).

## Acceptance

- [ ] Inbox rules and forwarding list per mailbox and add/edit/remove through the gated path.
- [ ] A forwarding-enabling change is classified security-sensitive and surfaces the warning before apply.
- [ ] Every write captures before/after and writes an `AuditEvent`.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
