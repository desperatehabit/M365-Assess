# T-0015 — Guard test: the BFF contains no M365 SDK calls or domain logic

## Report

ADR-0014 calls the "BFF stays thin" rule load-bearing and names its failure mode: "domain
logic creeps into the BFF". Its stated mitigation is "a guard test/lint forbidding M365 SDK
usage and check logic in the BFF". EPIC-001 SPEC.md §9 repeats the rule ("no new write paths",
read-only boundary intact for this epic).

Deliver:

- A `guard.test.ts` that scans `portal/bff/src/**` (excluding test files) and fails if it finds:
  an import of an M365 SDK (`@microsoft/microsoft-graph-client`,
  `ExchangeOnlineManagement`, etc.), an `Invoke-MgGraphRequest`-style call, or a remediation /
  collector construct (`Add-Setting`, `Set-*` tenant operations).
- Wired into the BFF package's test script so it runs with the other unit tests.

## Acceptance

- [ ] The guard fails on a deliberately added M365 SDK import (test asserts the failure).
- [ ] The guard passes on the tree produced by T-0007/T-0008.
- [ ] The guard is part of the package `test` script.
- [ ] No file outside `scope` is modified.
