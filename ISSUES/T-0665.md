# T-0665 — DNS check API with result TTL cache and domain history

## Report

EPIC-034 SPEC.md §6 exposes `POST /v1/tenants/{id}/domains/{domain}/check-dns` (analyse now) and
`GET /v1/tenants/{id}/domains/{domain}/history` (history). §4.2 runs the analyser and stores the
result; §3.4 keeps history for trend. Resolved §11.3 adopts a **DNS analysis result TTL**
(default 1 hour, configurable): a repeat `Check DNS` inside the window serves the cached result
instead of re-resolving, which also mitigates the SPEC §9 risk of egress and resolver rate limits.

Build the two routes and a `dns-cache.ts` TTL cache keyed by tenant+domain that wraps the T-0664
analyser job. On a cache miss the route enqueues the job, persists a T-0661 `DomainCheck`, and
caches the result; history returns the stored checks for the trend view. RBAC `domains.read` and
tenant scope are enforced. Extend `portal.v1.yaml`.

## Acceptance

- [ ] The first `check-dns` resolves and persists a `DomainCheck`; a second call inside the TTL
      returns the cached result without re-resolving.
- [ ] After the TTL expires the next call re-resolves; the TTL is configurable.
- [ ] History returns ordered stored checks for a domain and is tenant-scoped.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
