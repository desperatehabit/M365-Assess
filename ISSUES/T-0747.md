# T-0747 — API client CRUD, secret hashing, and rotation

## Report

EPIC-038 SPEC.md §3.3, §5, §6: `GET`/`POST`/`PATCH`/`DELETE /v1/api-clients` and
`POST /v1/api-clients/{id}/rotate-secret`. `ApiClient` carries `secretHash`, `roles[]`,
`ipRanges[]`, `rateLimit`, `enabled`, `lastUsedAt`; the secret is **shown once** and stored
hashed. SPEC.md §9 names secret leakage a risk with mitigation "hashed at rest, returned once,
never logged."

Add the `api-clients.ts` route and `api-client-secret.ts` (generate, hash, verify). Create
returns the plaintext secret exactly once and persists only the hash; `rotate-secret` issues a
new secret, again once; hash generation uses a vetted KDF and is never logged. `Add client`
fields (name, role(s), IP ranges `Any` or CIDR list, rate limit) map to the entity. Extend
`portal.v1.yaml`.

## Acceptance

- [ ] Create and rotate return the secret once; no endpoint ever returns it again.
- [ ] No plaintext secret is stored or logged; only the hash is persisted.
- [ ] A client's roles/ipRanges/rateLimit/enabled round-trip through CRUD.
- [ ] A test covers the change and fails without it.
- [ ] No file outside `scope` is modified.
